Inputs (in a scratch dir next to the patched gem copies, as `overrides/rubocop/work/` holds them now): a.rb (2 lines), c.rb (clean), b.rb
(rubocop's cli.rb), d..n.rb (other rubocop/rubocop-ast sources, 58-793 lines), and `sub/` (a directory of 3 files).
`overrides/rubocop/check files...` (then `cmp.sh`) compares stdout and exit status with MRI and fails on any "An error occurred while" in the

## Correctness

The all-cops binary (round f36, every registered cop compiled) equals MRI on all 15 inputs: stdout, exit status, and
no cop errors. Optimized and debug builds agree.

## Build cost (not met yet)

- Generated Go: 216k functions (182k before every registered cop was compiled; the extra cops are needed because a
  directive comment can name any cop).
- Optimized `go build`: 293 MB binary. A clean single build (standard library warmed in a private GOCACHE, so only
  the program's package compiles): **14m23s wall, 17m50s user, 21m43s system**, compiler peak ~7 GB with another 5 GB
  VM on the machine. System time that high is paging, so part of the 14 min is memory pressure; even the user time
  alone is 2.8x the 6m17s baseline's wall clock. (An earlier attempt took 73 min: two copies ran at once by mistake and
  swapped 12 GB.)
- Transpile: 10-19 min under today's load; ~4.5 min on a quiet machine before the extra cops.

## Speed work after the first measurement (2026-11-12 evening, quiet machine)

Cold transpile (`RUGAROO_NO_INFER_CACHE=1 rugaroo gen ... -trace`, the transpile step of `overrides/rubocop/build`), output compared byte for byte:

| change | transpile | output |
|---|---|---|
| start of the evening | 381 s | |
| `noteDynUses` types each argument once, not once per method of the name | 269 s | identical |
| `markCalleeDefaults` walks a class's own methods; `staticPrivate` memoized after link | 241 s | identical |
| GOMEMLIMIT 8 GiB / 12 GiB instead of the CLI's 4 GiB | 269-271 s | identical (no effect) |
| cache each class's ivar writes; memoize `isSubclassOf` (reverted) | 241 s | identical (no effect) |
| 2 settled rounds instead of 3, with or without untyping the parameters still changing (reverted) | ~226 s | `Layout/IndentationWidth` raises on every input: untyping spreads one call level per round |
| a round falls back to the previous round's kept ivar typings before searching (reverted) | 263 s | equal to MRI on all 15, but the final pass then widened 3 times instead of once (+35 s) |

Where the 241 s goes: 7 inference rounds 126 s (each regenerates every body twice: return inference and use collection,
~10 s, plus ~2 s ivar refinement; round 2's refinement searches, 21 s), format 32 s, final pass 2 x ~17 s, Go type check 13 s,
boot 7 s. The next levers are structural: regenerate only the methods whose parameter types changed in a round.

Optimized `go build` on a quiet machine (no VM, ~15 GB free), `-gcflags=-bench`: 7m15s and 10m35s on two runs, the compiler
at 13-17 GB. 708,531 compiled functions (216k top-level, the rest closures and generic instantiations) at 2,822/s:
backend 251 s, object writing 87 s, parse 45 s. Brew's 264k functions built in 95 s at 5,150/s with memory to spare, so
the size is the lever: per-class forwarders (50k: each cop and each of ~2,000 class objects copies the shared
methods), the respond_to?/send tables a computed send needs for every name (22.8k small functions), and prism
(19.7k functions rubocop-ast loads for its prism engine, unused on these inputs).
