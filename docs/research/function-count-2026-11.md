# Function count of large programs: design, 2026-11-21 (main 0ea44f41)

Written by a read-only planning agent; nothing here is built. Every number comes from the existing rubocop `main.go`
(`$TMPDIR/rugaroo-831620060/main.go`, 113.7 MB, 2,336,195 lines, 217,329 `func`s, the same file as the census in the brief) or from
the cited docs. A claim marked *(inferred)* was not read in code or measured.

## Summary and recommendation

The census is right about volume but wrong about where the sharing is. 15,991 Dyn wrappers call **their own class's** method
(`Prism_AliasGlobalVariableNode_ChildNodes(self)`). Census normalizes the receiver name, so these look identical, but they are
distinct by nature. The real duplication is elsewhere:

- **32,403 private `_DynX` wrappers** (plus 638 public ones) call a **module** function instantiated at the class's own interface:
  `return RuboCop_Cop_Util_Line[RuboCop_Cop_Style_AndOrI](self, args[0])`. That is 486 module methods, each copied across about 615
  cops and 633 `PathUtil` includers.
  - Each wrapper costs a function.
  - Each type argument is its own GC shape (decision 208: "an includer's own CI is a GC shape per class"), so Go also compiles
    the module body again per class: about **522k lines of module bodies**, by my count (callee length × callers).
  - The forwarders already avoid this. Decision 208 instantiates `Mod_Self[any]` for them, and decision 234 gives dispatched
    module methods one shared arm. The Dyn wrapper path never got the 208 rule for non-dispatched (private) module methods.
- The forwarders and the per-metaclass method sets exist because a parent's Go **method** costs one function on every
  subclass: an explicit forwarder, or Go's autogenerated promoted wrapper (decision 209, "Found, not done").
  - Only taking the name out of Go method sets removes them. That means more names dispatched by type switch (decisions 212/213).
  - 61,995 functions (28.5%) are methods on the 2,008 metaclasses.

**Recommended order:**
1. **A**: module wrappers as shared arms.
2. **F**: fold the respond markers.
3. **B**: dispatch more Cop::Base names, after the debug experiment Q1 below.
4. **D**: the cheap metaclass parts.
5. **C**: only `loop`, if its reason turns out to be incidental.

Stop there. C's `==`/`to_s`/`to_json` and E trade hot-path or binding-decision risk for about 37k more functions and need the
owner's sign-off.

**Model for build cost:** I take build time as linear in compiled functions, anchored on the 2026-11-12 measurement
(`docs/research/rubocop/results-2026-11-12.md`: 216k source funcs → 708,531 compiled) and today's 7 min / 16.5 GB, and memory as
the same ratio. It is conservative:
- rubocop compiles 2,822 funcs/s against brew's 5,150/s (same doc), so the gain grows if memory pressure eases;
- A also removes large instantiated bodies, worth more than one tiny function each.

For A, I give a range: count-linear, up to line-linear.

| after step | source funcs | main.go | compiled (est.) | go build (linear) | memory |
|---|---:|---:|---:|---:|---:|
| today | 217.3k | 113.7 MB | ~708k | ~420 s | 16.5 GB |

- A: −33k wrappers − ~32k instantiations × ~1.3 (the closures inside module bodies are compiled per instantiation too).
- F, B, D, C: one compiled function per source function removed.

## How the code works today (verified)

- **Dispatcher** (`emitDynName`, `internal/compiler/dynamic.go:389-468`):
  1. shared class-ID arms, public then private, as two separate switches (`:417-418`, `emitDynArms` at
     `dynamic_wrapper.go:339-370`; a private arm is guarded by `how != rbCall`, `:350-352`);
  2. `recv.(interface{ DynX(...any) any })` (`:419`);
  3. views, `_DynGenN`, nil/Object fallbacks;
  4. `_DynX` for private (`:447-449`);
  5. `method_missing`, then `NoMethodError`.
- **Why arms go first** (comment at `:411-412`): "a class they serve may still embed its parent's DynX, promoted by Go with the
  parent as self".
- **Sharing** (`dynWrappers`, `dynamic_wrapper.go:111-156`): each class's body is generated (`dynWrapperBody`, `:421-455`), and
  `dynShareable` (`:221-275`) admits a body that does not name the class. Paths:
  - a universal owner's free func over `[any]`;
  - the owner's plain func through `ownerIface` (`:189-194`, `:246-251`);
  - a **dispatched** module method rewritten to `Mod_Self[any]` (`:252-261`, requires `c.dispatchable(mod, e.M)`);
  - a public `self.X(` call through an interface literal (`:262-268`).
  - The class-name guard (`:270-272`) rejects the rest.
- **Why the module wrappers stay per class:**
  - `dynWrapperBody` types `self` as the class (`:436-443`), so `typeArgs` (`expr_callcode.go:810-841`) renders `[AndOrI]`.
  - `dispatchable` requires `plainMethod` (`dispatch.go:250-252`: kindDef/kindPrimitive, **not Private**, not generic). So every
    private module method misses `:252`, and the class name in its body fails `:270`.
  - Forwarders use decision 208's case instead (`emit_adapters.go:705-711`: `!sigMentions && !constraintNamesSelf` →
    `Mod_Self[any]`).
  - Of the 131 module constraints in rubocop's `main.go`, only `Comparable_Self` names `Self`.
- **Who gets forwarders:** struct classes forward everything except `dispatchableAll` names (`emit_policy.go:13-37`). Universal
  names come off only through `universalDispatch` (`dispatch.go:244-247`, `emit_policy.go:106-121`).
  - Protocol names stay Go methods: `genericProtocol` lists `==`, `to_s`, `inspect`, `to_json`, `<=>` (`emit_policy.go:40-46`),
    and `dispatchableOwner` (`dispatch.go:222-240`) rejects them.
  - `dynPinned` keeps `DynOp_cmp` per class (`dynamic_wrapper.go:84`).
- **Typed calls of non-dispatched names** are interface method expressions, e.g. `RuboCop_Cop_Layout_IndentationWidthI.Config(self)`
  (decision 122, `expr_callcode.go:778-800`). The pruner then keeps the name on every implementer (`prune.go` `scopedOn`/`ifacesOf`).
- **Respond tables** (`dynamic_send.go:17-71`): each name emits `rbHas_RespondsX` (a class-ID switch) and `rbRespondsX`, which calls
  it. In rubocop: 8,895 `rbHas_Responds*` with exactly one call each (17,790 occurrences = definition + call), 5,004 `rbHas_Private*`
  (three uses each), 8,899 `rbResponds*`.
- **Const-return (13,844)** are per-type metadata accessors:
  - `_ClassID` 3,706 (instances and metas; read by every arm switch);
  - `_DescID` 2,008, `_Kind` 2,010, `_Superclass` 1,703, `_ClassObj` 1,388, `_ClassOf` 1,641, `_Consts` 751.
  - Each metaclass also carries `_Ancestors`, `_Methods`, `_PrivateMethods`, `_ProtectedMethods`, `_SingletonMethods`,
    `_IsInstance`, `Name`, `ToS`, `Inspect`, `Op_cmp`, `cmpNil`, `Include`, `MethodDefinedQ`, `PrivateMethodDefinedQ`, `Autoload`,
    `Loop`, `ToJson`, `Op_eq`, `DynOp_cmp`, `DynInclude` (2,008 each).

## Options, ranked

### A. Module-body Dyn wrappers instantiated at the constraint, as one shared arm (amends 234; applies 208 to wrappers)

- **Change:**
  - In `dynShareable` (`dynamic_wrapper.go:252`), replace `c.dispatchable(mod, e.M)` with decision 208's condition, as in
    `forwardTypeArgs` (`emit_adapters.go:705`): no type params, `!sigMentions(e.M, cls)`, `!c.constraintNamesSelf(mod)`.
  - The existing rewrite (`:255-259`) already turns `[AnyI](self` into `[Mod_Self[any]](self`, and the `private` flag already goes
    into the arm key (`:137`).
  - In `emitDynArms`, emit public and private cases in **one** `_ClassID()` switch. For one name a class has one resolution, so the
    ID sets are disjoint; a private case opens with `if how != rbCall {`. Without the merge, every public receiver of a name with
    private arms pays a second interface call and a missed search.
  - Optionally, build the body once per (module method, visibility) instead of per class in `dynWrappers` (`:127`), to cut
    transpile time.
- **Removes:** 32,403 private + up to 638 public wrappers = ~33.0k source funcs (about 9.5 MB: 6.9 MB of bodies plus headers),
  plus the per-class instantiations of 486 module bodies (~522k lines), which the census does not count.
- **Runtime:** the same work as today. The old path: one or more failed assertions, then `_DynX` through an itab. The new path: an
  int switch (rubocop's cop IDs are contiguous, so a jump table or range compares), then one assertion to `Mod_Self[any]`. The
  body runs on an interface shape either way.
  - Measure: `scripts/benchmark` with instructions retired (`GOMAXPROCS=1`, minimum of 5, as decision 471); the rubocop
    instruction table in `docs/research/runtime-speed-2026-11.md:259-270` on the same 7 inputs.
  - Add a microbenchmark: `send(:private_module_method)` across 600 classes.
- **Invariant:** `self` in the arm is `recv`, the concrete subclass object, asserted to the constraint. Calls through it reach
  the subclass's own Go methods, and module ivars come from the same object (`self._Mod()`). The private arm fires only when
  `how != rbCall`, as `_DynX` does at `:447`. Protected methods are not checked on this path today; that is unchanged *(inferred:
  no `Protected` in `dynamic*.go`)*. `Comparable` and any constraint naming `Self` keep per-class wrappers.
- **Verify:**
  - `dynamic_test` cases: a private module method sent to a subclass whose override the module body calls; a private module
    method with an explicit receiver raises a NoMethodError naming private; `respond_to?(:x, true)`.
  - `RUGAROO_COST=1 go test -run TestCompileCost` (005/064/116 must not grow; decision 234 notes wrappers "grew by what the
    forwarders shrank" without arms), `scripts/gen-compare`, `go test ./...`, `overrides/rubocop/check` on the 15 inputs, census.
- **Risk:** low to medium. A constraint method the pruner slims away is not a hazard: a weaker interface matches more, never less.

### F. Fold `rbHas_RespondsX` into `rbRespondsX` (amends the marker bullet of 209)

- **Change:** `emitRespond` (`dynamic_send.go:46-71`) writes the class-ID switch inline instead of calling `emitMarkers`.
  `rbHas_Private*` stays, since it has three users.
- **Removes:** 8,895 funcs.
- **Runtime:** one call less per `respond_to?`, no regression possible *(inferred)*.
- **Verify:** `testdata/boot`'s `dyn_responds`, `TestCompileCost`, `go test ./...`.
- **Risk:** very low.

### B. Inherited Cop::Base names leave the Go method set (amends 212, extends 234)

- **The answer to Q3:** a parent's Go method always costs one function per subclass. Only a name with **no** Go method (decision
  210's free func `Owner_X(self OwnerI)`, called directly or through an `rbSend_` type switch, decision 212) costs nothing per
  subclass. `self` stays the subclass because it is passed in, never embedded.
- **Scope:** about 14-18k forwarders. My grep finds 23 Base names at 494-620 each, about 14.1k including `Meta_Inherited` and
  `Meta_JoiningForces`; the census counts ~30 names, ~18k.
- **Reasons the names are not dispatchable**, from `rubocop-1.92.1/lib/rubocop/cop/base.rb` read against `dispatch.go`:
  - `config`, `processed_source` are `attr_reader` (`base.rb:43`). `plainMethod` admits only kindDef/kindPrimitive
    (`dispatch.go:250`; `kindAttrReader` at `model.go:162`). That is 1.2k forwarders.
  - `callback_argument`, `apply_correction`, `find_severity`, `range_for_original` are private (`base.rb:400`); `plainMethod`
    excludes private. That is 2.5k.
  - `name` is an alias (`base.rb:246`); `initialize` is excluded by rule; `inspect` is protocol.
  - `message`, `on_new_investigation`, `on_investigation_end` are probably overridden with another Go signature
    (`dispatch.go:78`) *(inferred)*.
  - `cop_config`, `cop_name`, `target_ruby_version`: probably `includerCalls` (`dispatch.go:65`; `AutocorrectLogic`/`Util` call
    them on self) *(inferred; Q1 settles it)*.
- **Change, per reason:**
  - admit attr readers and writers (their free func exists: the forwarders call it);
  - admit private defs (decision 212 does not record why it is public-only; Q2);
  - a module self-call of a name every includer resolves to one dispatchable class method compiles to that owner's free func or
    `rbSend_` with `any(self).(OwnerI)`. Decision 234 already does this for module-to-module calls.
- **Runtime:** typed calls in cop bodies go from interface method expressions to direct, inlinable calls (decision 212 measured
  0.33 → 0.23 s). Module bodies add one itab assertion per such call. Measure with the rubocop table and `benchmarks/objects`.
- **Invariant:** decision 212's (`dispatchableAll` walks ancestors; every override has the same signature).
- **Verify:** as A, plus `RUGAROO_DISPATCH_DEBUG=all` before and after.
- **Risk:** medium. It changes a binding decision's admission rules, so it needs a decision.

### D. Metaclass `<=>` and `include` (amends 398's unbox rule, 209's `dynPinned`)

- `DynInclude` (2,007 copies) differs per class only by `.(RuboCop_Cop_Style_AndOr_MetaI)` on a result that is boxed to `any`
  anyway. Drop the assertion when the result is boxed, as `unboxLeafSelf` does (`dynamic_wrapper.go:316-322`), and the body
  shares a `self.Include(` interface arm (`:262-268`). Removes about 2k.
- `DynOp_cmp`, `cmpNil` and the `Op_cmp` body on every metaclass are about 6k.
  - The fix: `rbCmp` and `rbDynOp_cmp` answer a `ModuleI` receiver with `Module_cmpNil` directly, before the `DynOp_cmp`
    assertion. Then metaclasses need none of the three.
  - Runtime: `<=>` on class objects only; one extra type test on other `rbCmp` fallbacks *(measure benchmarks `collections`, `hash`)*.
- `Include`, `MethodDefinedQ`, `PrivateMethodDefinedQ`, `Autoload` (8k) are kept by method-expression calls on `XMetaI`.
  `Include` is `-> self`, so not `plainSelf`. The others' reason is open (Q1).

### C. Universal names `loop`, `==`, `to_s`, `to_json` (11.6k: 3,645 + 3,174 + 1,168 + 3,648; touches 212/213, 209)

- **`loop`:**
  - Module bodies call `self.Loop()` (`for range self.Loop()`), so their constraints declare it, which puts it on every class.
  - It is not a protocol name and no prelude Go selects `.Loop(`.
  - So some rule rejects it; Q1 says which. If the reason is incidental (an iterator path that skips `sendCall`), removing it
    costs nothing at run time.
- **`==`, `to_s`, `to_json`:**
  - The prelude's Go asserts or calls them by method: `I_ToJson`, `e.Op_eq(y)` at `prelude/go/runtime.go:1021`, and
    `genericProtocol`.
  - Replacing those with generated `rbSend_BasicObject_Op_eq`-style type switches is allowed: compiled code, no map, no reflect.
  - But it moves the hottest assertions (Hash keys, `==`, string conversion) onto a type switch. **Owner sign-off needed**, after a
    Go microbenchmark of an itab assertion vs a 100-case concrete type switch and `benchmarks/{hash,collections,objects,strings}`.
- Making the forwarders "emitted only where a call can reach them" is what the pruner already does by selector (decision 89).
  These names are called everywhere, so pruning cannot remove them.

### E. One descriptor per metaclass (about 25k; touches 121, 209, 213)

- **Change:** fold `_Kind`, `_DescID`, `_Superclass`, `_Subclasses`, `_Ancestors`, the four method lists, `_IsInstance`, `Name`,
  `ToS`, `Inspect` into one `_Desc() *rbClassDesc`.
- **This is data, not dispatch**, so the no-maps rule is not at issue. But the synth `Name` overrides are decision 121's hazard,
  and `_Consts`/`_Ancestors` contents need care at startup (`docs/research/startup-2026-11.md`).
- **Runtime:** one more load on reflection calls; `rescue`/`===` read `_IsInstance`.
- **Owner sign-off; not in the stop set.**

## Already tried or ruled out (do not repeat)

- **Compile-time research, lever 5b** (`compile-time-2026-11.md:96`): "share Dyn-wrapper bodies as a free func the per-class
  method forwards to". Not built, because of runtime doubt. It also keeps one method per class, so it would not cut the count.
  A removes the method instead (decision 85/209/234's arm mechanism).
- **Embedding replaced by a named field and accessors** (209): only −1.7k functions and −3% RSS on 064; not pursued. So promoted
  wrappers are not removed by changing the struct layout.
- **`*C` as type argument** for class owners (208): more dictionary wrappers. Rejected.
- **Decision 235:**
  - giving Dyn methods only to instantiations held untyped saves nothing (brew 97/97);
  - scoping a computed send by receiver class does not help: one untyped site flips the global flag;
  - `Array[any]` with a copy at the boundary costs a runtime copy;
  - precompiled prelude or sharding: no gain.
- **Package split:** 80-91% of lines sit in one strongly connected component (`compile-time-2026-11.md:60-70`). Rejected.
- **RTA dead code:** 2.2% (`:83-85`). Rejected.
- **`-c`** is exhausted (`:49`); the brief adds GOGC, GOMEMLIMIT, `-c=2`.
- **Interfaces instead of generics** for typed code (236): boxes every element. Rejected.
- **Hash entry-level view** (304): more functions for cuba. Reverted.
- **Kernel block-taking generics** get no wrapper (243: +5k in brew).
- **Phase-5 `rt` package** (210, 213, 235): measured, not done.

## Open questions, each with the experiment that settles it

1. **Why does each top forwarder name stay a Go method** (the 30 Base names, `loop`, `Module#include`/`method_defined?`/
   `autoload`)? Run the rubocop gen with `RUGAROO_DISPATCH_DEBUG=all` (`dispatch.go:46-48`) and tabulate the reasons by forwarder
   count. This sizes B, C (`loop`) and D before any code.
2. **Why is decision 212 public-only?** Not recorded. Admit private defs behind a flag and run `go test ./...` plus `gen-compare`;
   failures name the reason.
3. **Does Go compile one body per class-interface type argument?** Count `Util_Line[go.shape` symbols in `go tool nm` of the
   package archive (`go build -work`, then `-gcflags=-S`), before and after A. This confirms A's ~32k instantiations and the
   522k-line figure.
4. **Merged vs separate arm switch:** instructions retired on `rbDynLine` for AST nodes (public) and cops (private), A with and
   without the merge.
5. **Does the linear model hold?** After A alone, rebuild rubocop with `-gcflags=-bench` on an idle machine; compare wall, RSS and
   compiled functions with the table above. If memory falls enough that the rate approaches brew's 5,150/s, the gain is larger
   than the table says.
6. **The 19.7k prism functions and the remaining respond/send tables** (`results-2026-11-12.md:62-64`) are outside this design.
   Dropping prism changes what the `ParserEngine` config can select: behaviour, owner's decision.
