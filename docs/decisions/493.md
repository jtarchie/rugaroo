# Decision 493

**Rule:** A parameter list that repeats a `_` name (`def m(_a, _a)`, `|_a, _a|`, `|_a, *_a|`, `|_z, (_z, _w)|`) binds it once, where MRI does: the first plain parameter, or the last occurrence inside a destructuring tuple when there is one; the other occurrences become Go blanks, and `Method#parameters` still lists the written names.

**Repeated underscore parameters** (2026-11-22). *See also decision 428 (Proc#parameters names are positional).*

Ruby allows a name to repeat in one parameter list when it starts with `_`. rugaroo emitted each one as a Go parameter or `:=` of the same name, so `go build` failed with "redeclared in this block" instead of a compile error. Spinel's matz/spinel#12391 (a rename that leaked a slot name like `_a__dup1` into `#parameters`) prompted the probe; rugaroo never renames a written name, so its reflection was not affected.

- **Methods and lambdas:** `goParamName` takes the parameter list; a repeat (`repeatedParam`) gets the throwaway Go name `_` already gets (`rbU<i>_`), and `paramLocals` and the `*rest` prologue skip it, so reads see the first. `Param.Name` keeps the written name, which `rbMethodInfo` lists.
- **Blocks:** `blankRepeated` rewrites `blockParamList`'s names once: MRI binds plain parameters first and destructuring tuples after, so the winner is the last tuple occurrence, else the first plain one; the rest are `_` (an anonymous rest for `*_a`). Every binding path then sees distinct names.
- **Not covered:** a repeated keyword (`_k:` twice), since block keywords are decision 456's narrow form; `Proc#parameters` still names parameters positionally (`p1`, `p2`; decision 428).

Proved by `RepeatedUnderscoreParamTest` in testdata/test/method_test.rb against MRI.
