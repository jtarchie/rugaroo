# Decision 438

**Rule:** Enumerable's Symbol and init forms resolve at compile time: `inject(:sym)`/`inject(init, :sym)` with a literal Symbol is the block form `inject(&:sym)`, a String or Array `sum(init)` is `inject(init, &:+)`, a numeric `sum(init)` picks `__sum_<class>` (and `__sum_<class>_block` with a block) by init's class, and a Symbol only run time knows is a compile error.

2026-11-11, issue #145. MRI's `inject(sym)` is `send(sym)` per element; rugaroo has no runtime method table (memory: compiled dispatch), so the literal Symbol is the only form that compiles, and it compiles to the `&:sym` block path that already typed `(A, E) -> A`. `inject(op)` with a Symbol variable fails with "inject(sym) needs a literal Symbol" rather than "requires a block".

`sum(init)`'s result class follows init's through the numeric tower: an Integer init sums to the element type (`[1.5].sum(3)` is a Float), a Float init is always a Float (Kahan-Babuska from init, as enum.c), any other numeric init (`Rational`) is `[N] (N) -> N`. Decision 12's `__<name>_<class>` covers the blockless call; a call with a block now also tries `__<name>_<class>_block` (`classBlockOverload`) before `blockOverload`, and `__<name>_block` no longer takes a call with arguments (`xs.sum(10) { }` is `__sum_1_block`, not `__sum_block`). String and Array inits go through `+` as MRI's sum does past the tower, so they are the inject rewrite; with a block they stay numeric-only.

See also decision 12.

*See also decision 450* (#145): the second batch of Enumerable forms; `sum(init) { }` with a String or Array init.
