# Decision 495

**Rule:** Tuples go up to 14 elements, an unread `_`-prefixed target of a multiple assignment is Go's blank, and `sig/gems/racc` types racc's pure-Ruby parser loop by its 14-element `Racc_arg`.

**Racc's parser loop typed** (2026-11-23). *See also decision 135 (the old 7-element limit), decision 160 (vendored gem sigs).*

A compiled program runs racc's pure-Ruby runtime (`Racc::Parser#_racc_do_parse_rb`, `_racc_evalact`, `_racc_do_reduce`); MRI runs its C core, cparse. The runtime reads every grammar table out of one mixed constant Array, `Racc_arg`, destructured at the top of each method (`action_table, action_check, _, _, ... token_table, * = arg`), so inference left every table untyped and every lookup and comparison in the loop was a dynamic call. A profile of compiled rubocop on 250 files of a private Rails app put ~0.8 s of the 3.4 s per-file loop there, more than the lexer (0.29 s) or the grammar actions (0.28 s).

- **`sig/gems/racc/racc.rbs`** declares the loop's three methods with `Racc_arg`'s real shape: eight `Array[Integer?]` tables (one `Array[Integer]`), `nt_base`, the reduce table (`Array[Integer | Symbol]`), the token Hash, `shift_n`, `reduce_n` and `use_result`. `_racc_evalact`'s `act` is `Integer?`: the error branch reassigns it from `action_table[i]`, which can be nil.
- **14-element tuples.** `maxTuple` was 7 (Socket's getaddrinfo rows). Past it a gem's tuple was `Array[untyped]`, so the sig typed nothing. Every arity is still emitted and pruned when unused (decision 432), so a program without wide tuples is unchanged.
- **Unread `_` targets.** `a, _, _, b = t` assigned `_` like any local, so two destructures giving `_` an Integer and then an Array widened it to untyped, and the Go did not compile (`var _ any`, then `_.(Integer)`). Now a target whose name starts with `_`, which nothing reads, is `_ = value` (nothing for nil). A `_x` that is read is a plain local as before.

**Measured** (instructions, 250 files of a private Rails app, TargetRubyVersion 2.7, macOS): the parser-only program went 11,854M -> 9,656M (MRI 11,851M); compiled rubocop 40,927M -> 38,289M, byte-identical output (MRI 40,010M).

**Not done:** the reduce table's `Integer | Symbol` elements keep `_racc_do_reduce`'s `len`/`reduce_to` reads as union dispatch, and the `__send__(method_id, ...)` to each grammar action stays dynamic. The constant itself is untyped (a mixed Array literal), so `_racc_setup` converts it to the tuple once per parse.

Proved by `WideTupleTest` in testdata/test/array_test.rb against MRI and `tuple_fifteen_elements` in testdata/errors/arrays.txtar.
