# Decision 448

**Rule:** A Hash whose keys are `String?` (Go `*String`) hashes and compares each key by its bytes in its own table (`rbHashFindStr`), with no `rbKeyIndex` canonicalization; every other Hash's lookup path is unchanged.

**One lookup for `String?` keys** (#154; amends decisions 388 and 397; 2026-11-13). *See also decisions 138's fast path (#138), 440.*

Since decision 440, `freq = {}` filled from an Array of `String?` stays `Hash[String?, Integer]` (spinel's bm_wordfreq). Each `key?`, `[]` and `[]=` looked a key up twice: `rbKeyIndex.find` hashed the String's bytes to find the stored key pointer equal to it in a Go map (`byHash`), then `rbHashFind` hashed that pointer again through `maphash.Comparable` for the open-addressing table.

- **The flag.** `NewHash` sets `idx.str` when K is `*String` (`rbStrPKey`); a key set (`uniq`'s) leaves it off and keeps `find`'s canonical path. `compare_by_identity` clears it (identity is pointer equality, `plain`).
- **One path, entered once.** Inside each lookup's existing `!idx.plain` branch (`rbGet`, `rbHashSlot`, `[]=`, `delete`), a `str` Hash calls `rbHashFindStr`: a scan of up to `rbSmallHash` entries, or the slots probed from `rbHashOf(k)`, comparing with `rbStrPEq` (both nil, or equal Strings). `rbHashOf` hashes a `*String` by its bytes (nil to a fixed value), which rehashing and deletion use too. The checks sit only on the non-plain branch so `rbHashFind` keeps its size: a first version that tested the flag inside `rbHashFind` and the scans measured `benchmarks/hash.rb` +7.3% (Integer keys), `collections` +1.9%, `json` +1.0%.
- **Unchanged behaviour:** insertion order, `nil` as a key, a String key mutated after insertion (decision 397 copies an Array's String on read, so the stored key is the Hash's own).
- **Measured** (instructions retired, macOS arm64, `GOGC=off GOMAXPROCS=1`, old and new binaries alternating, min of 7, against main f45f0d3a): bm_wordfreq at 1M words 1,537M → 1,015M (−34%; output == MRI); bm_csv_process 2,013M → 1,822M (−9.5%); `benchmarks/` hash −0.57%, collections +0.23%, json +0.26%, strings −0.02%.
- **Compile cost** (`TestCompileCost`, 11755457 → a8c3baf3, with decisions 445-453): compiled functions 005_word_count 2,063 → 2,071, 064_observable 8,324 → 8,334, 116_cuba_web 33,183 → 33,293 (+0.1-0.4%): `rbHashFindStr` is instantiated per Hash type though only a `String?` key reaches it (ponytail: a non-generic entry would drop it); wall and CPU within noise.
- **Proof:** `testdata/test/hash_test.rb` `HashStringOptKeyTest` (counting `String?` words with a `nil` key, equal Strings from different reads, delete, past `rbSmallHash` entries) against MRI.
