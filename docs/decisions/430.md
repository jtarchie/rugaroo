# Decision 430

**Rule:** The CLI keeps each program's inferred parameter types on disk, and a compile whose inputs all hash the same starts from them and runs no inference rounds; any changed input, or any error from the cached start, compiles cold, so the output is always what a cold compile makes.

2026-11-01, compile-time research (docs/research/compile-time-2026-11.md). Decision 146's rounds are most of a large compile: the rubocop CLI's gen is 388 s, of which the 8 rounds are 284 s. The rounds only exist to type pending keys (unannotated parameters, yielded values, lambda arguments, an escaped block's `self`: `pendingType`); a compile that meets none untyped runs one pass. The in-process seed `cmd/rubyspec` already carries (`Inference`) showed what that buys, byte-identical: liquid 4.7 → 1.5 s, kramdown 24.6 → 6.6 s, rubocop 347 → 52 s of compile.

**What is kept** (`internal/compiler/infercache.go`): the `inference` (types, and the `none`, `noUnion`, `noDrop`, `from` key sets) and the generic instances the compile created (decision 308; without them a hit restarts per instance). A type is stored by kind with its classes by Ruby name (`cachedType`), and decoded around placeholder classes that `rehome` resolves, the same path a type takes between rounds; internal class names (`ANY__Singleton`, `RbAnon…`) need no RBS spelling. Measured before building: 1,612 rubocop and 427 tokenize types, all of the nine `Type` kinds rehome handles. A program with no pending keys keeps no file.

**Where and by what key.** `os.UserCacheDir()/rugaroo/infer/<hash>.json`, the hash over the compiler binary's own sha256 (another build, so another prelude or other rules, never loads a cache), the sources by name (a traced entry's path is its content hash, decision 88, which a changed load list would move), the load path, gem dirs, the options that change output, and the output-changing part of the `RUGAROO_*` environment (diagnostics such as `RUGAROO_TIMING` do not split the cache). The file carries a manifest: each input's hash by the path its keys start with (every non-prelude source file, every sig file tried, including an absent sidecar), and the boot manifest's hash (minus MRI's object addresses and the hook's temp dir, which differ every run). Written atomically (temp file + rename).

**A hit only when nothing changed.** Any input whose hash differs, or a different boot manifest, compiles cold and rewrites the cache. Partial reuse was built and measured first: drop the changed files' keys and run the rounds from the rest. Liquid with one comment line added to main.rb converged in 3 rounds instead of 8, but `Liquid::ResourceLimits#render_length` came out `untyped` where a cold compile types it `Integer?`: the rounds are not confluent (where they start changes where they end; kramdown never converges at all, three keys flipping each round). A cache whose output depends on history breaks decision 88 and here also loses a type, so it was taken out.

**Never worse than cold.** Any error from a cached start (a seed key that no longer fits, a missing instance the restarts cannot reach) is retried as a cold compile; only the cold compile's error is reported. Tests never turn the cache on (`SetInferCache` is the CLI's), so the oracle is cold. `RUGAROO_NO_INFER_CACHE=1` turns it off. `TestInferCache` checks a hit is one compile pass and byte-identical, and that an edited input compiles cold.

Not done: `refineIvars`' accepted set (decision 15's container ivars; ~18 s of a rubocop hit) is still recomputed; caching it needs the same exactness argument. Old cache files are never collected (`// ponytail:` in `writeEntry` has the same gap for entries).
