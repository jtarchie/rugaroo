# Decision 480

**Rule:** A final pass that widens a parameter (decision 444) gives the parameter its wider type at once when the pass will run again, so the methods emitted after it widen what they pass on in the same pass; the last pass allowed leaves its signatures alone.

**One more pass, not one per link** (2026-11-21). *See also decisions 444, 478, 479.*

Decision 444's final pass notes a parameter the rounds typed too narrowly where a call passes it something that does not fit (`noteWidenPending`), and runs again with it widened. The wider parameter then does not fit what its own method passes on, which the next pass notes, and so on: rubocop's Myers diff ran three more passes of about 30 s each for one value (`RUGAROO_TIMING` now names the parameters):

```ruby
return backtrack(trace) if reached_end?(...)        # trace: Array[untyped]
trace.each_with_index.reverse_each do |furthest, distance|
  previous = previous_position(furthest, distance, *position)   # the next pass: furthest untyped
def previous_position(furthest, distance, old_index, new_index)
  previous = previous_diagonal(furthest, old_index - new_index, distance)   # and the one after
```

A pass that has widened anything is thrown away, so nothing it emits afterwards has to agree with what it emitted before. `widenParam` therefore writes the wider type into the method's `Param` as it records it; a method emitted later is typed with it, and its calls are noted in the same pass. Emission follows source order, so a chain that runs down a file (caller above callee) is one pass; a link that points up the file still takes its own.

The pass at the cap (`maxWidenRedo`) is the one whose output is the program, so it changes no signature (`widenChain`).

**Measured** (idle machine, rubocop 1.92.1, transpile only): final-pass reruns 3 -> 1, compile 262 s -> 222 s, generated Go byte-identical. The parser gem's test program has one rerun either way.
