# Decision 444

**Rule:** The rubocop CLI compiles and runs under `-trace` with three small gem patches and no `eval`: gem code's run-time shapes (an untyped value where a typed parameter or ivar was guessed, a block or `break value` through an untyped call, `self::CONST` per subclass, a run-time `autoload`) compile to what MRI does when they run, an ivar typing that stops a gem method compiling is vetoed instead of poisoning the method, and the inference rounds try the previous round's ivar typings first.

**rubocop as a compile target** (2026-11-12; #149). Amends decisions 4, 13, 15, 20, 141, 146, 175, 205, 241, 307, 331, 428 and 433. *See also decision 140 (the `Float::INFINITY` range end #149 named as a blocker is no longer reached: see the gem patches) and decision 430 (the inference cache is unchanged).*

The question #149 left open: does a compiled rubocop produce a lint result? It does. `docs/research/rubocop/round.sh` builds rubocop 1.92.1 (rubocop-ast 1.50.0, parser 3.3.13.0 on its whitequark lexer, regexp_parser 2.13.1, racc, rainbow) and the binary's stdout, stderr and exit status equal MRI's on the same patched copies. Every stop on the way was found by running the binary, reproduced in a 10-second `-gem` program, and fixed by a general rule; none of the rules below names rubocop.

*This file is written as the work lands; the measurements and the test list at the end are filled in when the branch is merged.*

## Gem patches (docs/research/rubocop/*.patch)

A patch is used only where the Ruby asks for something a compiled program cannot do. Each leaves MRI's output on the test inputs unchanged; two drop behaviour and say so.

- **rubocop-ast, `def_node_matcher`/`def_node_search`:** return at once when the class already defines the method. Under MRI the method never exists yet, so nothing changes. In a compiled program decision 204 compiled every matcher at boot, so the pattern compiler (which reads `(0..Float::INFINITY).max`, decision 140) no longer runs at startup.
- **rubocop, ERB in configuration files:** `ERB.new(text).result` on a `.rubocop.yml` is `eval`. The patched loaders take the text as it is and raise `RuboCop::Error` when it contains `<%`. *Behaviour dropped: ERB in config files.*
- **rubocop, `YAMLDuplicationChecker`:** stubbed (Psych's tree API is not built), the config loaded with `YAML.safe_load`. *Behaviour dropped: the duplicate-key warning.*
- **rubocop, small rewrites with the same meaning under MRI:** `args = define_options.parse!(args)` (the dynamic call converts the untyped Array, so the in-place edit was lost); `callbacks_needed` finds a callback's owner with `ancestors.find { |m| m.instance_methods(false).include?(name) }` instead of `instance_method(name).owner` (decision 141: no method object for a computed name); `"-#{s}"` for `s.insert(0, '-')`; three `define_predicate ... child_index: 1..-2` written out (decision 198).
- **regexp_parser:** `Struct.new` with its members written out, and a `def` for an alias of a `class_eval`'d method.

## Typing rules

- **A gem method an ivar typing stops compiling vetoes the typing** (amends 15, 205). `refineIvars` tries a typing by emitting the classes that see the ivar. A gem method that failed in such a try was poisoned for good (decision 205) and the try counted as passing, so `@options = {}` with one typed store became `Hash[Symbol, Boolean]` and every method storing a String into it raised `NotImplementedError`. Inside a try the error now propagates and the typing is dropped.
- **Conversions are compared by site and target** (amends 307). A try's `rbAs[*Hash[Symbol, Boolean]]` at a site is not the untyped baseline's `rbAs[*Hash[any, any]]` there; it can fail on the Hash's contents. A destructured ivar store (`@options, paths = parse(args)`) counts as a store.
- **A container of untyped is element evidence** (amends 13, 15). `@stack << Set.new` beside a `String?` is evidence of a class the element type must hold; only a plain untyped value is ignored.
- **Settled rounds untype a gem parameter fed an untyped gem argument** (amends 146, 331). The rounds never converge on a large gem program: a few parameters flip until the cap. Once a round changes at most 2% of the parameters, a gem parameter that some static gem call passes an untyped value becomes untyped, and the rounds go on. A typed one would assert the class at the call and raise where MRI runs (`StaticEnvironment#declared?(name)` typed Symbol, called with a String it calls `to_sym` on).
- **The final pass widens a round-typed container parameter** (amends 146). A round types ivars from what it has seen, so a parameter can take `Hash[Symbol, Boolean]` from an ivar the final pass leaves untyped. The final pass records such a parameter, makes it the untyped container and runs once more (`errWidenRedo`, at most 4 times).
- **`x ||= value` narrows x only when the value cannot be nil.** `root ||= yield` followed by `root ||= if ...` compiled the second away as dead.
- **Sibling subclasses of a core value class stay a union** (rainbow's `Presenter | NullPresenter`, both `< String`), converted member by member where a String is wanted; `self.class.new(text)` in a leaf String subclass is its own constructor.
- **An override keeps its own parameter defaults** and, when they differ from its ancestor's, both take callee-side defaults; a slot adapter passes the caller's argument count on.
- **A subclass's included module overrides a superclass method** (`BuilderExtensions#n` over `Parser::Builders::Default`'s private `n`), so the superclass's calls dispatch.
- **A gem override's untyped tail under an inherited return type** answers what fits, else the zero (decision 428's adapter rule, for the override's own body).

## Run-time shapes in gem code

- **Blocks:** an untyped delegator (`def_delegators :@hash, :each, :each_key, :map`) forwards its block; a named `&block` forwarded into a method that yields several values takes them all; an untyped callable (`&predicate`, one of two Method objects) is `{ |*xs| predicate.call(*xs) }`; a destructuring block parameter binds on an untyped receiver; `|(x)|` binds the first element (it was read as `|x|`); `with_index` without a block and `with_object` work on an untyped Enumerator; a gem class with its own `transform_values` gets its own arm in `dynEnumBlock`; an iterator call used as a value (`h.each_value(&:freeze).freeze`) runs as a statement.
- **`break value`** out of a gem block (amends 4, 241): through `rbBreak`'s new `val` for a closure block, through the loop's result variable for an iterator. User code keeps the compile error.
- **`super`:** an alias's `super` looks up the name its body was defined under; a module method an includer reaches through `super` stays in the module beside the other includers' copies; `super` in a class's own `def self.new` is `Class#new`.
- **Constants:** `self::CONST` that subclasses redefine is `const_get` on the receiver, typed as the join over the subclasses; a constant named as a String (`'ProgressFormatter'` in a table read by `const_get`) keeps its autoload file (amends 175); `rescue ::Bundler::GemfileNotFound` of a library the program never loads matches nothing and raises `NameError` if an exception reaches it.
- **`autoload` with run-time arguments is a no-op** (amends 175, 324): `register_cop` calls `autoload constant_name, path`. Every file the traced run loaded is in the binary; one it did not load is not, and naming its constant raises `NameError`. A `-trace` run must load what the binary is to hold. `Const.autoload :X, path` at the top level is that class's autoload.
- **`$LOADED_FEATURES`** in gem code is the list of source files compiled in, the same wherever it is read. **`nil.methods`** and **`Kernel.methods(false)`** are MRI's own lists for the release `.mri-version` names (a linter compares method names against them); regenerate them on a Ruby upgrade.
- **Splat:** `*x` of an untyped x spreads a gem object's own `to_a` (`name, = *node`); a gem `to_a` answering an Array or a tuple spreads at run time; `end_with?(*list)` takes any number, none included; an untyped `**hash` into keyword parameters has its keys checked when it runs; `a, *rest = x` of a union splits at run time.
- **Library:** `Hash#compare_by_identity` (object identity for objects; a String, Float or tuple key still matches by content, since it is a Go value), `Set#compare_by_identity`, `Hash#merge!`/`update` with a block, `String#match` with a block, YAML's `!ruby/regexp`, `Array#to_h` on untyped elements (pairs checked when it runs; a typed receiver keeps its compile error), `Symbol#start_with?` with several prefixes, an Array sliced by a Range of untyped bounds, a wrong-class key in `Set#include?` is a miss, `Gem.loaded_specs`/`path`/`win_platform?` (empty: a compiled program activates no gems).

## Compile time

- **Inference rounds try the previous round's ivar typings first** (amends 15, 433). `refineIvars`' search is 2n+2 dry-runs (decision 15's salvage). Each round after the first tries every candidate but those the previous round dropped, and searches only when that does not compile. The final pass always searches. On the rubocop repro a round goes from 33 s to 14 s.
- **A dry-run reuses the local typings its method kept last time** (amends 13). Inside `refineIvars`, a method's own search over its container locals (2m+2 emissions) runs once; later dry-runs try all, then the kept set. Without it the parser gem's 5,000-line lexer method made one ivar search run for over ten minutes.
- `RUGAROO_CONST_DEBUG=1` prints why a gem constant was left nil (decision 205) even when a discarded pass was the first to type it, where the warning is dropped.

## What this does not do

- A run-time `autoload` of a file the trace did not load, ERB in config files, and rubocop's `--server` mode stay unsupported.
- The gem-warning list is incomplete for methods first poisoned in a discarded pass; the complete list is every `does not compile` string in the generated Go (`docs/research/rubocop/stubs-2026-11-12.txt`).
- `-gem dir` with a lazy `require "yaml"` breaks MRI's psych in the boot run (not investigated).
