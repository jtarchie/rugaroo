# Decision 478

**Rule:** `RUGAROO_TIMING` splits an inference round into `ivars`, `r-refine`, `r-rets`, `r-uses` and `r-update`; a compile's sources are parsed and scanned again in every round and pass, because later passes rewrite the syntax tree and the scan depends on what earlier passes found.

**Where a compile's rounds spend their time** (2026-11-21). *See also decisions 146, 430, 444.*

Each inference round and each final pass is a whole `compileWith`: a new `Compiler`, the prelude, the sources, link, ivar discovery, then the bodies. `RUGAROO_TIMING` now splits a round (`ivars`, `r-refine`, `r-rets`, `r-uses`, `r-update`), and on the parser gem's test program (8 rounds, 3 final passes, 47 s on an idle machine) says:

| step | total | per pass |
|---|---|---|
| `r-refine` (refineIvars: re-discover, a baseline dry run, the tries) | 17.8 s | 1.2 s, and 8.9 s in the one round that searches (17 dry runs) |
| `infer` (the final passes' refine and returns) | 5.9 s | 2.0 s |
| `r-uses` (every method emitted for its calls' argument types) | 5.6 s | 0.7 s |
| `ivars` | 5.0 s | 0.45 s |
| `prelude` | 4.7 s | 0.39 s |
| `format`, `emit`, `r-rets` | 2.6, 2.4, 2.1 s | |
| `link`, `user` | 0.7, 0.4 s | |

`prelude` is not the prelude: `scanRequires` runs in it, and it parses every source and required gem file through prism's wasm again, 12 times for one compile.

**Tried and taken out: keeping the scan's files for the compile's next passes.** On the parser program it took `prelude` from 4.6 s to 0.7 s (compile 46.6 s to 42.6 s) with identical output, and `scripts/gen-compare` over everything then failed 3 of 272 inputs, for two reasons that are not three bugs:

- **Passes rewrite the tree.** `forwardArgs` replaces a `def m(...)`'s `g(...)` arguments in place at link time, so the next pass finds no forwarding call (`object_test.rb`: "needs one call that forwards with (...)"). Other in-place rewrites exist (`exprNode` receivers on copies are safe; `lambdaOpt`, `movedOpts`, `kwBlocks` record more); a shared tree needs every one of them repeatable, or a deep copy the prism binding does not have.
- **The scan is not a function of the sources alone.** What a pass autoloads or drops (`opts.autoloaded`, `lazyAutoloads`, `droppedLazy`) changes which files the next scan walks (`require "prism"`: `Prism::Visitor` unknown).

A reuse that is safe needs a tree copy, or a parse cache below the tree (the wasm call's serialized answer, decoded per pass); the decode is most of the cost, so the second is worth measuring before building.

**Not done, in the order the table gives.** A round walks every body about five times (discovery, refine's baseline and try, returns, uses), and the walk for uses is the only one whose result the next round reads; one walk per round that records ivar writes, container elements, returns and uses together against the last round's state is the redesign that would cut a round to about a third. The searching round's 17 dry runs (78 s of rubocop's 456 s) and the final pass run again for a handful of widened parameters (rubocop: three more passes of 33 s for 4, 1 and 1 parameters) are the two next largest.
