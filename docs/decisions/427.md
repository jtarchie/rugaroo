# Decision 427

**Rule:** `require "prism"` compiles the prism gem's own Ruby, bundled at prism.wasm's release in `vendored/prism` (no `ruby` or installed gem at build time), and answers `require "prism/prism"`, the C extension, with `prelude/prism.rb`: prism/ffi.rb's API over prism.wasm, run under wazero in the program, whose bytes the gem's `Prism::Serialize` turns into the tree.

Research spike, 2026-10-30. Goal: rubocop-ast's default engine (`Prism::Translation::Parser40`) running compiled. Before this, `prism` was in `mriLibs`: `require "prism"` was a no-op and `-trace` skipped the gem's files.

**Where the Ruby comes from: bundled, compiled as an installed gem is.** First built against the installed gem (decision 173), then switched the same day: prism ships with MRI, so a program should not need `ruby` and a matching gem to build, and with the installed gem the wasm and the Ruby could disagree (serialize.rb raises "Invalid serialization" on another release's bytes; three prism versions were installed here, and rubocop-ast asks for `prism ~> 1.7`). Bundled, they are one release by construction.
- **Layout.** `vendored/prism/{lib,sig,LICENSE.md}` is the 1.9.0 gem's, less the C extension and prism/ffi.rb, copied by `scripts/vendor-prism` from the released `.gem` (node.rb, serialize.rb and dsl.rb are generated at gem build time, so a ruby/prism submodule would not hold them), plus `sig/0_rugaroo.rbs` (below). `TestPrismWasm` holds serialize.rb's version to `prismVersion`, the wasm's `pm_version` and `prelude/prism.rb`'s `VERSION`; `TestVendoredMirror` leaves it out.
- **Not decision 328's vendored route.** That is one `lib/<require>.rb` compiled as strict user code without `require_relative`; prism is ~30 files and 45,000 lines, unannotated, with autoloads. It is compiled as gem code instead: decision 169's pruning, 172's leniency, 306's shipped `sig/`, which types node fields (`Symbol`, `Integer`) that inference left `untyped`.
- **Mechanism** (`internal/compiler/bundled.go`). `bundledGems` makes `prism` a builtin lib, so gem lookup and `-trace` never ask MRI for it and an installed prism (a rubocop-ast dependency) is dropped from the gem dirs. A require of `prism` or `prism/x` extracts `vendored/prism` from the embedded FS to `os.UserCacheDir()/rugaroo/bundled/prism-<content hash>/` once per process (atomic rename; the compiler reads gem files by path, `// ponytail:` until gem dirs can be an `fs.FS`) and adds its `lib` to the gem dirs, which turns on gem pruning. `go:embed` takes the whole directory. The playground has no filesystem, so prism does not compile there.
- **Autoloads without a boot.** Nothing runs prism under MRI, so its autoloads are resolved statically (`bundledAutoloads`): each one a bundled file registers is parsed and handed to decision 175's `neededAutoloads`, which keeps a file when a kept file names one of its constants. Two refinements: `prelude/prism.rb` counts as a kept file (it names `Serialize`), and `prism/translation*` and `prism/lex_compat.rb` are optional (`bundledOptional`): only a name from outside the gem's core loads them, since they need the parser, ruby_parser or Ripper gems and lex_compat.rb's own mention of `Translation::Ripper` would otherwise drag them into every program. So `Prism.lex_compat` does not work unless the program also names `Prism::Translation`.
- **`Prism::BACKEND`** is `:CEXT`, set in `prelude/prism.rb`: prism.rb's own assignment is under `if RUBY_ENGINE == "ruby" and !ENV["PRISM_FFI_BACKEND"]`, which cannot fold, and a constant write in a top-level `if` is skipped (decision 205).

**The backend.** `preludeLibs["prism/prism"]` is `prelude/prism.rb`: `Prism.dump/lex/parse/parse_comments/parse_lex/parse_success?/parse_failure?/profile` (and their `_file` forms, which `File.read`), `StringQuery.local?/constant?/method_name?`, `dump_options` ported from prism/ffi.rb. Each calls `rbPrismSerialize(fn, src, opts)` or `rbPrismCall` (`prelude/go/prism.go`), which run `pm_serialize_parse`, `pm_serialize_lex`, `pm_serialize_parse_comments`, `pm_serialize_parse_lex`, `pm_parse_success_p` or `pm_string_query_*` in a wazero instance and copy the buffer out. go-ruby-prism exports only `pm_serialize_parse` and keeps the wasm bytes unexported, so `prelude/go/prismwasm.go` holds them (gzip, base64: 492 KB → 223 KB), generated by `scripts/prism-wasm`. The gem's prism.rb picks its backend with `if RUBY_ENGINE == "ruby" and !ENV["PRISM_FFI_BACKEND"]`, which cannot fold; prism/ffi.rb is shadowed (`shadowedGemFile`) by the same prelude lib, so the FFI branch loads nothing (`PRISM_FFI_BACKEND` is ignored).
- **Why a String constant, not `//go:embed`.** The output is one `main.go` (`rugaroo gen > main.go` must build with `go.mod` alone); an embed needs the file beside it, and cannot reach another module's files. The pruner drops the constant from programs that do not require prism: example 05's `main.go` is byte-identical to before.
- **wazero in the program.** `GoMod` requires `github.com/tetratelabs/wazero v1.9.0` (already rugaroo's own dependency through go-ruby-prism), imported only when the helper survives pruning. The module compiles once per process (`sync.OnceValues`) through the compiler's own cache dir (decision 156; same bytes and wazero version, so a machine that ran rugaroo hits it; `RUGAROO_NO_WASM_CACHE` opts out). Instances come from a `sync.Pool`: one is not safe for two goroutines, and a pool is not a lock. Measured on an M-series Mac: AOT compile 160 ms cold, 7 ms from the cache; the interpreter compiles in 19 ms but parses ~9x slower (430 µs against 50 µs for a two-line file), so it is not used. A process that parses once runs in 22 ms.

**Three backend mechanisms**, each named `gemBackends`/`backendNamed` and limited to `prelude/prism.rb`:
- **Reach walks it whole** (`reach.go`). Prelude methods are always compiled, but decision 169 walks a prelude def only when something calls it; `Prism.lex` then compiled against a `Serialize.load_lex` the pruner had dropped.
- **Autoloads it names load** (`backendNamed`, and `neededAutoloads` notes it). serialize.rb loads through an autoload only the backend names. Its own `require "stringio"` is not walked by the require scan on that path, so the backend `require_relative`s stringio itself.
- **Its defs win over the gem's** (`addDef`). It loads before the gem's files, so the gem's later `def` would replace it. It replaces one: `Serialize::Loader#initialize`, less `raise unless serialized.encoding == Encoding::BINARY`, since a rugaroo String has no encoding flag (bytes that are valid UTF-8 report UTF_8, `prelude/encoding.rb`). `Prism.load` of a non-binary String therefore does not raise as MRI does.

**The gem's shipped sig is patched** (`vendored/prism/sig/0_rugaroo.rbs`, written by `scripts/prism-sig` from the bundled `sig/prism/node.rbs`; first in the sig dir's walk, so it wins per member, decision 306; it lives in the bundle because `sig/gems/` is only read by gem-lookup compiles). serialize.rb passes every node location packed into an Integer (`(start << 32) | length`) unless `freeze:`, and each reader unpacks it on first read; the sig says `Location`. The patch types every initialize's Location parameter `Location | Integer`, `Node`'s `@location` the same, and each `*_loc` reader (an `attr_reader` in the sig, a lazy `def` in the code) a `def` answering `Location`/`Location?`; and `Loader#load_node` answers `Node` (its `case` has no `else`).

**General fixes the gem needed**, each with a narrow test:
- **A file under several autoloads** (prism's visitor.rb: `BasicVisitor`, `Visitor`): `neededAutoloads` kept one constant per file, the first boot saw, so naming the second dropped it (`testdata/boot` `Demo::BothA`/`BothB`).
- **A stale shipped sig in gem code is dropped** when its arity, rest or keywords do not fit the def: prism 1.9.0's `Source.for: (String) -> Source` for a 3-parameter def, `lex_compat: (String, ?command_line: ...)` for `**options` (`sigFitsDef`; `testdata/boot/sigdemo`'s `scaled`, `summary`). Inference types it as with no sig. A program's own sig stays strict.
- **`String#unpack`/`unpack1(fmt, offset:)`** (serialize.rb's constant pool), the gem's `__unpack_wrap` (decision 324) too; `@` counts from the string's start, as MRI's (`string_test`).
- **A prelude def with keywords reports its parameters by name**, as MRI does for the core methods it writes in Ruby (`unpack1`, `clone`, `warn`, `IO#readline`): prism's `polyfill/unpack1.rb` prepends a Module to String unless `instance_method(:unpack1).parameters` has `offset`, and rugaroo's `[[:rest]]` sent it there (`method_test`). The prelude's `IOReadable#readline(chomp:)` reports `[[:key, :chomp]]`, where MRI's IO#readline also has `sep` and `limit`.
- **`RUBY_ENGINE == "x"` and `!=` fold** in class-body conditions, as `RUBY_VERSION` does (decision 167): serialize.rb's `if RUBY_ENGINE == "truffleruby"` and `if RUBY_ENGINE == "ruby"` around `load_node` (`object_test`'s `Guarded#engine`).
- **For Translation::Parser40, under `-trace`:** `attr_accessor(*FLAGS)` of an assigned literal Symbol Array, `.freeze` or not (parser's Context; `testdata/run/gem_lenient`); a boot-recorded class-body `class_eval <<~RUBY` site is registered before any file is collected, since the traced entry loads racc before main's turn collects the evals (racc's `do_parse`); `-trace` no longer skips racc for having a C extension (`pureFallback`: its parser.rb rescues the LoadError of `racc/cparse` into its Ruby routines; prism is bundled; boot defines racc's own `Racc_No_Extensions` switch, so its class_eval'd `do_parse` calls the Ruby routine the program has, not MRI's `_racc_do_parse_c`: `TestTraceRacc`); and `Kernel#gem` (prism's translation/parser.rb calls `gem "parser", ">= 3.3.7.2"`) answers true. It is defined in `prelude/prism.rb`, not core: a new core Kernel name added a `_Dyn` wrapper per class to programs that dispatch dynamically (example 64: +37 functions). MRI answers false on a second activation.

**Measured.**
- `TestCompileCost`: 2,065 / 7,950 / 30,379 compiled functions, unchanged; example 05's `main.go` byte-identical. Two near-misses on the way: `goCalled` (decisions 212-213) scans prelude source text, comments included, so a Go `x.Call(` in `prism.go` made `call` a Go method on every class (cuba +11); the helper uses wazero's `CallWithStack`.
- Example 136: 98,000 Go lines, ~10,700 functions (`scripts/census`: 1,839 Dyn wrappers, 1,843 forwarders); all 152 node classes stay, since `inspect` reaches each one. gen 5.5 s, build 12 s warm, binary 19 MB.
- `Serialize.load` compiled is fast; the wasm is the cost. On a 964-line file (prelude/string.rb, 24 KB serialized), per call: `Prism.dump` 1.7 ms here, 0.35 ms in MRI's C; `Prism.load` 0.6 ms here, 3.2 ms in MRI's Ruby loader; `Prism.parse` 1.65 ms here, 0.65 ms in MRI (whose C extension builds the nodes without serializing).
- Ractor: only prism/ffi.rb names it (`require "prism/serialize" if defined?(Ractor)`), and that file is shadowed.

**Not done.**
- **Translation::Parser40 compiles but does not run.** Under `-trace` (racc's `class_eval` needs the boot capture; the program needs `require "parser"` beside `require "prism"`) the build succeeds in ~1m45s with ~6,400 gem warnings, mostly the parser gem's lexer. Bundled, its first run-time stop is prism's `polyfill/append_as_bytes.rb`, which includes an anonymous Module into String when `"".respond_to?(:append_as_bytes)` is false (rugaroo has no `String#append_as_bytes`; its Strings are immutable, decision 382). Past that, with the installed gem, it stopped in parser's `VariablesStack#push` ("no implicit conversion of Set into element"): in the whole program `@stack` is inferred `Array[String?]` from `@stack.last << name.to_sym` read as `String#<<`; the same class alone compiles right, so it is a gem-inference interaction across the parser gem, which the rubocop compile research owns. rubocop-ast's `ProcessedSource` with `:parser_prism` waits on both.
- Two fixes made for that path: a bundled gem file's class-body `require_relative` loads at compile time (translation/parser.rb's builder, compiler, lexer; in a traced compile it was a run-time require of a file the trace never listed), and boot-resolved autoload files of an installed copy of a bundled gem are not sources (MRI's prism string_query.rb beside the bundled one declared `StringQuery#string` twice).
- `parse_stream` reads the whole stream (`pm_serialize_parse_stream` needs a host fgets callback; MRI stops at `__END__`). `Prism::Pack.parse` (C-only in MRI 4.0) is absent.
- `Prism.lex_compat` (optional, above); prism in the browser playground (no filesystem to extract to).

**Proof:** `testdata/test/prism_test.rb` (parse, `inspect`, errors, comments, locations, lex, dump/load, StringQuery, VERSION; == MRI with the operand trace), example 136, `TestPrismWasm`; a build with no `ruby` on PATH prints what MRI prints.
