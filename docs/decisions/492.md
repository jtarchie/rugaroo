# Decision 492

**Rule:** Under `RUGAROO_INFER_UNKNOWN` as in the default lane, dynamic calls by a method's name widen its parameters but never type one alone (decision 331); the rule that let agreeing dynamic calls type a parameter no static call reaches (`dynUsesAgree`) is gone, with the setter exception decision 477 added to it.

**Why it went** (2026-11-22). *See also decisions 331, 444, 477, 491; docs/research/inference-2026-11.md.*

A parameter typed from the dynamic calls that were recorded is sound only if every call that can reach the method at run time was recorded. Calls that run in the compiled program and record nothing:

- a computed-name `send` in gem code, which may reach any method of the right arity (`noteSendUses` records nothing for gem code, `noteDynAll` only notes that one exists);
- a dynamic call in user code (`noteDynUses` records only in gem files);
- a call in a statement that did not compile during the rounds and compiles in the final pass, whose widening check (`noteWidenPending`) sees static calls only.

Decision 477 had already met two of these on rubocop (a splat, a setter) and patched each. A body poisoned into a stub is not one of them: the stub never runs, so its calls pass nothing.

**What it was worth.** Measured with the switch on, inference cache off:

| | typed only by dynamic calls, last round | dynamic call sites with the rule | without |
|---|---:|---:|---:|
| liquid (example 124) | 2 (`I18n#name`, `Tag#render(_context)`), up to 14 mid-rounds | 2,716 | 2,803 |
| kramdown (example 123) | 1 (`Html#in_html_tag`) | 3,743 | 3,743 |
| parser gem program | 2 (`Range#*what`) | 7,452 | 7,452 |

liquid's example runs 58.1M -> 59.0M instructions (+1.5%), and its output equals MRI's both ways. All three gems have computed-name sends with one argument in gem code, so a sound version of the rule ("no computed send could reach it") would have typed nothing here either.

Gone with it: `paramUse.setter` and `fctx.dynSetter` (decision 477's setter part). Decision 477's splat part stays: an untyped use of each parameter from a dynamic call's splat on is evidence for untyping after resolution, rule or no rule.
