# Decision 464

**Rule:** A String of 256 bytes or more has its ASCII flag, UTF-8 validity and character count cached by data pointer and length (16 lock-free slots), so `length`, `[]`, `index`/`rindex` with a position and `Regexp#match(str, pos)` on one large String stop rescanning or rune-converting it on every call.

**String facts** (amends decisions 349, 399, 454; 2026-11-15). *See also decisions 136, 395.*

MRI keeps a String's coderange and (for a single-byte one) answers character offsets in constant time. A compiled String is a Go `string` with no room for a flag (decision 136), so every character operation asked again: `rbASCII` scanned the String or a prefix of it, and three methods converted the whole String to `[]rune` and back per call: `String#index(s, pos)`, `String#rindex(s, pos)` and `Regexp#match(str, pos)`. The parser gem's `Source::Buffer#line_begins` (`while index = @source.index("\n", index)`) is quadratic that way: on a 124 KB source, 4,000 calls each converting 124 KB twice.

- **The cache.** `rbStrFactOf(s, level)` (`prelude/go/fastpath.go`): `rbStrFacts`, 16 `atomic.Pointer[rbStrFact]` slots indexed by a hash of the length; an entry is keyed by `unsafe.StringData(s)` and `len(s)` and holds `ascii`, `valid` and `chars`. Entries are immutable and swapped whole, so there is no lock (memory: no global locks) and a collision only rescans. A non-ASCII String is validated and counted only when a caller asks for that level: its ASCII scan stops at the first high byte, as before.
- **Why it cannot go stale.** Go strings never change in place except under decision 395's `rbStrSetbyte`: the first time it gives a long String a buffer to write in place it sets `rbStrMutable`, and from then on no fact is cached (the cache is still read: its entries are of other, immutable Strings). A test on every `setbyte` instead cost spinel's `bm_ruby_xor` 7%, and clearing on every write 56%; this way a program that edits long Strings in place gives up the cache and nothing else. Holding the data pointer keeps the bytes from being reused for another String; at most 16 Strings are kept alive by the cache (decision 349's `rbValidCache`, which this replaces, kept one).
- **Who asks.** `rbStrLen` and `rbValidUTF8` for a long String; `rbASCIIFact` in `rbStrLenA`, `rbASCIIPrefix` (the whole String's fact before a long prefix's scan, in `rbStrAt` and `rbStrSub`), `rbCharOffset` and `rbCharCount`. `rbASCII` itself is unchanged and calls nothing, so a short String pays no frame: making it consult the cache cost `benchmarks/format.rb` and `strings.rb` 3% each.
- **No more rune slices.** `__index_2`, `__rindex_2` and `__match_2` find the byte offset of a character position with `rbCharOffset` (the position itself in an ASCII String) and count characters only over the bytes they skipped.
- **Not done:** a non-ASCII long String still pays O(position) per `[]`; a sparse offset table in the entry would make that constant too. The parser gem works around MRI's same cost with a UTF-32LE copy, which a compiled String cannot index by character (decision 136): `overrides/rubocop/gem-patches/parser-3.3.13.0.patch` removes that copy.
- **Measured** (instructions retired, `GOGC=off GOMAXPROCS=1`, against main be30d759): a 60-line untyped-library program doing 200,000 `line_for` lookups and 40,000 slices of a 124 KB String, 31,261M → 130M for that part (MRI 2,112M for the whole program); `benchmarks/` strings 159.3M → 159.4M, regexp 2,468M → 2,479M, kramdown 3,855M → 3,847M, liquid 1,670M → 1,675M, json 1,169M → 1,172M, format 1,274M → 1,302M (+2%, not from the cache: it stays with the cache turned off); spinel's bm_csv_process, bm_io_wordcount, bm_template, bm_json_parse, bm_wordfreq within ±0.5%.
- **Proof:** `testdata/test/string_test.rb` `StrFactTest` (ASCII and non-ASCII Strings past 256 bytes: `index`/`rindex` with positive and negative positions, `[]`, `match` with a position, three same-length Strings in one slot, `setbyte` after a cached length, four threads) against MRI.
