# Decision 460

**Rule:** to_enum takes decision 414's typed Enumerator for a method with callee-side defaults or keywords only when its block's value is unused; pack converts a program's object with to_str/to_int; Hash#hash mixes each pair; `(b...Float::INFINITY).minmax` raises TypeError; only `self.class.new` in a String subclass builds the subclass; decision 447's container type skips lambda arguments.

**ruby/spec regressions from the batch after decision 425** (amends 414, 432, 444, 447; 2026-11-13). *See also decisions 414, 432, 444, 447, 459.* The rest of the test-by-test comparison of the 2026-11-13 ruby/spec refresh with a rerun of 2887634c (decision 459 has the first part). Each was bisected to the commit that changed it.

- **`Matrix.build` with a block typed as an Enumerator** (eb4d89b4, decision 444). That commit let a method with callee-side defaults (`build(row_count, column_count = row_count)`) or keywords take decision 414's typed to_enum, so `build`'s value became `Enumerator | Matrix` and spec code calling `lower_triangular?` on it stopped compiling. A Go range loop gives `yield` no value back, and build's block value is its elements, so such a method keeps to_enum's run-time dispatch unless its block's value is unused (rubocop's `each_capture` still takes the typed path). `library/matrix` 282 → 285, `lup_decomposition` 14 → 18: the baseline's.
- **`Array#pack` with a program's object** (f85fa08c, lazy format reading). pack's run-time path took only a String (or nil) for `a`/`A`/`Z` and an Integer or Float for the integer directives. The format used to be checked whole first, so `[obj, obj].pack("a K")` raised ArgumentError before reaching obj; read lazily, it raised TypeError converting obj. A value with `to_str` or `to_int` now converts as MRI's implicit conversion does (`I_ToStr`, `I_ToInt`, as `I_ToS` for to_s). `core/array/pack` back to 1,136+.
- **`Hash#hash` let equal values cancel** (283602b1, decision 432: Symbols hash to small table indices). The pairs were summed as `hk*31 ^ vh`, so `{a: 2, b: 2}` and `{a: 7, b: 7}` hashed alike. Each pair is now `mix(mix(hk) ^ vh)` with the Integer mixer (rbMixHash).
- **`(0...Float::INFINITY).minmax`** answered `[0, Infinity]` (eee61761, decision 140's shortcut); MRI raises TypeError "cannot exclude non Integer end value", as `max` already did.
- **`Float(my_string.new("10"))`** raised TypeError (dea4253f, decision 444). `new` on a held String-subclass class built the subclass's own object, which `Float()` cannot read; the rule is meant for `self.class.new` in rainbow's Presenter, and is now limited to that receiver. Another held class keeps String's `new`, as before.
- **A lambda's argument typed as a container** (5e5015a6, decision 447). The spec harness's `-> format, *args { ... }` is typed per position from its calls; one position's container uses made it `Array[untyped]` and the `%*d` specs stopped compiling. Lambda and stored-block arguments are left to joinUses. `core/kernel/sprintf` 98 of 119, the baseline's.
- **Not regressions, left as found:** concurrent `StringIO#write` from threads loses writes or panics (`slice bounds out of range`) at 391dfa41 as now: StringIO has no lock, and the baseline's pass was luck. `Hash#hash` of a recursive hash differs from `{x: h}.hash` in the baseline too.
- **Proof:** `testdata/run/gem_lenient/buildish.rb` (a callee-default `build` with a block, called from strict code: a compile error before); `testdata/test/hash_test.rb` (pairs do not cancel); ruby/spec `library/matrix`, `core/array/pack`, `core/hash`, `core/range/minmax`, `core/kernel/Float`, `core/kernel/sprintf`, `core/string/modulo`, compared test by test with the baseline.
