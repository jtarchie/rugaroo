# Decision 450

**Rule:** Enumerable has `to_h { }`, `uniq { }`, `compact`, `find(ifnone) { }`, `slice_before(pattern)`, `slice_after(pattern)`, `zip(other) { }` and `chain`; a blockless `sort_by`/`min_by`/`max_by`/`group_by`/`partition` followed by `.with_index(off) { |x, i| }` or `.each_with_index { |x, i| }` compiles to `__<name>_with_index(off)`; and `sum(init) { }` with a String or Array `init` is `map { }.inject(init, &:+)` on Enumerable, Array, Range, Set and Hash.

**Enumerable call forms, second batch** (#145; amends decision 438; 2026-11-13). *See also decisions 4, 241.*

- **Copied from Array:** `__to_h_block`, `__uniq_block`; `compact` is `to_a.compact`; `map`/`select`/`filter`/`reject` without a block are Array's `Enumerator::Map`/`Select` over `to_a`.
- **`find(ifnone)`** (`__find_1`, by decision 241's arity rule): `ifnone` is `^() -> E`, called when nothing matches. A lambda returning another class is a compile error (a union of type variables is not a type, decision 150); a `^() -> E?` lambda built an `rbOpt` Go type where the parameter expected `*E`.
- **`slice_before(pattern)`/`slice_after(pattern)`** (`slicePattern`, compile time): the block form `{ |x| pattern === x }`, for a pattern that reads the same each time (a literal, a local, a constant). Not `__slice_before_1` twins: a `__slice_` name is also what a `slice` call's overload scan looks for, and with them a gem's `hash.transform_keys(&:to_sym).slice(*keys)` went dynamic and failed a cast at run time (TestBootAutoload).
- **`zip(other) { }`:** a Go iterator, so a statement (decision 4's rule for a void block: `p xs.zip(ys) { }` stays a compile error, as the issue's notes say).
- **`chain(*arrays)`:** an Enumerator over `to_a` plus each argument's elements (ponytail: eager; MRI's `Enumerator::Chain` is lazy, which only an infinite or side-effecting source shows; `Enumerator#+` already worked).
- **Blockless `map`/`select`/`filter`/`reject`** on an Enumerable class are `Enumerator::Map`/`Select` over `to_a` that keep the receiver's `inspect` (`#<Enumerator: {"a" => 1}:map>`, as MRI's).
- **Blockless enumerators fed back** (`withIndexChain`, compile time): `xs.sort_by.with_index(1) { |x, i| }` becomes `xs.__sort_by_with_index(1) { |x, i| }`, which runs `sort_by` with a block that counts the index, the order MRI's enumerator feeds it. A bare blockless enumerator object (`xs.min_by.class`, `xs.map.with_index(1).to_a`) is still not built.
- **`sum(init) { }`** with a String or Array init: `xs.map { }.inject(init, &:+)` (`sumPlus`), now also for Range's, Array's, Set's and Hash's own `sum`, whose numeric adder raised "can't convert String into Complex".
- **ruby/spec `core/enumerable`:** 181 → 184 pass, skipped 254 → 239 (more spec files compile; the 9 new errors are examples that did not run before, mostly fixture classes ruby/spec defines in ways rugaroo leaves out: `YieldsMulti`, `should_receive`).
- **Proof:** `testdata/test/enumerable_test.rb` `MoreFormsTest` against MRI.
