# Decision 457

**Rule:** rugaroo reads an `rbs collection install` directory (`.gem_rbs_collection/` beside the program, or `RUGAROO_RBS_COLLECTION`), the highest version present of each gem, after the program's own `sig/` and the vendored `sig/gems` and before a gem's shipped `sig/`; the first declaration of a member wins.

**gem_rbs_collection signatures** (#105 step 1; amends decisions 160 and 306; 2026-11-13). *See also decision 404.*

[ruby/gem_rbs_collection](https://github.com/ruby/gem_rbs_collection) is Ruby's community set of signatures for gems that ship none. Ruby tooling installs it per project with `rbs collection install`, which writes `.gem_rbs_collection/<gem>/<version>/*.rbs` matched to the Gemfile.lock. Vendoring the collection whole would pair one gem version's types with another version's code (rack 2.2's sigs with the rack 3 we compile), so rugaroo reads the installed directory instead.

- **Order** (`loadSigs`; `addSig` keeps the first declaration of a member): inline `#:` annotations, then a `sig/` directory beside a program file, then rugaroo's vendored `sig/gems` (our own fixes win over the community's), then the collection, then a gem's own shipped `sig/` (decision 306), then `foo.rbs` sidecars (decision 404, hints), then inference.
- **Versions.** `rbs collection install` pins one version per gem; if a directory holds several, the highest by numeric segments is read (`compareVersions`: 1.10 after 1.9). `_` and `.` directories are skipped, as RBS does; files are read leniently, like a gem's shipped `sig/` (decision 306).
- **Proof:** `TestRBSCollection` (internal/compiler): a gem method reached only with an untyped value gets the collection's 1.10 signature (`(Float) -> Float`), not 1.9's; it fails with the loading turned off.
