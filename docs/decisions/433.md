# Decision 433

**Rule:** The inference cache also keeps, per final-pass kind (lazy, eager), `refineIvars`' outcome: its candidate typings, which it kept, and what its dry-runs added to the catalogs the output still reads from (boxes, `optConv`, Marshal's value types, dispatcher and respond_to? names, block-send names, flags); a hit whose candidate list is exactly the recorded one applies that instead of running the dry-runs.

2026-11-01, amends decision 430 (the cache) and decision 15 (`refineIvars`). On a hit, decision 430 skipped the inference rounds but still ran decision 15's dry-runs: on rubocop's hit, 15 of 38.5 s. The first attempt to replay them (docs/research/compile-time-2026-11.md, "Replaying `refineIvars` on a hit") failed on side effects. Discarded emissions filled tables the output is built from, and the real emission reused their memoized analysis. Decisions 431 and 432 derived most of those tables from kept code. What is left is three catalogs whose entries come from the types a body renders (boxes, `optConv`, Marshal's types; research doc, hard tables) plus the dispatcher-name sets, all of them sets, now emitted in a fixed order.

**What is recorded** (`refineRecord`, `internal/compiler/refinereplay.go`). A final pass (not an inference round) that runs the dry-runs records:
- the candidates as `owner ivar tried original` strings, in order;
- for each candidate, whether `salvage` kept the tried type;
- what was added between the first dry-run and the end of `salvage` to `boxes`, `argBoxes`, `leafBoxes`, `optConv`, `marshalSeen` (as `cachedType`), `dynSeen`, `respondSeen` and `dynBlockNames`, and any of the eight whole-program flags it turned on.

The record is keyed by `refineKind`, because the eager recompile (decision 49) runs its own pass. The cache file's version is 2.

**When it is used.** The candidate loop (`refineContainer` plus its `discoverIvars` reruns) still runs on a hit; only the dry-runs are skipped. If the loop's candidate list equals the record's, string for string, the record's typings and entries are applied (Marshal types are re-homed to this compile's classes, as decision 430's types are). Anything else runs the dry-runs and records anew. A hit's final pass starts from the same state as the cold final pass (decision 430), and on that state the dry-runs are deterministic. The real emission redoes the analysis the dry-runs had memoized, and every table that analysis feeds is now either derived from kept code (decisions 431, 432) or one of the recorded catalogs.

**Gate:** a hit must be byte-identical to `RUGAROO_NO_INFER_CACHE=1`. Measured: examples 123 (kramdown) and 124 (liquid) are; liquid needed the replayed `argBoxes` and Marshal entries (`*Liquid_BlockBodyI`, `Hash[Symbol, String]`). `TestRefineReplay` checks a small program both ways and that the hit replayed. Rubocop: see the research doc.

A table added later that a dry-run can fill, and that the output reads without a kept-code filter, must join the record. `TestRefineReplay` only catches that if its program reaches it, so the rule is: render-time catalogs are derived from kept code or recorded here.
