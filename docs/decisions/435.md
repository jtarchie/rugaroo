# Decision 435

**Rule:** An example's rbs-inline + `rbs validate` pass is cached by its sources, the vendored `sig/*.rbs`, Ruby and Gemfile.lock, beside the MRI output cache; only a pass is recorded, and `RUGAROO_NO_MRI_CACHE=1` skips it.

2026-11-01, amends decision 272 (the MRI oracle cache). TestExamples runs `rbs-inline` and `rbs validate` on every example on every run: 166-231 s and 474-681 s of CPU per full run on 137 examples (3.5-5 s each, 9 s for the net/http ones), 35-40% of a warm run's CPU (docs/research/test-time-2026-11.md). Both tools are deterministic in their inputs: the example's directory (main.rb, what it require_relatives, its Gemfile and lock when it has one: `exampleSources`, as the MRI cache keys), the repo's `sig/*.rbs` the harness passes with `-I`, and the rbs, rbs-inline and signature gems Gemfile.lock pins. The entry (`os.UserCacheDir()/rugaroo-test/rbs/<sha256>`) is written only after both commands exit 0, so a failing example is rerun every time and never replays a stale pass; an rbs upgrade changes Gemfile.lock and so every key. The `-r` library flags derive from the sources, so they need no key of their own.
