# Decision 482

**Rule:** A gem's `xs.map! { ... }.flatten!` is one step (`Array#__map_flatten!`), so a typed Array never holds the Arrays between the two calls and kramdown's `Element#children` is an `Array[Kramdown::Element]`; a `while` condition's nil guard on a local holds in the loop's body, and after the loop when no `break` leaves it.

**kramdown's children** (2026-11-21; amends 333, 357). *See also decisions 160, 333, 357, 371, 476.*

`RUGAROO_UNTYPED_REPORT` (decision 476) put two roots behind 331 of kramdown's 1,109 dynamic call sites: `Element@children`, declared `Array[untyped]` in `sig/gems/kramdown/kramdown.rbs`, and `Parser::Kramdown#parse_blocks(el)`, untyped because a child read from it is. The declaration's own comment said why: `update_tree` writes

```ruby
element.children.map! do |child|
  case child.type
  when :raw_text then ...; child.children   # an Array
  when :eob      then ...; []
  else                     child
  end
end.flatten!
```

and four more methods do the same, so between the two calls the Array holds Arrays.

- **One step.** In gem code a `flatten!` with no argument whose receiver is a `map!` with a literal block compiles as `Array#__map_flatten!` on the `map!`'s receiver (`mapFlatten`): each element becomes what the block answers, an Array's elements spliced in at any depth, and the result is `flatten!`'s (self when something was spliced, else nil). The block answers untyped; each spliced value is checked into the element type. It applies whatever the receiver's static type is: an untyped `element.children` is the typed Array at run time, and a plain `map!` there stored an Array in it (TypeError).
- **The declaration** is `Array[Kramdown::Element]`, ivar and accessor.
- **The loop guard.** Typed, `parent = li; while !parent.children.empty? && ...; parent = parent.children.last; end; para = parent.children.last` guarded `parent` three times, and Go's nilness analysis (decision 371) rejects the second and third as impossible. `genWhile` now applies the condition's `callNarrowing` to the body, as `genIf` does to its branches (decision 357), and again after the loop unless a `break` leaves it (the condition is then the last thing that ran). This is codegen for every program: fewer redundant nil checks, no change in what raises.

**Measured** (default lane, no switch): kramdown's dynamic call sites 1,109 -> 968; `benchmarks/kramdown.rb` about 3,850M -> 3,809M instructions (MRI 3,865M), output equal to MRI's. The sites went and the time did not: what is hot in kramdown is not these calls, and site counts do not rank roots by cost.

**Proof:** `testdata/run/gem_lenient/treeish.rb`; example 123.
