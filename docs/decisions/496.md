# Decision 496

**Rule:** Prism's translation to the parser gem's AST (`Prism::Translation::Parser40`) runs compiled and equals MRI's output: `Node#accept` answers what its visitor returns, a gem's `a...b` with a nil `b` is endless, a dynamic `byteslice(range)` takes the range twin, `start_with?`/`end_with?` take four arguments, a blockless `filter_map` has `with_index`, and a gem's `Integer < x` compares a Float x as a number.

**Prism's parser translation compiled** (2026-11-23). *See also decision 427 (prism over wasm), decision 495 (the racc path this replaces for rubocop).*

rubocop-ast parses with prism for every target Ruby 3.3 and later, and only prism for 3.5 and later. Its translation layer is prism's own Ruby: prism.wasm parses (decision 427), then `Prism::Translation::Parser::Compiler` builds the parser gem's AST and `Lexer` its tokens. Each fix below came from running that layer on 250 files of a private Rails app; each was reduced to a small program and checked against MRI.

- **`Node#accept` returns.** prism's shipped sig declares `def accept: (_Visitor) -> void`, a Visitor's view. A `Prism::Compiler` returns the node it built, so every translated node was nil. `scripts/prism-sig` now writes `def accept: (untyped) -> untyped` into `0_rugaroo.rbs`.
- **A nil range end is endless.** `source.byteslice(start_offset...end_offset)` with a nil `end_offset` searches to the end in MRI (`Range.new(a, nil)`). In gem code, a range whose end is `T?`, or untyped where a `Range[T]` is expected, builds the Range and sets it endless when the end is nil. User code keeps decision 20's error.
- **Dynamic overload by class with fewer parameters.** `x.byteslice(a...b)` on an untyped String picked byteslice's `(Integer, ?Integer)` and failed converting the Range. `dynClassOverloads` now also offers a twin with fewer parameters than the method (`__byteslice_range(r)`) for that argument count.
- **Four prefixes.** `opening&.start_with?("%w", "%W", "%i", "%I")`: `__start_with_q_4`, and `__end_with_q_4` for symmetry.
- **Blockless `filter_map`.** `Enumerator::FilterMap`, whose `with_index` and `each_with_index` keep the block's truthy results, as MRI's do. Array and Enumerable answer `__filter_map_enum` with it. On an untyped Array the view dispatcher (`rbViewBlockCall`) answers `filter_map` with and without a block, and the FilterMap's `DynWithIndex` is hand-written in `prelude/go/enumerator.go`: the method's `[U]` is one the wrapper generator leaves out (growsTypeParams).
- **An Integer against a Float held untyped.** `result = Float::MAX`, then `n < result`: the Integer operator converted its argument to Integer and raised RangeError. In gem code, an Integer `<`, `<=`, `>` or `>=` whose argument is untyped or a union goes through `rbIntCmpAny`, which compares a Float as a number and converts anything else as before.

- **`is_a?(Proc)` narrows nothing on an untyped value.** A compiled Proc is a Go func (rbIsProc's cases), not the prelude's `Proc` struct, so narrowing to it asserted `.(ProcI)` and panicked: rubocop-ast's `tokens.is_a?(Proc)` on prism's deferred-token lambda.

**Measured** (250 files, instructions, macOS): `Parser40#tokenize` on each file, compiled 5,260M vs MRI 8,689M (MRI uses prism's C extension, 1.9.0 pinned to match the bundled wasm); the parser gem's own Ruby 2.7 grammar compiled was 9,656M (decision 495). Every file's AST `inspect`, tokens with positions and comment ranges hash the same as MRI's.

**Compiled rubocop on prism** (overrides/rubocop): `rubocop-ast-1.50.0.patch` names the four lazy-token parsers instead of `Class.new(base)` (decision 145) and drops the parser gem's grammars; `rubocop-1.92.1.patch` defaults TargetRubyVersion to 3.3. Transpile plus Go build went from ~19.5 min to 7.5-9.7 min.

Proved by `prismish.rb` and `lazyish.rb` in testdata/run/gem_lenient, `FilterMapWithIndexTest` in testdata/test/array_test.rb and `FourPrefixTest` in testdata/test/string_test.rb, against MRI.
