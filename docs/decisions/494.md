# Decision 494

**Rule:** A sidecar's `untyped` return (or an optional or Array of it) is a hint, so the body types the method as an unannotated def's; in a module only classes extend, `instance` is a type parameter bound to the class a call is made on, and `new` on self or a class method ending in it answers that parameter.

Snails (decision 404's sidecars, Spinel's `--rbs` input) types its finders `find: (untyped id) -> untyped` and `fetch_many: (...) -> Array[untyped]` in `Sqlx::Query`, a module `Sqlx::Base` extends. Upstream keeps them so on purpose (snails-rb/snails#104): Spinel infers `Post.find` as a `Post` from the Ruby. rugaroo took the sidecar's `untyped` as declared, so a strict compile of the app stopped at its first model read and `app/` needed `-gem app -gem gen`. Three changes close it; `overrides/snails/build` now compiles the scaffold app with `-gem snails-core` alone and equals MRI.

- **A hint, not a declaration.** A sidecar method whose return is `untyped`, `untyped?` or `Array[untyped]` (`untypedHint`) sets `advisoryRet`, and `resolveMethod` then infers its return as it does for a def with no annotation (decision 36). Decision 404 already did this for a sidecar's `untyped` parameters. The hint is a floor: an inference that ends untyped (a gem's recursive walk, a body of dynamic calls) keeps the hint's type (`hintOr`), so roundhouse's `Relation#to_a: () -> Array[untyped]`, whose walk recurses through `to_ary`, stays an Array; without the floor example 135 grew 506 Go functions of dynamic `dup` and `+`. A typed sidecar return still binds, and so does every `untyped` in a `sig/` file or an inline `#:`: only sidecars are hints. A method that itself overrides an inherited one keeps the hint, since its Go signature is its parent's (roundhouse's `Comment#before_validation: () -> untyped` over Base's `-> void`, example 135). An unannotated override of a hinted stub that only raises infers its own return (`inheritsRet`), not the stub's: `Sqlx::Base.all` raises NotImplementedError, and `Post.all` is an `Array[Post]`.
- **`instance` as a type parameter.** A module that only classes extend (no include, no module extender, not prelude), that names `instance` or calls `new` or such a class method on self, and that holds no instance variable (decision 147: a generic module has none) gets a last type parameter `Instance` (`instanceParams`, after `linkExtends`); `instance` in its signatures resolves to it. Every extender binds it to `untyped`, so the Go methods on class objects, their interfaces and the dispatchers are what they were: one erased instantiation. A call on a class object whose method nothing below overrides (`exactInstance`: always so on the constant itself) goes to the module's free func with `Instance` bound to that class, so `Post.fetch_many(...)` is `Query_FetchMany[Query_Self[any, *Post], *Post](Post_class, ...)` and returns `*Array[*Post]` with no copy. A class method's own self call binds its class the same way (`Post.all` calling `find_by_sql`). Where an override exists below a receiver that is not the constant, the call stays erased and decision 404's assertion types a bare `instance`.
- **What answers `Instance` in the body.** `new` on self is found by name at run time, as before, and asserted to `Instance` (ponytail: each extender's constructor takes its own arguments; a static call needs `New` in the module's constraint). A self call that reaches the extenders' one class method (decision 486's `includerRootCall`) answers `Instance` when that method is `-> instance`, or its inferred return is `new` on self as its last expression (`newTail`, `instanceRet`): `Sqlx::Base.from_row`. The assertion holds because self is the class the call was made on. `includerRootCall` also infers the root's return before it reads it; a return not inferred yet read as void, and the caller's own return was then inferred from a dynamic call, by the order the methods were reached.

Not done: a module's self call does not type the unannotated parameters of the class method it reaches (the call is dynamic until the method has a signature; decision 492 removed typing from dynamic uses), and a method called on an `Instance` value inside the module is dynamic, since the parameter has no bound.

Proof: `testdata/test/class_method_test.rb` (`instance` in a container, under an override, through a block), `testdata/run/require_shims` (sidecar hints over a finder module), `overrides/snails/build`.
