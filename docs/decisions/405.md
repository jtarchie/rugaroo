# Decision 405

**Rule:** A class method or top-level def that appends to a String parameter, or passes it on to another such parameter, and never rebinds it, takes it by reference, with the caller's append buffer: the caller passes a local String it owns, the method appends in place and writes it back however it returns, nothing in the method may keep or pass on the String except to another such parameter, and a method that may return it makes the call's value a use of the caller's local.

**String out-parameters** (amends 382; 2026-10-27; #128, #143). *See also decisions 58, 136, 395, 404.* Decision 382 let a proven-unaliased String local take `<<`; a parameter could not, since the caller's String would have to see the append. Roundhouse's views are all that shape, `def self.form_into(io, article, ...)` appending to the caller's `io` and nesting partials with `Views::Comments.comment_into(io, ...)`, as Rails templates append to one output buffer. #128's option 1 (out-parameter rewrite): compile-time only, no mutable String type.

- **Which parameters.** `markOutParams` (`outparam.go`, after signatures resolve): a positional, required parameter typed `String` of a class method or top-level def in user code, whose body has `p << x` or `p.concat(...)` and never assigns `p`. Instance methods are left out: an override or a dynamic call (`send`, a dyn wrapper) would pass a `String` where a `*String` is taken.
- **The callee.** The Go parameter is `p_out rbStrOut`, the caller's String and its append buffer (`{s *String; b *[]byte}`); the prologue binds `p := *p_out.s` and defers `*p_out.s = p`, so the appends are on a local and reach the caller on return or raise (MRI shows a raising partial's appends too). They go through the caller's buffer (`rbStrAppend(p_out.b, ...)`), so a partial appends in place and the caller's next append continues there: nested partials build one page in one buffer. Decision 382's proof runs on it with no seal: any read that may keep the String (stored, returned, passed to anything but another out parameter, the method's own value) is a compile error, since the caller keeps appending after the call.
- **The caller.** The argument must be a local String variable; it is passed as `rbStrOut{&local, &rbBuf_local}` (an out parameter passes its own `p_out.b` on), and counts as an append on that local in the caller's own proof (`outCallArg`), so a local that something else holds is still refused. Inside a block that may run after its call, it is refused as an append there is.
- **Cost.** A first version gave each callee its own buffer, so every partial copied the page so far: 16 KB of copies for example 135's 6.5 KB index. Sharing the buffer leaves only amortized growth.
- **Not covered.** An attribute (`page.out << ...`, #128's option C, deferred), an Array element through a block parameter (#128's option B, a design limit: decision 58), a user instance method, and a String argument that is not a local. *(A returned parameter is covered since the #128 amendment below.)*

*Amended (rubocop, 2026-10-31):* in a gem file, a private instance method that no subclass redefines takes its appended
String parameter by reference too (prism's translation lexer: `escape_read(result, scanner, control, meta)` appends the
unescaped bytes into `unescape_string`'s `result`, recursing with it): only its own class calls it, so no override or
dynamic call can pass a plain String. A gem parameter inference typed String in an earlier round (decision 146) counts,
since each round recompiles. A gem caller passes the pointer with no buffer and skips decision 382's alias proof (the
callee rebinds its copy and writes it back on return, as before); `rbStrAppend` takes a nil buffer. `append_as_bytes`
(Ruby 3.4: each argument's bytes, an Integer's low byte, `rbBytesArg`) is an append wherever `<<` and `concat` are
(`strAppendNames`). Before this, a gem method appending into its parameter silently lost the appends (`mini/gemlib/outgem.rb`
printed `!` for MRI's `A-BC-!`). `testdata/run/gem_lenient` (outish), `testdata/test/string_test.rb` (StringAppendAsBytesTest).

*Amended (#128, 2026-11-11):* option A of #128, and the bugs its research found.
- **A returned out parameter.** `def grow(s) = s << "x"` and `add_field(line, ...)` ending in `line` compile: an out parameter may be the method's value or be `return`ed. The caller pays for it: when the callee may return the parameter (`OutRet`, a syntactic look at the method's value and its `return`s, and a return type that may hold a String), the call's value is a read of the argument local in the caller's own decision 382 proof, placed after the call's append. A dropped value, `puts grow(s)` and `grow(s).size` are fine; `t = grow(s); s << "1"` stays an error ("the value of grow (`s` itself) is stored or passed on line N before its last append"), since `t` would miss the append, and inside an out-parameter method the value may not be kept at all. The callee needs nothing new: its value is `*p_out.s` as written back.
- **Pass-through.** A parameter the method only passes on to another out parameter (`def outer(buf, items) = items.each { |it| inner(buf, it) }`) is an out parameter too, by fixpoint over statically named callees (self's class, a top-level def, a constant's class method); before, the caller's proof refused it as "`buf` is a parameter".
- **Untyped callee.** When an appended-to parameter is left untyped (an unannotated method whose only caller failed an inference round, e.g. on a mixed-value Hash, the research's "bug 2"), the caller's error now says so and names the `# @rbs` fix; with the annotation the real error (the round's) shows. With full annotations a mixed-value Hash argument always worked: the probe's trailing `def m(a) #: (...) -> nil` is a return-type annotation, not a signature.
- **Gem methods** (amends 428). A public gem instance method qualifies too when no subclass redefines it and it overrides no ancestor's method (a call through the ancestor would pass a plain String); before, `pub_into(buf, x)` silently printed `"s"` for MRI's `"sx"`, and kramdown's `extract_text(el, raw)` lost its raw text. A gem argument that is not a String local (an ivar, `el.options[:raw_text] = +''`, a dynamic call's) gets the appends on a copy, as before this decision (ponytail: write back to the expression's target); user code may pass a fresh String (a literal, `+""`, ...) to a gem's out parameter the same way, and any other non-local stays an error.
- **Element blocks** (design limit, decision 58). An append to a block parameter of an iterator whose receiver keeps what it yields (`each`, `each_with_index`, `each_with_object`'s memo, ...; not `each_char`, `each_line`, `times`, ...) stays a compile error in user code, now naming the cause and `map! { |r| r + x }` / `StringIO`. In gem code, where it compiled to a rebinding that left the element unchanged, it raises NotImplementedError: the whole method when the parameter is a String, the String arm when it is untyped.
- **Widening.** An unannotated Array literal local (decision 193) whose typing fails decision 382/395/405's proof keeps that error: before, the retry left it `Array[untyped]`, and `rows = ["a"]; rows.each { |r| r << "x" }` compiled with a warning and raised NoMethodError at run time.
- **Cost.** Programs that compiled before generate the same Go, except gem methods newly by reference (kramdown's `extract_text`); TestCompileCost unchanged.
- **Proof:** `testdata/test/string_test.rb` OutParamTest (returned, field builder, pass-through annotated and inferred, mixed-value Hash elements); `testdata/errors/strings.txtar` `shovel_param` (`t = grow(s); s << x`), `out_param_returned_kept`, `out_param_untyped_callee`, `shovel_element`; `testdata/run/gem_lenient` (strapish).

*See also decision 455* (#156): `replace`/`clear` rebind a proven local or out parameter, and prelude instance methods may take out parameters.
