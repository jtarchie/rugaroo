# Decision 440

**Rule:** An inferred container (an unannotated `[]`/`{}` or seeded literal typed by what is put in it: a local, decisions 13 and 193; an ivar, decision 15) whose typing only decision 20's nil error vetoes keeps its element type: each site the typing made possibly-nil compiles as decision 393's run-time check, with a warning per site, while a nil site the untyped run already has stays the compile error.

**Inferred containers keep their type past nil reads** (amends 15, 20, 393; 2026-11-11; #141). *See also decisions 13, 193, 404, 433.* `@box = []; @box << min_x ...; x >= @box[b]`: decision 15 typed `@box` `Array[Float]`, `@box[b]` is `Float?`, decision 20 rejected `Float?` as `>=`'s argument, so the dry run dropped the typing and `@box` stayed `Array[untyped]`: every read boxed, every comparison a dynamic call, an error on nil only at run time. No compile error came of it, only a slower program that failed at run time all the same. spinel's point_in_polygon showed the cost: 1,515M instructions against 440M with `--nil-check=runtime`, where the typing survives.

- **Which typings.** A dry run (refineIvars' `try`, analyze's `try`) that fails on a nil error is retried once with its nil sites deferred. `nilErrorf` marks decision 20's errors as nil vetoes: `optWhereClass`, a `T?` in `unionMismatch`, an annotated ivar write, nested destructuring. Any other error, or a new conversion, still vetoes the typing, so only a container whose sole problem is a nil read changes.
- **Which sites.** A nil site is the file and offset of the node coerced (`nilSite`). `nilAt` asks at every decision 393 gate: the coerce, `nilTwin`, `nilNumArgs`, `nilSpaceship`. Before the first retry, the candidates' untyped run is replayed once in record mode (`nilRetry`, `nilDeferral.rec`: every site checked at run time, and noted). Those sites do not come from the typing, so in the retry they stay decision 20's error. A program with its own nil error (a `T?` parameter, an annotated `Integer?`) next to a container read therefore fails as before (`nil_read_inferred_other_nil`). A record run that fails for any other reason gives no retry. The retry's other sites are deferred, and only those: the final emission checks exactly them (ivars: `c.nilDefer`, for every later body; locals: the function's own `f.nilDefer`).
- **The check and the warning.** A deferred site is decision 393's run-time check (`rbNilArg`/`rbNilArgO`/`rbNilArgV`) with MRI's message: `1.0 > nil` raises ArgumentError "comparison of Float with nil failed", `1 + nil` raises TypeError "nil can't be coerced into Integer". Each site also warns "possibly-nil T? where T is expected is checked at run time: an inferred `[]`/`{}` keeps its element type (decision 440)". The untyped fallback raised on nil too, but not always MRI's class: its `x > @xs[i]` raised TypeError "no implicit conversion of nil into Float", where MRI and now rugaroo raise ArgumentError. Warnings are deduplicated by line and text, so several sites on one line warn once. It is not a flag, and it is not silent. An annotated container is unchanged: the program said what it holds, and decision 20 holds it to that.
- **What the dry runs do not see.** The ivar dry run covers the classes that can see the ivar (decision 15). A read through an `attr_reader` from the main program or another class is first compiled in the final emission. If a nil error turns up there after a decision 440 typing (`options.nilDeferred`), `compileOnce` compiles the whole program again with decision 440 off (`noNilDefer`), so a program that compiled before still compiles, the same way (`testdata/run/array_nil_read_reader.rb`). A test method `rugaroo test` would skip for such an error does the same. `||` on a non-nilable value stays decision 404's error outside `--nil-check=runtime`. Gem code was already lenient (decision 172), and the prelude never takes a nil mode.
- **Cache.** A refine record (decision 433) carries the deferred sites (`nil_sites`: offsets by file name), and a `noNilDefer` compile does not replay one that has them. `inferCacheVersion` is now 3.
- **Measured** (instructions retired, macOS arm64, `GOGC=off GOMAXPROCS=1`, old and new binaries alternating, min of 7). `bm_point_in_polygon` 1,515M → 440M (3.4x; cycles 375M → 116M; wall 0.18s → 0.079s, spinel 0.060s): its Go is now byte-identical to the `--nil-check=runtime` build's. `bm_csv_process` 4,504M → 4,264M (`lines = ["header"]`, a seeded literal, keeps `Array[String]`). `bm_wordfreq` rose 50.5M → 54.9M (3,126M → 3,633M at 1M words; cycles +2.5%): `freq` is now `Hash[String?, Integer]`, and a `String?` key takes #138's boxed `rbKeyIndex` path, which #138's String-key fast path removes. Gen-compare of `examples/*/main.rb`, `testdata/run/*.rb`, `benchmarks/*.rb` and spinel's 74 `bm_*.rb` (288 files; the gem examples with their `-trace`/`-gem`/`-I` flags): byte-identical but for those three and example 120, whose `path = [target]` keeps `Array[String]` (no `rbAs` copy of the returned path; `prev[path.first]` checked at run time). Every program that failed to compile still fails the same way. kramdown and liquid (`-trace`): byte-identical, rbDyn dispatchers unchanged (329/457, benchmarks 327/459). `TestCompileCost`: compiled functions and instances unchanged (2,065/970, 7,953/2,521, 30,699/9,400).
- **Proof:** `testdata/test/infer_test.rb` `NilReadTest` (typed ivar reads, and a nil read's ArgumentError, TypeError and NoMethodError checked by class; a local Hash's nil read's TypeError; against MRI); `numbers.txtar`'s `nil_read_inferred_ivar` and `nil_read_inferred_local` (the warnings) and `nil_read_inferred_other_nil` (still an error); `testdata/run/array_nil_read_reader.rb` (the recompile).
