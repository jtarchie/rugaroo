# Decision 503

**Rule:** Under `RUGAROO_INFER_GENERIC=1`, a program that does not compile is compiled again with each user parameter whose calls disagree (typed as a union, or whose union broke its method) given a type parameter of its own, so each call types it as its argument; the result is kept only when that compiles. A program that compiles is the same Go with the option or without.

**Per-call-site parameter types, as an option** (2026-11-27; Crystal's polyvariance). *See also decisions 146, 150, 492, 502.*

Crystal types a def once per tuple of argument types: `id(1)` and `id("a")` are two instances, and `id(1) + 1` compiles. rugaroo gives a def one signature, its parameters the join of their calls (decision 146), so `id(1)` and `id("a")` make `x` an `Integer | String`, and `id(1) + 1` is a compile error. Go has type parameters, which give the same per-call typing without a copy of the def per call.

- **What it does.** After the rounds, the parameters whose calls disagree (`genericCandidates`: inferred a union, or in `noUnion`, the union that broke their method's body) are listed. When the final compile fails, it is run again with each of those, in user code, written as a type parameter (`paramSig`: `def id(x)` is `[T0] (T0) -> untyped`); the return is inferred from the body as before, so `x`'s method `id` returns `T0`, and each call binds `T0` to its argument (`func rb_Id[T0 comparable](x T0) T0`, called as `rb_Id(Integer(1))`). If that compile fails too, the first error stands.
- **Why only for a program that fails.** A parameter that compiles as a union today is a type switch over its members, a typed call each; as a type parameter its method calls are dynamic (`xs.size` on a `T0` is `rbDynSize`, with the dynamic-call warning). Trying it first would make programs that compile now slower.
- **Why an option.** It turns compile errors into programs, which the project decides per relaxation, not silently. It is off by default.
- **Measured** on the snippets of the Crystal comparison (each a compile error without the option): `id(1)` / `id("a")`, `twice(x)` called with a union and an Integer, and `size_of` called with an Array of Integer, an Array of String and a Hash now compile and print what MRI does; `total` over an Integer and a Float Array (`t += x` with `t = 0`) and `first_of` called with two element types still fail, with the error they had. Of the 348 inputs gen-compare reads and spinel's 74 programs, none fails for this reason, so the option changes none of them.
- **Not done:** a copy of the def per argument tuple (Crystal's own form), which `total` needs; it costs generated functions, which the Go build is bound by.
- **Proof:** `internal/compiler/generic_infer_test.go` `TestInferGeneric` (the failing program compiles with the option, as one generic func; a compiling program is the same Go either way).
