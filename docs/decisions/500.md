# Decision 500

**Rule:** A method that passes its own unannotated `&block` on to a method that yields gives the block the types that method yields, during the inference rounds as well as in the final compile.

**A forwarded block takes what the last method yields** (2026-11-26; extends 307). *See also decisions 183, 307, 484, 499.*

kramdown's `parse_raw_html(el, &block)` hands its block to `handle_html_start_tag(line, &block)`, which yields a `Kramdown::Element` and two Booleans. The caller writes `parse_raw_html(el) { |iel, ic, ih| handle_kramdown_html_tag(iel, ic, ih) }`. Decision 183 made the unannotated `&block` `{ (*untyped) -> untyped }`, and decision 307 typed it only from calls of the Proc (`block.call(a, b)`). A forward is no call, so `iel` was untyped, then `handle_kramdown_html_tag(el)`, then `parse_blocks(el)`, which five other callers pass an Element, then `@tree`: 183 dynamic calls from one block literal.

- **The rule** (`noteForwardedBlock`, `expr_blockfwd.go`). Where a method passes its own block on (`forwardClosure`), each parameter of the callee's block is recorded as a use of the stored block's parameter at that position, and the count as its count, exactly as a call of the Proc records them. A callee whose block is variadic, takes none or more than eight records "any count", so the block stays variadic. `typeStoredBlock` then reads them as before: one count from every call and forward, each parameter the join of what reached it.
- **In the rounds too.** `typeStoredBlock` ran only in the final compile, so the block was typed there while the methods its literal calls had already been inferred from an untyped argument. Under the not-known-yet rounds (decision 499) it runs in every round. The older rounds (`RUGAROO_INFER_UNKNOWN=0`) keep the final-compile-only rule: the fixture below has 39 dynamic calls there with or without this change.
- **What it uncovered: a block's `|a, b|` over a union of tuples.** With `@tree` typed, kramdown's `@stack` became `Array[[Element, Symbol?] | [Element?, StringScanner?, Hash?]]` (two tuple shapes, docs/research/inference-2026-11.md), and `@stack.any? { |el, _| el.type == element }` bound `el` to the whole tuple: `el.type` compiled to a raise, and `TestGemCorpus` reported `TypeError` on 30 inputs. One tuple was destructured (`bindTupleParams`); a union of them was not. `bindTupleUnionParams` gives each name its position's field from whichever tuple the value is, typed as the join of that position across the members, nil where a member is shorter.
- **Where it came from.** Crystal types a block's parameters from the `yield`s that reach it, through any number of methods that pass the block on, because a yielded block is typed in its caller's context. The untyped-roots report (`RUGAROO_UNTYPED_REPORT`) named this parameter as kramdown's largest root.
