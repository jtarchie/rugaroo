# Decision 442

**Rule:** Each literal Fiddle `extern`/`bind` also gets a typed twin, and a call whose arguments are all statically the Integer (integer or pointer parameter) or Float (float or double parameter) its C signature takes calls the twin, which passes them to C and decodes the result unboxed while the slot holds a plain `Fiddle::Function` of that signature, and otherwise takes the extern's own path; every other call, and what compiles, is unchanged.

2026-11-11, issue #148; amends decisions 326 and 329 (329 named this as the lever left), extends decision 12's pick-by-argument-class to a synthesized method. Both backends (purego and `--cgo`, decision 426) share it: the twin ends in the `rbFiddleCall` both define with one signature.

**Why.** Decision 326 already types an extern's *result* from the C signature; every parameter stays `untyped`. So each call boxed its arguments into `any`, went through `Fiddle.__callN` and `rbFiddleFast`'s type switch, boxed the C result in `Fiddle.__ret`, and unboxed it again with `rbAs`. A 5M-call loop of `abs`/`fabs` spent ~40 ns of ~104 on that (darwin/arm64), and sqlite3-fiddle's rows cross C ten times each.

**Why not type the parameters.** `int` → Integer, `double` → Float on the extern itself would make valid Ruby a compile error: `pow(2, 10)` (an Integer to a double) and `abs(-1.5)` (MRI truncates). A `void *` parameter takes a String, a Pointer, a Closure or nil in real code (sqlite3-fiddle's `sqlite3_open16`, `create_function`, `bind_parameter_index` broke when the research typed them as Integer). The choice belongs to the call site, where the argument's static class is known, not to the declaration.

**What is generated.** Next to `def self.abs(a0)` (326, 329), `collectFiddleCall` synthesizes, for a fixed-arity signature with at most 8 integer and 8 floating parameters and no `bool` parameter (Ruby truthiness takes any object):
- `def self.__fiddle_t_abs(a0)`, typed `(Integer) -> Integer` from the C types (Integer for integer and pointer types, Float for float and double), which reads the same `__fiddle_func_at` slot and calls
- `def self.__fiddle_c_abs(f, a0)`, a `%x{}` Go body (allowed outside the prelude only for this generated file, `File.goBody`). `rbFiddleTyped(f, ret, args...)` answers the bound C function only when `f` is exactly a `Fiddle::Function` (no subclass that may override `call`) whose return and argument codes are still the ones the compiler read (an `extern` or `bind` may have replaced the name since), and which is neither variadic nor spread. Then the twin places each argument as `rbFiddleInvokeArgs` would (`rbFiddleIntArg`, `rbFiddleFloatArg`: a float's low half), calls `rbFiddleCallTyped` (`rbFiddleCall` plus `Fiddle.last_error`), and decodes the result with the helpers `rbFiddleValue` itself now uses (`rbFiddleIntValue`, `rbFiddleFloatValue`, `rbFiddleBoolValue`; a pointer result is `Pointer.new(addr)`, as `Fiddle.__ret` makes it). Otherwise it calls the extern's own `Fiddle.__callN`/`__call` with the same values, so the fallback is today's path exactly.

**Which calls take it.** `fiddleTwinCall` (in `callTwin`, before decision 12's overloads) takes the twin when the call has no block, no splat, exactly the parameter count, and every argument's static type is exactly `Integer` or `Float` as above. Anything else keeps the extern: a String or nil or Pointer argument, an Integer to a double (`ldexp(5, 8)`), a Float to an integer (`labs(-7.9)`), an untyped value. A user `def self.abs` that replaces the extern has no twin. Only the call site changes, so a program compiles exactly when it did before.

**Not covered.** String arguments (they need decision 329's C copy and its keep-alive for a `void *` result; their sqlite callers are dominated by sqlite's own work), FFI's `attach_function` (its arguments go through `FFI.__ptr`/enum and callback wrappers; the same twin fits its plain numeric signatures, a follow-up), `Function.new` called directly (its types are run-time values), and variadic or spread signatures. The twin's methods answer `respond_to?` (as `__fiddle_func_at` already does), and `singleton_methods` hides them with every `__` name.

**Measured** on an Apple M4 (darwin/arm64), old and new binaries alternating, medians: a 5M-call loop (7 runs) in ns per call, and sqlite3-fiddle's `bench/benchmark.rb` (5 runs) in seconds. 24 of the bench's externs get a twin and 35 of its call sites take one.

So 12–22% off every workload but ruby_function, whose time is in the callback path (329), which the twin does not touch. A program without Fiddle generates byte-identical Go (211 of 214 examples, `testdata/run` files and benchmarks; the other three are examples 121, 122 and 127, which use Fiddle or FFI and change in `rbFiddleValue`, now split into the typed decoders, and in the twins they call). A Fiddle program gains two small functions per extern it calls with numeric arguments; the Go pruner drops the rest.

**Proof:** `testdata/test/fiddle_test.rb` `test_typed_twins` (also in the `RUGAROO_CGO=1` lane): twin calls with Integer and Float arguments to integer, pointer, float and double parameters, a `bind` closure, void, bool, pointer and narrow results, errno through `Fiddle.last_error`, and to the same externs a Float to `long`, an Integer to `double`, a String, a Pointer and nil (the extern's path), and a String to `long` raising TypeError; examples 121 and 122 and `sqlite3_test.rb` unchanged.
