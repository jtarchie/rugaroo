# Decision 458

**Rule:** In gem discovery, a method's untyped parameter written over a class-object ivar widens the ivar to untyped, as a write of another class does (decision 416).

**An untyped parameter replaces a placeholder** (amends 416, 444; 2026-11-13). *See also decisions 416, 444.* net-ftp's `initialize` sets `@sock = NullSocket.new` and `set_socket(sock)` later stores the real `BufferedSocket`. Decision 416 widened `@sock` to untyped because that write is a class object of another class. Decision 444 then made `set_socket`'s `sock` untyped once the inference rounds settled (a gem call passes it an untyped value). An untyped value fits any ivar (it is cast where it lands, decision 225), so the write no longer widened `@sock`; it stayed `NullSocket` and `connect` raised `no implicit conversion of Net::FTP::BufferedSocket into Net::FTP::NullSocket`.

- **The rule.** In gem code, during discovery, `@x = param` where the parameter is untyped and `@x` holds a class object (not a value class, module or container) makes `@x` untyped. A parameter has no class of its own to cast to; any untyped value read from storage still converts where it lands (decision 392).
- **Found by** the final ruby/spec refresh: `library` 1,937 → 1,616, `library/net-ftp` 334 → 19 of 460 (most examples hung waiting for a server thread that had raised). Bisected to bae8243e.
- **Measured:** the generated Go for `benchmarks/kramdown.rb`, `benchmarks/liquid.rb` and examples 116, 123, 124 is byte-identical before and after.
- **Proof:** `testdata/run/gem_lenient/sockish.rb` (TypeError before, == MRI after); `library/net-ftp`.
