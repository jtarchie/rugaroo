# Decision 439

**Rule:** A String keeps no run-time encoding tag and stops at text (UTF-8) vs binary (decisions 136, 352): a tag costs +50% bytes per boxed String and +69% per `[]String` element, US-ASCII reads as UTF-8, text in another encoding enters through `encode(to, from)`, and `force_encoding` of a literal naming another text encoding is a compile-time warning.

**No per-String encoding, reaffirmed** (#131; 2026-11-11). *See also decisions 136, 352* (which this keeps), *380* (the transcoders that make `encode` the way in).
#131 asked whether a String should carry MRI's encoding at run time, so
`"é".force_encoding("ISO-8859-1")` has 2 characters and `"é".b == "é"` is
false. It stays no: the compile-time binary flavor (decision 352) is the
whole of it.
- **Cost of a tag** (measured, GOMAXPROCS=1, darwin arm64; bytes are
  deterministic, ns varied 2x on a busy machine and are not cited). A
  String as `struct{s string; enc uint8}` is 24 bytes where a Go `string`
  is 16: a `[]String` of 1,000 grows 34,944 → 59,008 B (+69%), and 1,000
  values boxed into `any` grow 1,600 → 2,400 B (+50%). Every hot String
  helper would branch on the tag, Go's `==` and map hashing would be wrong
  for MRI's encoding-compatible equality (`{"a".b => 1}["a"]` is 1 in MRI,
  so Hash needs its own hashing), and about 112 `string(self)` and 1,430
  `String(` sites in the prelude and compiler change. That breaks the
  no-runtime-cost rule on memory alone.
- **What it would buy.** About 200 of the ~12,200 ruby/spec examples
  counted (1.6%): core/string has 187 encoding fail/error lines (about 62
  are only US-ASCII's name, 30 need EUC-JP/Shift_JIS/UTF-16 text, 95 are
  binary or invalid-encoding behaviour), and core/encoding's 167 errors are
  `Encoding::Converter`, which needs the class, not a tag (#151).
- **Demand.** Across ~70 installed gems (rails, rubocop, parser, prism,
  rack, json, kramdown, ...), `force_encoding` takes a UTF-8 spelling ~101
  times (a no-op here), BINARY/ASCII-8BIT ~78 (decision 352), a variable
  ~150 (no compile-time flag sees these), US-ASCII ~15, and a non-UTF-8
  text encoding only 5 times (ISO-8859-1 3, Emacs-Mule 2); a
  `force_encoding(X).encode(Y)` chain from Latin-1 or Shift_JIS, 0.
- **Spinel made the same call** with a free bit to spend:
  `lib/sp_alloc.h:273-283` keeps "no per-string encoding tag", one binary
  bit in its header's spare top bit, so no string grows; its
  `docs/limitations.md` (the "Multi-encoding strings" row) answers "write
  UTF-8; transcode at the boundary before the data enters the program"
  because a shared byte representation is "load-bearing for their
  performance". A Go `string` (pointer, length) has no spare bit, and a
  side table keyed by pointer would need a process-wide lock and breaks on
  substrings that share bytes, so the bit stays compile-time here.
- **US-ASCII is UTF-8.** As spinel's `docs/limitations.md:1990-2015`
  argues, US-ASCII and ASCII-only UTF-8 agree on every operation that can
  tell two Strings apart (`==`, `hash`, `length`, `[]`, regexps,
  `encode`, ...); only the encoding's name (`1.to_s.encoding`) and
  `inspect` of a control byte (`"\x01"` vs `"\u0001"`) differ, which are
  decision 136's derived-encoding differences.
- **Way in for other encodings.** Text in Latin-1, Shift_JIS, UTF-16, ...
  is converted where it enters: `s.encode("UTF-8", "ISO-8859-1")` (decision
  380's tables), or an IO mode with an internal encoding (`"r:ISO-8859-1:UTF-8"`).
- **Warning.** `force_encoding` whose argument is a literal naming an
  encoding MRI has and rugaroo can transcode, other than UTF-8, binary,
  US-ASCII and the default-encoding names (`"ISO-8859-1"`, `"utf-16le"`,
  `Encoding::Shift_JIS`, `::Encoding::ISO_8859_1`; matched with `-`/`_`
  ignored), warns: `force_encoding("ISO-8859-1") keeps the bytes and reads
  them as UTF-8: a String carries no encoding tag (decision 439); convert
  the text with encode("UTF-8", "ISO-8859-1")`. A warning, not an error:
  the 5 gem sites run correctly on ASCII data, and an error would reject
  programs that compile today. A gem file's warning is printed only under
  `RUGAROO_GEM_WARNINGS=1`, as every gem warning (`addWarning`). A name
  rugaroo lacks stays decision 136's compile error, without the warning;
  a variable argument is not seen. Proof: `testdata/errors/encoding.txtar`
  (`force_encoding_latin1`, `force_encoding_sjis_const`).
- **Producers** (amends decision 352). Spinel's producer list
  (`docs/limitations.md`, the same row) has one rugaroo lacked: `unpack1`
  with a literal format whose first directive is `a`, `A`, `Z`, `m`, `u`
  or `M` now returns a binary String (`__unpack1_binary`, picked by
  `literalOverload` like `__pack_binary`; MRI's result is BINARY whatever
  the receiver's encoding), so `"é!".b.unpack1("a*").length` is 3. A gem's
  `unpack1` keeps decision 324's wrapping form. No cost to programs that
  never call it (pruned). Proof: `testdata/test/string_test.rb`
  (`test_binary_flavor_producers`).
- **Not done here, filed:** the binary flavor across a parameter, ivar or
  collection element (#150), and `Encoding::Converter` (#151).
