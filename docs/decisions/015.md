# Decision 15

**Rule:** Ivars type from `attr_*`/`@rbs` annotations or a dry run of the class's bodies, where an unannotated user ivar is the join of its writes; unannotated `[]`/`{}` ivars type from what is stored, dry-run checked.

Instance variables are typed from `attr_*` annotations, `# @rbs @x: T`,
or a dry run of the class's method bodies (`initialize` first); an ivar
that is only ever assigned `nil` needs an annotation.
*Amended:* an ivar first assigned an unannotated `[]`/`{}` is typed
as decision 13 types locals, from what the class's methods put in it,
re-discovering until nothing new is typed. Evidence that is untyped
only because it reads the container itself (`h[k] = (h[k] || 0) + 1`)
is skipped. Every typing is checked by a dry-run emission of the
classes that see the ivar: one that fails to compile or adds a
conversion is dropped, trying all, then all but one, then one at a
time ([example 35](../../examples/035_ivar_containers/main.rb)).
*See also decision 307:* in gem code only a conversion where something is stored (an element added, an ivar assigned) vetoes a typing.

*See also decision 433: a cache hit with the same candidates applies the recorded outcome instead of the dry runs.*

*Amended (#127):* in user code an ivar no annotation types is the join (decision 150) of its non-provisional writes, `=` and `op=` alike, as a local assigned two classes is: `@value = ""` in `initialize` and `@value = v` with `v: Array[Integer] | Integer | String` is that union, `@total = 0` then `@total += 1.5` is `Integer | Float`, two sibling classes their nearest common superclass. The first write no longer pins the type, which made an ivar stricter than a local for no reason MRI has ("cannot assign String to @id, which is Integer"). An annotation (`attr_accessor :v #: T`, `# @rbs @v: T`, a trailing `#:`) still decides alone, and gem code keeps first-write-declares (its ivars widen to untyped instead, decisions 331, 392, 416). An open `[]`/`{}` ivar is still typed by the refinement above. What a union cannot hold stays an error, now saying why: two instantiations of one generic class (`Array[Integer]`, then `Array[String]`: one Go type) and a module (decision 385). A literal written under the ivar's type (`@a = ["x"]` into an `Array[Integer]`) fails inside the literal, as before ("String where Integer is expected"). spinel's `bm_poly_cells` == MRI, its Go identical to the hand-annotated `attr_accessor :value #: Array[Integer] | Integer | String`; every example, `testdata/run`, `testdata/test`, benchmark and spinel `bm_*` program but `union_test.rb` and `bm_poly_cells` generates byte-identical Go (`union_test.rb` `UnionIvarTest`, `objects.txtar` `ivar_reassigned_*`).

*See also decision 440:* a typing whose only veto is a nil read (decision 20) is kept, its nil sites checked at run time.
