# Decision 498

**Rule:** A module's self call of a name it does not answer, which every class that includes the module resolves to one sibling module's method, compiles as that module's method on self asserted to its constraint; an includer with its own definition leaves the call dynamic.

**A module's self call of a sibling module's method** (2026-11-26; extends 486). *See also decisions 9, 214, 234, 307, 486.*

rack's `Request::Helpers` calls `get_header` and `set_header` on self; `Request::Env` answers them, and `Rack::Request` includes both. Decision 307 copies such a method into its includer, but only an unannotated one, and the vendored `sig/gems/rack/rack.rbs` annotates Helpers. The method then stayed shared, and decision 486's `includerRoot` took only a class's method ("an includer that resolves the name to a module ... leaves the call dynamic"). Every one of those calls was `rbDynGetHeader(rbFCall, self, ...)`.

- **The rule** (`siblingModuleRoot`, `dispatch.go`). When a class resolves the name to a method of a module that is neither universal, generic nor the prelude's, that entry stands where `classRoot` found none. `includerRoot` still requires every class that includes the calling module to resolve to the same method, so a class or subclass that defines the name itself leaves the call dynamic, and its override runs.
- **The call** (`includerRootCall`). The sibling's body is generic over its own constraint, which every includer satisfies: `Env_GetHeader[Env_Self[any]](any(self).(Env_Self[any]), name)`, typed as one includer's resolution (`anIncluder`). The rest is decision 486's: only a dispatchable method, without a block, when the typed call compiles; the value is boxed to untyped unless the method's own type is one.
- **At the sibling's own constraint, always** (2026-11-27). The call was typed as one includer's resolution, and for a method that keeps its direct call (a private one nothing overrides, decision 486) the type argument was that includer's interface: `Util_CommentLineQ[Style_DocumentationI](any(self).(Util_Self[any]), ...)`, which Go rejects. The method was then a stub that raises (decision 205): compiled rubocop had 19 such methods where main has 4, and `Style/Documentation` raised on every class. `atConstraint` rewrites the one call to `Util_CommentLineQ[Util_Self[any]](...)`; a call it cannot find in that form stays dynamic. Counting dynamic calls did not show this; stubbed methods (`does not type-check in Go`) are counted with them now.
- **Where it came from.** Crystal resolves a call on a module-typed receiver over the module's including types (`lookup_matches_in` for a module, `semantic/call.cr`). A closed world gives rugaroo the same set.

- **Speed.** None measured: the example runs 71-73M instructions before and after (three runs each), most of it start-up. This is a typing change.
- **User code too.** An annotated module method in a program's own code takes the same call (it was dynamic, with a warning).
- **Proof:** `testdata/test/dynamic_test.rb` `DispSiblingModuleTest` (two modules and a subclass; a private method with three includers, which did not build before the constraint fix; a second pair where one includer defines the name itself and its own method still runs); example 116; `overrides/rubocop/check`.
