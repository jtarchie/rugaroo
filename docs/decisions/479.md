# Decision 479

**Rule:** One compile parses each source and gem file once and shares the tree with its later rounds and passes; a file whose tree a pass rewrote in place leaves the cache at that pass's end and is parsed again, and `RUGAROO_NO_FILE_REUSE=1` parses every file every pass.

**The parse, not the scan** (2026-11-21; the user's piece-table suggestion). *See also decisions 430, 478.*

Decision 478 found that each round and pass parsed every source and required gem file through prism's wasm again, and that sharing the whole require scan broke on two things: passes rewrite trees in place, and the scan depends on what earlier passes autoloaded. Both go away one level down.

- **The cache is per file** (`fileCache` on `options`, key: name and text; `parseSource`). The scan still runs in every pass and walks whatever that pass's autoload state says; only its `parseFile` calls are answered from the cache, as are `bundledAutoloads`' and a lazily required file's.
- **A rewritten file is dropped, not protected.** A file's tree is summed when parsed (`nodeSum`: every node's type and place, in order) and again when a pass that used it ends (`dropRewritten`); a different sum deletes the entry, so the next pass parses it fresh, which is what every pass did for every file before. Nothing has to know which pass rewrites what. `RUGAROO_TREE_CHECK=1` prints each def a pass rewrote: over `testdata/test`, `testdata/run`, the examples, liquid, kramdown and the parser gem's test program it names three kinds of site (a `def m(...)` whose forwarded arguments link fills in, a `def self.included(base)` hook, one kramdown method), so nearly every file is shared.
- **What the sum does not see:** a rewrite that changes a field of a node and neither a node's type, place nor children. None is known; the parse-time lowerings (`fillAnonForwards`, `lowerSingletonDefs`, the Sorbet pass) run before the sum is taken, and what gen writes into a `File`'s side tables (`lambdaOpt`, `movedOpts`, `kwBlocks`) stays with the shared `File`. `scripts/gen-compare` with the reuse on against off is the check, and the one to rerun when a pass that edits trees is added.

**Measured** (idle machine, generated Go byte-identical on and off): the parser gem's test program `prelude` 4.7 s -> 0.6 s, compile 47.8 s -> 43.1 s; `scripts/gen-compare`: 272 of 272 inputs the same.
