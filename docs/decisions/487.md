# Decision 487

**Rule:** An environment switch that turns a landed optimisation off is temporary: it is removed, with the code path it kept, once the change has passed the suite, ruby/spec and the rubocop check; cache bypasses and `RUGAROO_NO_PRUNE` stay.

**Sixty switches, four kinds** (2026-11-22). *See also decisions 377, 386, 387, 389, 402, 444, 480, 485, 486.*

`RUGAROO_*` variables had grown to sixty. Most are one of three healthy kinds, and stay:

- **A behaviour option that mirrors a CLI flag** and selects a tested lane: `RUGAROO_INT_OVERFLOW`, `RUGAROO_REGEXP_COMPILE`, `RUGAROO_NIL_CHECK`, `RUGAROO_CGO`, `RUGAROO_COMPILER`, `RUGAROO_BACKTRACE`, `RUGAROO_GO_STACK`.
- **A diagnostic that only prints**, and changes no output: `RUGAROO_TIMING`, `RUGAROO_UNTYPED_REPORT`, `RUGAROO_UNTYPED_WHY`, `RUGAROO_INFER_DEBUG`, `RUGAROO_INFER_USES`, `RUGAROO_DISPATCH_DEBUG`, `RUGAROO_PRUNE_DEBUG`, `RUGAROO_PRUNE_WHY`, `RUGAROO_TREE_CHECK`, `RUGAROO_CPUPROFILE`, and their like.
- **A test-harness knob:** `RUGAROO_NO_MRI_CACHE`, `RUGAROO_RUN_SKIPPED`, `RUGAROO_TEST_TIMING`, `RUGAROO_FUZZ_*`.

The fourth kind turned an optimisation that is on by default off. Each was useful to measure its change and to bisect a regression just after it landed. None was run by a test or a script, so each was a second compiler nobody ran.

- **The rule.** A new change may land with such a switch. The switch and the path behind it are deleted in the batch after the one that landed it, once the full suite, a ruby/spec run and compiled rubocop's check against MRI have passed with the change on.
- **What stays for good:** a cache bypass, since ruling a cache out is always a fair question (`RUGAROO_NO_INFER_CACHE`, `RUGAROO_NO_WASM_CACHE`, `RUGAROO_NO_FILE_REUSE`), and `RUGAROO_NO_PRUNE`, which a test uses and the pruner's debugging needs.
- **Removed now, eleven:** `RUGAROO_NO_SPECIALIZE` (377), `RUGAROO_NO_WINDOW_REUSE` (386), `RUGAROO_NO_COUNTED_LOOP` (387, 402), `RUGAROO_NO_ZIP_FUSE` (389), `RUGAROO_NO_ANY_USE` and `RUGAROO_NO_EARLY_ROUNDS` (444), `RUGAROO_NO_WIDEN_CHAIN` (480), `RUGAROO_NO_MODULE_ARMS` (485), `RUGAROO_NO_PRIVATE_DISPATCH` and `RUGAROO_NO_INCLUDER_DISPATCH` (486), `RUGAROO_INFER_SPECIAL`. The defaults do not change, so generated Go is the same: `scripts/gen-compare` before against after.
- **`RUGAROO_INFER_UNKNOWN` is not this kind.** It is a second way of inferring, with its own code beside the default's. It ends by becoming the default and the old path going, not by staying a switch (docs/research/inference-2026-11.md).
