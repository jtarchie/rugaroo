# Decision 489

**Rule:** An interpolation reads each part at its turn (an earlier part a later one may change is read into a temporary first), `a[i] op= b[j]` with a nilable element operand of an Integer or Float Array takes the fused in-place update, and a `sub`/`gsub` block whose value is always a String replaces through a typed `func(String) String` with no `to_s` through an untyped value.

**Three small fixes** (2026-11-22). *See also decisions 382, 469 (amended), 488 (amended), 241.*

- **Interpolation order.** `j = 0; "a#{j += 1}b#{j += 1}c#{j}"` is `a1b2c2` in MRI and was `a2b2c2`: the assignments are statements the compiler emits ahead of the String, so every read of `j` saw its last value. `pinInterp` (`internal/compiler/expr_literal.go`, called by `interpParts` after each embedded part) does what an Array literal's `pinExprs` does: when a part emitted statements, the earlier parts are read into temporaries placed before those statements, except a local of the current scope that neither those statements nor any block assigns (`localKept`), and a part already read into one. Go orders calls but not plain reads against them (`self.s + Sw(self)` may read the field after the call), so when a part emitted nothing but may have side effects (anything but a variable read or a literal, or a `to_s` other than the prelude's), an earlier part that a call can change is read first too: an ivar, a global, a class variable, a block's outer local, or a local some block or lambda assigns (`writtenInBlock`). A local of the current scope that no block assigns changes only by a statement, so `"#{name}: #{foo(x)}"` takes no temporary, and an interpolation of plain variables and literals is unchanged. An Integer part pins its Integer (the `strconv.AppendInt` path of decision 488 reads the temporary); a String part pins the String; anything else pins its `to_s` result, which MRI also takes at the part's turn. One exception follows MRI's aliasing: a part that a later part appends to in place (`"#{s}#{s << "x"}"`, `concat`, `setbyte`, decision 382) is the same object in MRI, which shows the append (`axax`), so it is left as it was; `s += "x"` makes a new String in MRI and is pinned (`aax`). An Array literal still misses the no-statement case (`[@a, bump]` reads `@a` after `bump`), and so does a call whose argument emits statements after a plain receiver (`c * 2 + id(c += 1)` is 6, MRI 4: the receiver is not pinned in `genMethodCall`); neither is changed here.
- **Nilable element operand.** `sums[b] += vals[j]` (spinel's `bm_histogram`) has a `Float?` right-hand side, which `fusePure` refused, so it took the read-then-write path (`rbArrAt`, three `rbNilArgO`, an atomic frozen read). `fuseElemRead` (`internal/compiler/expr_hashfuse.go`) accepts `x[i]` as a fused operand when `x` is a local or ivar holding an Array of Integers or Floats with the prelude's `[]` and `i` is itself pure and an Integer: it only reads. A nil element raises in the operation exactly as before (`nil can't be coerced into Float`, before the frozen check and the write), since the operand is generated by the same `genOp`. The frozen check is not hoisted out of loops.
- **Typed `gsub` block.** `subBlockLastMatch` (`internal/compiler/expr_lastmatch.go`) now also takes a `sub`/`gsub` call with a block on a String outside a `$~` frame when `blockGivesString` (a probe of the block with its return as a type variable) finds the block's value is always a String: the closure is `func(String) String` and the replacement goes through `rbReBlockS` (or `rbReBlockLMS` in a `$~` frame; `prelude/go/regexp.go`), not `rbToS(any)` per match. A block that may return anything else (an Integer, nil, an object with its own `to_s`, a `String?`) keeps `rbReBlock`, where MRI's `to_s` runs. `rbReplaceLocs` grows its builder to the subject's length first.
- **Measured** (instructions retired, `GOMAXPROCS=1`, macOS arm64, load 6-9 from other work, two runs each, before/after; outputs equal): bm_histogram (`--nil-check=runtime`) 11,041M/11,034M to 10,039M/10,034M, 0.77-0.78 s to 0.64-0.81 s; regexp 2,792M/2,748M to 2,451M/2,392M (-13%); strings 117M/108M to 113M/108M; format 1,203M/1,202M to 1,201M/1,201M; collections 932M/931M/932M to 931M/931M/932M; kramdown 4,155M/4,078M to 4,116M/4,075M and liquid 1,726M/1,747M to 1,739M/1,697M, within their run-to-run spread.
- **Cost:** TestCompileCost compiled functions 005_word_count 2,088 to 2,088, 064_observable 8,276 to 8,276, 116_cuba_web 33,441 to 33,439. `scripts/gen-compare` (examples, testdata, benchmarks, spinel's benchmarks): 101 of 347 inputs generate different Go, none newly fails; 16 differ only by `rbReplaceLocs`' `Grow`, most others by a temporary before an interpolation whose later part emits statements (minitest's message helpers, `Tempfile#inspect`).
