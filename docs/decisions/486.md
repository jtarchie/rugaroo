# Decision 486

**Rule:** A private def dispatches by type switch as a public one does (decision 212), a name a module calls on self without answering it keeps no Go method on its includers, and that call goes to the includers' one dispatchable owner when they share one; attr accessors stay Go methods on their owner.

**Fewer forwarders: private defs and includers' names leave the Go method set** (2026-11-21; amends 212, extends 234; docs/research/function-count-2026-11.md option B). *See also decisions 208, 210, 212, 213, 234, 253, 307, 485.*

## Private defs

`plainMethod` admitted only public defs, and decision 212 did not say why. A private method nothing overrides is already its free func, called directly (`staticPrivate`, decision 253), with no interface slot and no forwarder. One a subclass overrides is an interface slot with a forwarder on every class below its owner: rubocop's `Cop::Base#range_for_original` and `#apply_correction` were 614 forwarders each. Now such a method dispatches like a public one: a self call is the owner's free func, or its `rbSend_` switch when overridden, and the name leaves the interfaces.

- **No real reason for public-only.** Visibility is checked where a call is resolved, before dispatch is chosen (`checkVisibility`: a private method with an explicit receiver is a compile error in typed code); `send`, `public_send`, `respond_to?(x, true)` and an untyped receiver's call go through the Dyn wrappers and the `rbHas_Private` tables, which read the class's own resolution and never the Go method. Nothing in prelude Go selects a private name. With the admission open, `go test ./...` finds no failure.
- **A private method nothing overrides keeps its direct call** (`dispatchCall` skips `staticPrivate`): a module's one would otherwise switch from `Mod_X[Self](self)` to an instantiation at the constraint, `Mod_X[Mod_Self[any]](self)`, which is a new instantiation where the caller's Self is a class interface (`116_cuba_web`'s `Rack::Request::Helpers`, +11 compiled functions).
- **Attr readers and writers are not admitted.** They are not free funcs: `emitMethod` writes them as Go methods on the owner's struct, which subclasses get by embedding, so they have no forwarders to remove (`needsForwarder`), and a dispatched one would still be a Go method on every class (Go's promoted wrapper). Removing those means emitting accessors as free funcs, a separate change. rubocop's `Cop::Base#config` and `#processed_source` are defs in the compiled gem (its patch), which the next part frees.

## A module's self call of its includers' method

`includerCalls` kept a class method a Go method on every class when a module the class includes calls the name on self. But a module's constraint declares only what the module itself answers (`emitModuleInterface`: its own and included modules' methods, Object's, and `_ClassObj` for `self.class`); a name it does not answer was compiled as a dynamic call, `rbDynConfig(rbVCall, self)`, which the class's Dyn wrapper answers. So nothing needed the Go method: rubocop's `Cop::Base#config`, `#cop_config`, `#cop_name`, `#processed_source`, `#target_ruby_version` (~615 forwarders each), `Module#method_defined?`, `#private_method_defined?` and `#autoload` (2,010 each, called by modules extended onto classes) were kept for it.

- **`notModules`**: a name the module calls on self that neither it, its `method_missing`, a top-level def nor Object answers (nor `class`, which the constraint declares as `_ClassObj`). `includerCalls` skips such a module. This holds whether or not the includers agree on the method: the module's call is dynamic when they do not.
- **`includerRoot`**: when every class that includes the module resolves the name, from the topmost class of its chain that still defines it, to one struct-class method, the module's call compiles as decision 234's does for an included module: `Owner_X(any(self).(OwnerI), ...)`, or its `rbSend_` switch when a class below overrides it, so the override runs (`includerRootCall`). Only when that method is dispatchable, without a block, not an iterator, and when the typed call compiles (a probe, as gem calls do; else it stays dynamic). Its value is boxed to untyped, as the dynamic call's was, so inference sees the same program; a void method in user code stays dynamic, where Go would reject its value.
- An includer that resolves the name to a module, a universal owner, another class's method or nothing leaves the call dynamic, as before.
- **Found on the way:** dropping `class` from the constraint made 2,242 rubocop methods fail Go's type check (stubs, decision 205): the gen-time `does not type-check` warning count is the check for this. A typed call inside a probe makes one attempt, not a probe of its own (as `callEntryAny`), or nested self calls in arguments cost a probe per level. `RUGAROO_DISPATCH_DEBUG=all` on rubocop is slow (each memo miss prints); measure without it.
