# Decision 477

**Rule:** A splat's element is a use of each parameter it fills, in a static call and (once the not-known-yet rounds resolve) in a dynamic call by name, where every parameter from the splat on takes an untyped use; agreeing dynamic calls of a setter (`x.name = v`) do not type its parameter.

**Found by rubocop under `RUGAROO_INFER_UNKNOWN=1`** (2026-11-21). *See also decisions 184, 331, 444, 475.* Both parts are about a parameter typed from the calls that could be counted while a call that could not be was ignored.

- **A splat in the arguments.** The parser gem's `@builder.loop(:while, val[0], *val[1], val[2], val[3])`: `noteDynUses` skipped a dynamic call holding a splat, so `loop`'s parameters were typed by the calls without one (`dynUsesAgree`), and the splat call then put the body's Array where a token pair was expected: `no implicit conversion of Array into [String, Parser::Source::Range]` on every file with a `while`. A dynamic call with a splat now gives each parameter from the splat's place on an untyped use (`noteDynSplat`), in the resolved phase, as any other untyped gem argument there. The default lane never typed a parameter from dynamic calls alone (decision 331), so it had no such case. A static call's splat into positional parameters (decision 184) now records the splat's element type as a use of each parameter it fills (`genArgs`), in both lanes: it recorded nothing.
- **A setter.** `self.config_to_allow_offenses = { 'Enabled' => false }` in rubocop's cop mixins is a dynamic call by name, which reaches every gem method of that name: `Cop::Base`'s, which it means, and the `attr_accessor` of `Formatter::DisabledConfigFormatter`'s class object, which holds the Hash those hashes are kept in. All the calls agreed, so the formatter's Hash was a `Hash[String, Boolean]` and `Base#config_to_allow_offenses` answered a Boolean. A setter's parameter is an ivar's value, and decision 331's caution (the call may be meant for another class's method) costs most there, since the ivar's readers are typed from it; `dynUsesAgree` leaves a setter's parameter to its static calls (`paramUse.setter`).

**Open, same family:** a typed receiver's call with a splat of a tuple (`b.pair(:x, *val[1])`, `val[1]` a `[Array[Integer], Symbol]`) goes through the Dyn wrapper and raises TypeError when the parameter was typed by another call, in the default lane too. Not seen in a gem yet.

**Proof:** `testdata/run/gem_inference/lib/splat_gem.rb` (fails under the switch without `noteDynSplat`). The setter rule has no small fixture (two attempts compiled correctly without it); it is checked on rubocop: `config_to_allow_offenses` is no Boolean in the generated program.
