# Decision 449

**Rule:** `-profile-out FILE` (build, run, test) builds a binary that records a CPU profile from its start to `rbFinish` and writes it to FILE, for a later `-pgo FILE` build of the same program; `-pgo` also works on `rugaroo test`.

**Profile, then rebuild** (#116; amends decision 377's PGO finding; 2026-11-13).

The 2026-10-26 measurement (issue #116) found PGO worth 0-15% instructions only with a profile of the program itself; a shared prelude profile was noise. `-pgo FILE` (babc5afc) passes a profile through to `go build -pgo`; nothing produced one without writing Go.

- **How.** With `-profile-out`, the CLI writes a second file into the temp module beside `main.go`: `profile.go`, whose `init` opens FILE (the path as given, so relative to where the binary runs) and starts `runtime/pprof`, and sets `rbProfileStop`. `rbFinish`, where every normal end and uncaught exception goes after the at_exit handlers, calls it before printing the uncaught exception or exiting. `exit!` (no at_exit, no flush in MRI either) and a death by signal write no profile.
- **Cost:** none for a normal build: `rbProfileStop` is one nil check at exit; `runtime/pprof` is linked only into the profiling binary.
- **Not built:** `--pgo=auto` (build, run once, rebuild), which would need the user's representative input anyway; TinyGo refuses `-profile-out` as it does `-pgo`.
- **Proof:** `TestProfileOutThenPGO` (cmd/rugaroo): builds a fib program with `-profile-out`, runs it (a non-empty profile is written), rebuilds with `-pgo`, and both binaries print what MRI prints; `rugaroo test`'s flag parser takes both flags. docs/cli.md's "Make a hot program faster".
