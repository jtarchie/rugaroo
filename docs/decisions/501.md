# Decision 501

**Rule:** Comparable's `==` is `<=>` answering 0, a gem's alias of an inherited fixed-arity method keeps that method's arity and signature, a gem's `fetch(key, default)` whose default is of another class than the values answers the default as it is, a default that is another parameter's untyped value is an untyped argument, `URI` parsers' `make_regexp` takes the schemes, and a nilable tuple keys a Hash by value.

**What compiled rubocop showed `main` got wrong** (2026-11-27). *See also decisions 287, 444, 497, 499.*

`overrides/rubocop/check` on eleven inputs (four prelude files, two examples, a script, two minitest files and the directory of them): `main` matched MRI on 5 of 12 outputs. Each cause, in a repro of a few lines, then fixed by a general rule:

- **Comparable#==.** The prelude's Comparable had no `==`, so an includer that only defines `<=>` (parser's `Source::Range`) compared by identity: rubocop's `modifier_locations.include?(node.loc.keyword)` never matched, and `Style/RescueModifier` reported nothing. Comparable#== is now MRI's: the same object, or `<=>` answering 0 (nil is not equal; a value of another class is not equal). An includer's own `==` still wins. It is written in Go over the includer's own `<=>` (`cmpNil` when that may answer nil): a first version called `<=>` on an untyped self, which put a dynamic call, and its warning, into every program.
- **An alias of an inherited fixed-arity method.** A gem's `alias_method :eql?, :==` of a module method is a forwarder (decision 444), and it took `*args`: its `eql?(*args)` matched no Hash key interface, so a value-keyed Hash fell back to identity. A forwarder of a method with only required positional parameters takes that many, under the method's own signature when it names no `self` (`aliasForwarder`).
- **`fetch` with another class's default.** rubocop's `REVERSE_COMPARISON.fetch(operator.to_s, operator)`, a Symbol default beside String values: the typed fetch converted the default and raised `TypeError`. In gem code such a call is `h.key?(k) ? h.fetch(k) : d`, with the receiver and key read once, when d is a literal or a variable read (`fetchOtherDefault`).
- **A default that is another parameter.** `report_offense(node, ..., offense_range: node)`, a Range from the calls that pass it: the keyword was typed Range and the untyped `node` converted to it. In gem code such a default is a real untyped argument, so the parameter is untyped (`noteDefaultUse`).
- **`make_regexp(schemes)`.** rubocop's `LineLength#uri_regexp` passes the schemes; the prelude's took none (ArgumentError). It now prefixes MRI's case-insensitive scheme lookahead.
- **A nilable tuple key** (`@seen[@ast]`, `@ast` a `[Symbol, String]?`): `rbPlainKey` called the tuple's value method on a nil pointer. A pointer-to-tuple key is not plain (`rbPlainOf`).

**Measured:** the eleven inputs and the directory equal MRI on all 12 outputs, 4 stubbed methods as on main.

**Proof:** `testdata/test/object_test.rb` `ObjectBugComparableStructTest` (fails on main), `testdata/test/stdlib_test.rb` `test_make_regexp_with_schemes`, `testdata/test/hash_test.rb` `test_nilable_tuple_key`, `testdata/run/gem_lenient.rb` (`fetchish`, `kwdefish`), `overrides/rubocop/check`.
