# Decision 434

**Rule:** Every test program's prelude `//line` directives are made stable before its build: pinned to `:1` where the program is only built, and numbered consecutively per prelude file where it is also linted (the examples), so a prelude line shift changes no program's bytes and lint positions stay distinct.

2026-11-01, amends decision 88. Decision 88 pinned prelude `//line`s in TestRun and TestMinitest and left the examples with real lines because golangci-lint correlates `//nolint` comments by position. Measured (docs/research/test-time-2026-11.md): a one-line comment near the top of prelude/string.rb changed the bytes of all 137 examples (only their `//line prelude/string.rb:N` lines), of TestMulti's two programs (never pinned, though the decision said so), and of TestBootAutoload, the traced tests, TestGemCorpus and TestPrimeVendoredSig; the run took 1974 s against 337 s warm, 1530 s of it the examples' lint pass alone after the last example.

- **Consecutive numbering** (`stableLines(code, pinned=false)`): walking main.go, each prelude file's first directive becomes `:1` and each later one `:1 + the lines of that file's earlier blocks in this program`. Positions are unique within each prelude file, as with real lines, so an inline `//nolint` still covers exactly its own node; a line added above a block in the prelude changes nothing, and adding a method still changes only the programs that keep it (their later blocks renumber). Checked on a 5-example module (30_dynamic_send and four small ones), real against renumbered: clean on both; with every `//nolint` comment stripped, 56 gosec issues on both with identical texts; an injected printf misuse reported on both.
- **Pinning** (`pinned=true`, the `:1` of decision 88) stays for TestRun, TestMinitest and now TestMulti, TestBootAutoload, TestTracedEntry, TestTraceEval, TestTraceRun, TestGemCorpus, TestPrimeVendoredSig: nothing lints them, and keeping their bytes as before costs no cold run.
- **What it leaves**: user-file and absolute `//line`s (`-I`, `-gem`, traced gem paths) are the program under test and stay real, so a worktree still rebuilds the 17 programs naming its path; `rbMethodInfo` keys carry a prelude byte offset (`String#@prelude/string.rb:2874`), so a shift above a method's definition still changes the two programs that build such a table (TestMinitest/method, prism).
- A lint failure on an example then reports a consecutive line, not the prelude's: `rugaroo build -work` on the example gives the real one.
