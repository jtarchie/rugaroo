# Decision 434

**Rule:** Every test program's prelude positions are made stable before its build: `//line` directives pinned to `:1` where the program is only built and numbered consecutively per prelude file where it is also linted (the examples), and Method keys' prelude byte offsets renumbered 1..n per file, so a prelude line shift changes no program's bytes and lint positions stay distinct.

2026-11-01, amends decision 88. Decision 88 pinned prelude `//line`s in TestRun and TestMinitest and left the examples with real lines because golangci-lint correlates `//nolint` comments by position. Measured (docs/research/test-time-2026-11.md): a one-line comment near the top of prelude/string.rb changed the bytes of all 137 examples (only their `//line prelude/string.rb:N` lines), of TestMulti's two programs (never pinned, though the decision said so), and of TestBootAutoload, the traced tests, TestGemCorpus and TestPrimeVendoredSig; the run took 1974 s against 337 s warm, 1530 s of it the examples' lint pass alone after the last example.

- **Consecutive numbering** (`stableLines(code, pinned=false)`): walking main.go, each prelude file's first directive becomes `:1` and each later one `:1 + the lines of that file's earlier blocks in this program`. Positions stay unique within each prelude file, as with real lines; a line added above a block in the prelude changes nothing, and adding a method still changes only the programs that keep it (their later blocks renumber). What was checked, real lines against renumbered: all 137 examples lint clean (run P0); on a 5-example module (030_dynamic_send and four small ones) with every `//nolint` comment stripped, 56 gosec issues on both with identical texts; an injected printf misuse reported on both. Not claimed: that an inline `//nolint` under a `//line` covers its own node; in that injection a `//nolint:govet` on the same line suppressed nothing in either variant (govet reports the `//line`-adjusted position, nolint matching reads main.go's), which is the coincidence decision 154's notes record; the renumbering neither adds nor removes such a case, since the main.go positions it reads do not move.
- **Method keys** (`"String#@prelude/string.rb:2874"`, decisions 414/418: a def's identity, so aliases compare equal): the byte offset moves with any edit above the def, which changed TestBootAutoload, 098_method_objects and 136_prism_parse in run P2 (320 s of lint for the last). Each prelude file's distinct offsets in the program become 1..n in numeric order, an injective map, so every equality the program computes is unchanged.
- **Pinning** (`pinned=true`, the `:1` of decision 88) stays for TestRun, TestMinitest and now TestMulti, TestBootAutoload, TestTracedEntry, TestTraceEval, TestTraceRun, TestGemCorpus, TestPrimeVendoredSig (the last added after run P2 showed its bytes still moving: a hit only because run b1 had built that variant): nothing lints them, and keeping their bytes as before costs no cold run.
- **What it leaves**: user-file and absolute `//line`s (`-I`, `-gem`, traced gem paths) are the program under test and stay real, so a worktree still rebuilds the 17 programs naming its path.
- A lint failure on an example then reports a consecutive line, not the prelude's: `rugaroo build -work` on the example gives the real one.
