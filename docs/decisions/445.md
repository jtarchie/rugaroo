# Decision 445

**Rule:** A program's unannotated attr writer that no call types, and that no `.x =` call, `:x=` Symbol or computed `send` in the program may reach, takes its ivar's type from the ivar's other writes (untyped only when there are none) instead of declaring the ivar untyped.

**Uncalled attr writers** (#152; amends decision 394; 2026-11-13). *See also decisions 15, 150, 179, 183.*

```ruby
class Cell
  attr_accessor :value      # value= is never called
  def initialize = @value = nil
  def set(v) = @value = v   # set("hello"), set(42), set([1, 2, 3])
  def get = @value
end
```

Before, `value=`'s parameter had no call to type it (decision 179: an attr writer no call types is untyped), its `@value = value` declared `@value` untyped, and every read went through dynamic dispatch: `render_one(cell.get)` warned that its parameter is untyped. Without the `attr_accessor` line `@value` is `Array[Integer] | Integer | String | nil`.

- **Final compile.** `resolvePending` marks such a parameter `UncalledWriter`. Discovery's write of it declares nothing (`uncalledWriter`); after discovery `typeUncalledWriters` sets the parameter to the ivar's type, or declares the ivar untyped when no other write typed it (an attr only the writer writes, as before).
- **Rounds.** Decision 394 drops the writer's write while its parameter is awaited, then `stopUnjustifiedDrops` puts a parameter no call typed in `noDrop`, and later rounds wrote it honestly: the ivar went untyped in the last rounds, so its readers' callers (`render_one`) lost their types. For a program writer nothing reaches the drop now holds through the rounds (`infer.none` and not `writerReachable`), which is what the final compile does.
- **Reach, not calls.** A dynamic call (`obj.value = v` on an untyped `obj`, `send(name, v)`) records no use, so "no call types it" does not mean "nothing calls it". `writerReachable` is a text check over the program's files: an `.value =` (or `||=`, `+=`, ...) anywhere, a `:value=` Symbol, or any send-family call by a computed name keeps today's untyped ivar. False positives only keep the old behaviour. A gem writer is untouched: under pruning its parameter is `pendGem`, not `pendNone`.
- **Proof:** `testdata/test/union_test.rb` `UnionNilCell` gains `attr_accessor :value` and matches MRI; `TestUncalledWriterIvarTyped` (internal/compiler) compiles the issue's program with no untyped or dynamic-call warning, and with a computed `send` added keeps the old warning.
