# Decision 447

**Rule:** A program parameter whose every use is a container holding untyped (a mixed-value Hash literal's `Array[Hash[Symbol, untyped]]`) is typed as the join of those uses instead of untyped, so the container's methods and blocks compile; a block on a parameter that stays untyped names the parameter and the `# @rbs` annotation in its error.

**Partly typed parameters** (#153; amends decisions 146 and 183; 2026-11-13). *See also decisions 13, 150, 366, 460.*

```ruby
items = [{ title: "a", price: 1 }]
def f(items)
  items.each_with_index { |x, i| p x }
end
f(items)
```

A Hash literal whose values mix classes is `Hash[Symbol, untyped]` (decision 13's `joinOrAny`: a mixed literal is untyped rather than a union, so `opts[:a] + 1` stays a dynamic call instead of a compile error on a union). Parameter inference (decision 146) skipped every use that holds untyped, since in a round that usually means another pending parameter not yet typed; with no other use the parameter was untyped and its `each_with_index { }` was "blocks on untyped receivers are not supported" (spinel's bm_template_render).

- **The fallback** (`partlyTypedUse`): when every use of a parameter is a generic container (a class with type arguments) holding untyped somewhere, none is bare untyped, none comes from gem code or a dynamic call, and they join to one non-union type, the parameter takes it. Only the untyped parts stay dynamic: `x[:price] * 2` is a dynamic `*`, `items.each_with_index { }` is a typed Array iteration. In a round, a use that holds untyped only because another parameter is still pending gives way to the real type the next round, when that use is typed and the ordinary join applies.
- **Why not a union value type.** Typing the literal itself as `Hash[Symbol, String | Integer]` changes every program with an options Hash: a call one member does not answer is a compile error on a union (decision 150), where untyped dispatches. Annotating the parameter (`# @rbs items: Array[Hash[Symbol, String | Integer]]`) still gives the union when wanted.
- **The error.** A block call on an untyped value whose receiver is a parameter typed from use now says `blocks on untyped receivers are not supported: parameter x of f is untyped, as no call gives it one type; annotate it (`# @rbs x: T`)`, so the root is named rather than the symptom (it also explains the out-parameter case of #128).
- **Proof:** `testdata/test/infer_test.rb` `MixedLiteralTest` (an Array of mixed Hashes iterated with `each_with_index`, a mixed Hash mapped) against MRI; `testdata/errors/dynamic.txtar` `block_on_untyped_param`.
