# Decision 431

**Rule:** `rbIsProc` and `rbDynProcCall` list the Proc Go types the kept program can make, found by the pruner in the kept Go (creation sites: `Ref(f)`, `&f`, `new`, a written `*func` type, and generic calls that point at an argument), and go out after every other table; the render-time `procTypes` map is only the Go type to `TFunc` dictionary and the trigger for the eager recompile.

2026-11-01, compile-time research (docs/research/compile-time-2026-11.md, last section). The tables the output is built from were filled when a type or name was rendered, and discarded emissions render too (probes, `refineIvars`' dry-runs, decision 15), while memoized analysis lets the real emission skip a render a dry-run already made. So the tables said which emissions ran, not what the kept code names, and neither replaying nor snapshotting the dry-runs' registrations could make a cache hit's output equal a cold one's. This is the first table built from the output instead.

**Why creation sites are enough.** A Go value of type `*func(...)` exists only if some expression of that type was evaluated: an address taken (`&f`, inside `Ref[T](v T) *T` and any generic func that points at a `T`), `new`, or a value already of that type, whose type is then written somewhere or came from one of the former. The pruner (decision 49) visits exactly the kept code, so it notes, in its own walk (`visitMade`, `prune.go`):

- a `*func` type written anywhere, and every func type written inside a type argument;
- `&e`, and `Ref(e)` through the generic-call rule: `funcTypesOf(e)` types the operand from the AST alone (no `go/types`): a func literal, a declared parameter, var or field, a call's result (a func, a method or a func-typed field by name, a conversion, an instantiation's explicit or inferred type argument), a `range` element, a type switch's variable, an element of a declared array, slice or map;
- a call of a generic func whose type parameter `T` the callee points at: the argument bound to `T` is a creation site (`settleMade`, to a fixpoint, so `Wrap[F](f F) any { return Ref(f) }` called with a literal makes that literal's type).

Where the AST cannot tell an operand's func type, three widening steps keep the set a superset: inside generic code, every func type that can instantiate a type parameter (written in a type argument, or a generic call's func-typed argument); for an element of a container it cannot type, every func element type of a kept array, slice, map or channel; anywhere else (`procValve`), every func shape kept code writes, signatures included. A case is then the rendered Proc type whose shape matches (`funcShape`, `unify` for a generic shape). On examples 44, 98, 105, 108, 116, 123 and 124 the generic and container steps fire and `procValve` never does: that last step is sound by argument, not exercised by a tested program.

**Emitted last.** The cases depend on what is kept, and kept code grows for rounds after the tables (decision 49's `emitNext`), so the proc tables are the last batch; a later round that makes another Proc type is `errPruneIncomplete`, as a late table input already was. `len(procTypes)` stays in `tableInputs` only as that recompile's trigger: without it kramdown and cuba stopped recompiling eagerly (kramdown gen 25.0 → 22.2 s), but the lazy path then splits generic dispatch into a `_DynGen` method per round (`freeze` and `dup` are reached only through the tables), +135 compiled functions in cuba, so the trigger stays until `_DynGenN` is emitted once.

**Measured.** Kramdown (`gen -trace`, example 123): the output differs from before only by three dropped cases in each table, `*func(String, String) Boolean`, `*func(Symbol, Boolean) any` and `*func(any, any, any) any`, which no kept code makes (the last is the type the snapshot experiment lost: kept code writes that shape only as the signatures of `rbIvarSet` and `Kernel_InstanceVariable_set`, which nothing points at), and by the tables' position. Cuba's cases are unchanged. TestCompileCost: 2065 / 7950 / 30491 → 2065 / 7950 / 30488. The forced render of a proc literal's type in `genExpr` (decision 137) now only feeds the dictionary. Under `RUGAROO_NO_PRUNE` there is no pruner and every rendered Proc type is listed, as before.

**Not shown:** a cache hit skipping `refineIvars` producing the cold output; that needs the remaining tables built the same way.
