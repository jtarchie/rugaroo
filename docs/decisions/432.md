# Decision 432

**Rule:** Tables whose entries a name in kept code decides are left to the pruner: every tuple arity is emitted, a union helper when kept code names it, package vars are named by what they are (a regexp by its pattern's hash, a `/o` guard by file and offset) and emitted sorted, dispatchers go out in name order, the regexp2 engine is kept when a pattern var or a body names `rxAltReady`, and `rbStringLits` lists only the literal texts kept code spells, emitted with the proc tables.

2026-11-01, the rest of decision 431's refactor (docs/research/compile-time-2026-11.md): a table filled at render time also holds what discarded emissions (probes, `refineIvars`' dry-runs) and pruned bodies rendered, and its names and order reflect render order. These tables need no type analysis to fix, because a Go name decides them.

- **Tuples.** `TupleN` types and methods were emitted for the arities some render noted (`tupleN`). Now all of 2..`maxTuple` go out; the pruner keeps a type only when kept code names it, and a prelude helper naming `Tuple3` no longer depends on a render having noted 3. TestCompileCost unchanged.
- **Unions** (decision 150). `rbUnion_<hash>` helpers went out with the tables for every union any render named, and after them for late ones. Now `emitNext` emits a helper in the round kept code first names it (`reached`), like a dispatcher. The helper's own renders (its members' Go types) then come only from kept unions.
- **Package vars.** A regexp literal's var was `rbRe<len(pkgVars)>`, so dry-runs shifted names and order. It is now `rbRe_<fnv64 of the compiled args>`, the `/o` guard is `rbReO<file>_<offset>` (one per literal, MRI's rule), and `pkgVars` is a set emitted sorted. The pruner already dropped a var nothing names.
- **regexp2** (decision 242, amended). `needRxAlt` was a whole-program flag any render could set, even in a dry-run or a pruned body, and it then rooted the engine (`var _ = rxAltReady`) and rewrote every pattern var. Now the engine source is always emitted, with no root. A pattern that needs it initializes as `rbRxAlt(rxAltReady, rbRegexpNew(...))`, an interpolated or lenient one that may need it is wrapped in `rbRxAlt(rxAltReady, ...)`, and a `Regexp.new` of a run-time string emits `_ = rxAltReady` in its body. So the engine is in the program when kept code can build a pattern RE2 rejects. Patterns RE2 accepts keep plain `rbRegexpNew`: they never use the engine, and Go orders var initialization by reference. `rbRxAlt` is an identity that the compiler inlines.
- **Dispatchers.** `rbDyn_` dispatchers and respond_to? checks went out in the order names were noted, which the dry-runs shift (kramdown: `rbDynChr` and `rbDynEachByte` moved). Each `emitDynamic` pass now emits what it needs in name order; a wrapper body that notes more names feeds the next pass.
- **String literals.** `rbStringLits` (String#frozen? by identity) listed every literal text any render saw. Now it lists the ones a kept Go string literal spells (the pruner collects them). Those are the only bytes the linker can share with a String, so dropping the others changes no answer. Because kept literals keep growing after the tables, it goes out with the proc tables (decision 431), and the same late check covers it.

Measured (examples 44, 98, 105, 108, 116, 123, 124 against MRI; TestMinitest regexp/string/union/marshal/array/hash/dynamic files): all pass. TestCompileCost 2065 / 7950 / 30488 → 2065 / 7950 / 30489. The one extra `nm` symbol in cuba's archive comes with the regexp change; the function set is the same apart from `rbRegexpNewAfter` → `rbRxAlt`, and the linked binary has two symbols fewer. Kramdown's `rbStringLits` 1,485 → 1,466 entries.

**Not covered here:** the box tables (`rbUnbox`, `rbKeyUnbox`, `rbCmpBox`, `rbMBox`). Whether a `*T` value can exist needs the type of each `Ref`/`&` operand, and `T` itself is always written wherever such a value exists, so a written-type scan is already the pruner's pending-case rule (decision 49) and drops nothing more. See the research doc.
