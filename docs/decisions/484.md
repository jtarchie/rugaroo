# Decision 484

**Rule:** In gem code a method's block forwarded to a callee whose block takes other Go types gets an adapter that converts each yielded value, as an argument is converted; `Net::HTTPResponse#error!` and `#value` raise net/http's exception classes.

**Two stubs the not-known-yet rounds left in rubocop** (2026-11-21). *See also decisions 172, 248, 290, 477.*

- **A forwarded block.** `VariableForce::Branch::Base#each_ancestor(&block)` passes its block to the private `scan_ancestors`, which yields `branch` from `while (branch = branch.parent)`, an untyped local. With `RUGAROO_INFER_UNKNOWN` the block of `each_ancestor` is typed by what its callers' blocks do with the value (a `Branch::Base`), so it is a `func(BaseI) any` handed where a `func(any) any` is wanted: Go func types are invariant, the Go did not type-check, and the method was a stub. `forwardClosureCode` now wraps the block when a parameter's Go type differs (`paramTypesDiffer`): the adapter takes the callee's types and converts each value to the block's, a run-time check like any gem boundary's. A program's own code keeps its error.
- **`error!`.** rubocop's `RemoteConfig` calls `response.error!`; the prelude's `Net::HTTPResponse` had neither it nor `value`. Both are there with MRI's classes: `Net::ProtocolError` and its three `Proto*Error`s, `Net::HTTPExceptions`, and `HTTPError`, `HTTPRetriableError`, `HTTPClientException`, `HTTPFatalError`, each holding its `response`; the status classes raise their own, as MRI's `EXCEPTION_TYPE` says.

**Proof:** `testdata/run/gem_lenient/fwdblk.rb`; `testdata/test/net_test.rb` `test_error_bang_and_value`.
