# Decision 467

**Rule:** A `case` of an `Integer` or `Integer?` subject with four or more arms whose every `when` is a distinct Integer literal compiles to one Go `switch` on the value (nil takes a value no arm names); an untyped `ary[start, len]` reads only that span, and `ary[start, len] = []` at the tail truncates in place.

**Integer case, untyped spans** (amends decisions 236, 302; 2026-11-15).

- **The switch.** `genIntCase` (`gen_case.go`): the arms were a `switch { case rbOptEqV(t, 14): ... }` chain, each test a call; a Ragel scanner's `case _lex_trans_actions[_trans]` has hundreds of arms and ran half of them per token on average (8% of the parser gem's time once its lexer was typed). A Go `switch` on an integer is a jump table or a binary search. An `Integer?` subject copies its value into a temporary that starts at `max(literal) + 1`, so nil reaches the `else` as before. Any other subject (untyped, Float: `1.0` matches `when 1`), a duplicated literal, a non-literal `when`, or fewer than four arms keeps the chain.
- **Untyped spans.** `rbViewIdx2` (`ary[start, len]` on an untyped receiver) built the result from `rbViewElems(s)`, a copy of the whole Array as `[]any`; `rbViewIdxSet` did the same and then rebuilt the Array. racc's runtime pops its three stacks with `stack[-len, len]` and `stack[-len, len] = []` on every reduction, so each reduction cost the stack's depth three times over. The read now takes only its span; the assignment truncates with `_Resize` when it empties the tail and splices an `Array[untyped]` in place with `slices.Replace`.
- **Measured** (instructions retired, the parser gem on 21 files with the lexer's signatures of decision 466's experiment): 2,470M → 1,751M.
- **Proof:** `testdata/test/control_test.rb` `ControlIntCaseTest`; `testdata/run/gem_lenient/ragelish.rb` (`Scanner`, `Stack`).
