# Decision 443

**Rule:** `-compiler tinygo` (or `RUGAROO_COMPILER=tinygo`) on `build`, `run`, `gen` and `test` builds the output with `tinygo build -trimpath -no-debug`, selects the `rugaroo_tinygo` prelude/go files in place of gc's (`compiler_tinygo.go` for `compiler_gc.go`), refuses `-race`, `-gcflags` and `-pgo` and a `require` of a library TinyGo cannot build, and is experimental, proven by an opt-in `TestExamples` lane with a skip list; gc stays the default.

**TinyGo as a second Go compiler** (#144; 2026-11-11). Amends decisions 88 (build flags), 373 (a new experimental tier row), 403 (goroutine tags) and 426 (a third build tag). *See also decision 372, whose lane and skip-file format the TinyGo lane copies.*

**Why.** TinyGo makes binaries several times smaller (below) and targets WebAssembly and small devices, which gc's output does not reach. It costs build time and thread performance, so it is a flag, never the default.

**The flag is `-compiler`, not `-target`.** It mirrors `go build -compiler`, and it leaves `-target` free for TinyGo's own platform word (`wasip1`, `wasm`, boards), the main reason to use TinyGo. Spinel splits `--target` from `--cc` the same way. The value is `gc` (the default) or `tinygo`; anything else is an error, before the compile and again in the compiler (`compileEnv`). Passing `-target` through is not done yet.

**Selecting TinyGo's helpers.** Decision 426's `goFileSelected` evaluates each prelude/go file's `//go:build` line at compile time; `rugaroo_tinygo` holds under the flag. What differs per compiler lives in one pair: `compiler_gc.go` (`rugaroo_prelude && !rugaroo_tinygo`) and `compiler_tinygo.go` (`rugaroo_prelude && rugaroo_tinygo`). The pruner sees one definition of each name; no override directory, no shadowing rule. `TestPreludeGo` vets prelude/go under a third tag set, `rugaroo_prelude,rugaroo_tinygo`. PreludeWhole (the stubs, decision 154) stays on gc.

The pair holds what TinyGo cannot build or run as gc does:
- **Hashing.** `hash/maphash` reaches gc's map internals (`internal/runtime/maps`, `abi.MapType`) and does not build under TinyGo. Every hash goes through `rbHashString(s)` and `rbHashComparable(k)`: gc's call `maphash.String`/`maphash.Comparable` with the process seed, both inlined (below); TinyGo's linkname its runtime's map hashes, `runtime.hash64` and `runtime.hashmapInterfaceHash`, seeded from `runtime.rand`. The interface hash is 32 bits, so two seeds make 64. This also reaches `Regexp#hash`'s `%x{}` body, which a build tag cannot: it calls `rbHashString` too.
- **Goroutine id.** TinyGo's `runtime.Stack` writes nothing, so `rbGoIDStack` cannot parse a header (it sliced past the buffer and crashed every program before `main`). TinyGo's answers 1, gc's id for main, for main and any untagged goroutine; not 0, which `Mutex` reads as "no owner" (the first lane run failed 042 and 079 on it).
- **Goroutine tags** (decision 403). gc keeps the tag in the profiler-label slot, through runtime/pprof's linknamed accessors, which TinyGo lacks. TinyGo's tag lives in a `sync.Map` keyed by the running task (`internal/task.Current`, linknamed as `unsafe.Pointer`, so gc's vet does not need the package). `Task.Ptr` and `Data` look free but channels, `sync.Cond` and the scheduler write them. The key keeps the task, and through its canary pointer the goroutine's whole stack, alive, so a goroutine that tags itself (Thread, Ractor, Fiber, Timeout) defers `rbUntagGoroutine()`: gc's is an empty function. Unlike gc's label, a TinyGo goroutine does not start with its parent's tag; every goroutine that runs Ruby tags itself first, so only main reads the untagged id, which is its own.

The linknames name TinyGo internals that any release can rename: rerun the lane after a TinyGo upgrade.

**Refused up front.** `-race` (TinyGo has no race detector), `-gcflags` and `-pgo` (no equivalent) are errors right after flag parsing, not a build failure after the compile. `-debug` drops `-no-debug`. A `require` (a literal one, in the program or a gem it compiles) whose first segment is `socket`, `net`, `webrick`, `open-uri`, `open3`, `fiddle`, `ffi`, `sqlite3` or `prism` is a compile error at that line naming the flag (`tinygoUnbuildable` in libs.go). Under `-trace`, a `require` inside a method is resolved at run time (decision 197) and skips the check; such a library then fails at TinyGo's link or run time. Checked by building each with TinyGo 0.44 on darwin: sockets fail ("Netdev not set"; on Linux the issue's probe found `Dial` refused and `Accept` returning nil), `os/exec` fails, purego does not link (`syscallXABI0` multiply defined) or panics (`reflect.Type.NumOut`), and wazero (prism.wasm's runtime) does not compile against TinyGo's `net`. What fails for one core method (backticks and `system`, `File.utime`/`FileUtils.touch`, `Process.groups`, backtraces through `runtime.Callers`) stays a run-time error or a skip-list line, since the class it belongs to otherwise works.

**Test lane.** `RUGAROO_COMPILER=tinygo go test -run TestExamples .` builds each example with `tinygo build -trimpath -no-debug` and compares with MRI as usual; the lint pass over the generated Go is gc's and is skipped. `testdata/tinygo/tinygo-skip.txt` (decision 372's format) lists what cannot build or run under TinyGo anywhere, `tinygo-<GOOS>-skip.txt` what fails on that OS only. Only `TestExamples` is the lane; the other tests under the variable are not kept green. It is run by hand, on Linux (the target that matters for TinyGo), after each TinyGo upgrade and before a release, with `-parallel 2`: no CI, as there is none for the gc suite, and its builds are several times slower.

**What gc's output gains.** Not byte-identical: moving helpers into the pair shifts `//line` numbers, and the hash call sites changed text. Compared by top-level declaration (order, comments and `//line` ignored) over `gen` of every `examples/*/main.rb`, `testdata/run/*.rb` and `benchmarks/*.rb` (214 files) against its parent, 1e29fc44: 9 fail the same way without their flags (byte-identical errors); 75 declare the same Go; 115 add `rbHashString` and `rbHashComparable`, which gc inlines (`-gcflags=-m`), and change the declarations that call them (`rbHashOfAny`, `rbKeyHash`, `rbIntHashSeed`, `Regexp#hash`, plus `rbMethodHash` and `rbObjectID` where kept); 39 add `rbUntagGoroutine`, an empty function deferred once per Thread, Ractor, Fiber or Timeout goroutine. `rbHashComparable` takes `any`: a generic one costs 82 in gc's inliner, over its budget of 80, so every hash would have paid a call; the `any` one costs exactly 80, which a Go upgrade could tip. Through it `rbHashOfAny[K]` hashes `any(k)`, as `rbKeyHash` already did, so a non-interface key's hash value changes (still per-process random) and gc instantiates fewer functions: `TestCompileCost` compiled functions against main at bdfe1a65: 2,065 → 2,060, 7,955 → 7,950 and 30,700 → 30,687 (005_word_count, 064_observable, 116_cuba_web).

Run time, gc, best of 5 against main at bdfe1a65 (thread_churn, fiber, hash, objects benchmarks): 0.044 / 0.131 / 0.040 / 0.060 s before, 0.044 / 0.131 / 0.038 / 0.061 s after, within noise.

**Measured** (2026-11-11, darwin/arm64, TinyGo 0.44.0 on Go 1.27.3, LLVM 22):
- The lane: 115 of 138 examples print what MRI prints; 23 are skipped: 13 refused requires, 7 TinyGo limits everywhere (`os.Getgroups` and `os.Chtimes` missing, `os/exec`, `runtime.Callers` for minitest's failure location and backtraces, a GC that never frees weak references) and 3 on darwin only (064, 123, 124: `syscall.Syscall`/`RawSyscall` do not link; #144's 0.43 probe passed them on Linux). 15 minutes at `-parallel 2`. The issue's 0.43 sweep found 116 of 136 on Linux, 112 on macOS. Linux is the lane's machine and was not rerun here.
- Binaries (`-no-debug` against gc's `-dwarf=false -ldflags=-w`): 005_word_count 2.32 MB → 546 KB, 023_threads 1.98 MB → 495 KB. Builds of a changed `main.go`: 1 s → 11-14 s for those two.

Not done: `-target` pass-through (wasip1), `-scheduler`, a `tinygo` column in `scripts/benchmark`, `os.Getgroups`/`os.Chtimes` shims, darwin's `syscall.Syscall`.
