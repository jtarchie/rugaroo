# Decision 453

**Rule:** Without a block, `sort_by`, `min_by`, `max_by`, `group_by` and `partition` return an Enumerator over the elements, `map.with_index(off)` an Enumerator of `[element, index]` pairs, and Range's `map` Enumerable's blockless map; Hash's `select`/`filter`/`reject` followed by `.with_index(off) { |(k, v), i| }` compile through decision 450's `withIndexChain` to a Hash.

**Blockless enumerator objects** (#155, #145's follow-up; amends decision 450; 2026-11-13).

- **Enumerable twins** `__<name>_enum` (`rbEnumOf(self.Each(), ...)`, sized by `rbCountSize`) reach Array, Hash, Set and Enumerable classes; Range defines its own `map`, so it has its own `__map_enum` (decision 331: a module's twin does not cover a method a class defines itself).
- **`Enumerator::Map#__with_index_enum(off)`** is the generic Enumerator's `with_index` without a block, over the Map's items.
- **Hash's `select.with_index { }`** returns a Hash, as MRI's: `withIndexChains` now also lists `select`/`filter`/`reject`, rewritten only where the receiver's class has the `__<name>_with_index` twin (Hash's); Array and Enumerable classes keep `Enumerator::Select`'s `with_index` (decision 450).
- **`tally(hash)` identity** (#155's last item) already holds in a typed program (`%w[a b].tally(h).equal?(h)`, frozen raises); ruby/spec's 3 failures come from its shared fixture class, whose element type is a union of every spec file's values, so the argument Hash is converted. That is fixture typing, not an Enumerable gap.
- **Proof:** `testdata/test/enumerable_test.rb` `BlocklessEnumTest` against MRI.
