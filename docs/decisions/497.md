# Decision 497

**Rule:** A gem's `yield(*args)` gives its def a `{ (*untyped) -> R }` block as user code's does; two modules every includer has both, setting one ivar, share one field; a block method called dynamically with no block and no arguments answers its `__<name>_enum` twin; and a class's own `eql?`/`hash` key Hashes and Array set operations even when its `eql?` infers untyped.

**Three rubocop cop crashes, each a place the compiled program disagreed with MRI** (2026-11-23). *Amends decision 250 (a gem's `yield(*args)`) and decision 147 (module ivars); see also decision 363.*

Compiled rubocop on 250 files of a private Rails app raised in three cops that MRI runs cleanly on the same patched gems (`Lint/ConstantReassignment` 498 times, `Layout/FirstHashElementIndentation` 4, `Style/ComparableBetween` 2). None of the three cop files is patched.

- **`yield(*args)` in gem code.** rubocop-ast's generated node matchers end in `yield(*captures)` and cops take them as `|*args|` (Style/ComparableBetween's `min_and_value, max_and_value = args.each_slice(2).to_a`). Decision 250 had a gem's def take a one-parameter block and spread the values by position, so a `|*args|` block got `[captures[0]]`, and `(nil & x).first` raised. A gem def now takes the `(*untyped)` block decision 363 gives user code. A gem's own fixed-parameter block forwarded into it with `&task` (decision 250's ns_execute) passes its values through a variadic adapter (`restVoidAdapter`).
- **One ivar across sibling modules.** FirstHashElementIndentation includes Alignment (`attr_reader :column_delta`) and MultilineElementIndentation (which sets `@column_delta`). Each module had its own ivar struct, so the cop read a field nothing wrote. A module's ivar is now the field of another module that every struct class including it also includes (`coIncluded`): looked up first, and moved over when the other module declares it second. User code with differing annotations is a compile error (`ivar @x declared as T but M, which every includer of N also includes, has it as U`); gem code joins them to untyped. A module included where the other is not keeps its own field, as before.
- **A blockless dynamic call of a block method.** `node.each_ancestor(:class, :module).reverse_each` returns an Enumerator, then `reverse_each` with no block on it went to the block form's wrapper, which yielded to nothing (LocalJumpError). The wrapper now answers `__<name>_enum` when the call brings no block and no arguments, unless that twin answers a bigger generic (each_with_index's `Enumerator[[E, Integer]]`, a Go instantiation cycle; growsTypeParams).

- **A gem's `eql?` and `hash` as keys.** With all four captures arriving, ComparableBetween's `(min_and_value & max_and_value).first` was still empty: the two `date` nodes are equal by the ast gem's `Node#eql?`/`hash`, but that `eql?` (an `&&` chain) compiles to `EqlQ(any) any`, and the runtime only took `EqlQ(any) Boolean`, so `&`, `uniq` and Hash keys compared the nodes by identity. `rbValueKey`/`rbKeyEql` now take the untyped form too (`rbEqlHashAny`, its result tested for truth). Inside it, `self.class.eql?(other.class)` on class objects held untyped reached no method: the `eql?`/`equal?` dispatchers end in Kernel's identity.

Proved against MRI by `captureish.rb`, `sharedivarish.rb`, `ancestorwalkish.rb` and `eqlnodish.rb` in testdata/run/gem_lenient, `SharedModuleIvarTest` in testdata/test/object_test.rb, and `module_ivar_sibling_types` in testdata/errors/objects.txtar.
