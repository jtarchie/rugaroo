# Decision 428

**Rule:** Gem code that MRI runs through metaprogramming hooks, polyfills and data files compiles by general rules, never by naming a gem: `method_added` is a class hook, a module-body `require` and a computed-path autoload load where they register, a class-body block's constant and a body unit's later constants are assigned in order, dynamic-call uses widen a parameter but never type it alone, a one-literal gem parent is a placeholder its overrides fill, a gem private instance method appends into its String parameter by reference, `Marshal.load` reads MRI's stream of core values, and `respond_to?` answers true for String's rebinding-compiled mutators.

**Rubocop research** (2026-10-31; amends 137, 170, 175, 197, 204, 205, 206, 212, 231, 232, 233, 331, 334, 382, 394, 405, 410; see also 140, 299, 427). The question was whether the unmodified rubocop CLI (rubocop, rubocop-ast, parser, prism, regexp_parser, racc, unicode-*, racc-generated and rex-generated code: 2M lines of Go) compiles. It does: the binary links, every gem loads alone, and a program tokenizing a file through rubocop-ast and prism's translation lexer runs twelve stops deep. Every stop was a general compiler gap; none of the fixes below names rubocop. The loop that found them: a 10-second gem-lane repro under `-gem`, a 6-second per-gem load check (`require "<gem>"; puts :ok` under `-trace`), a 2-minute tokenize program, then the narrow tests, instead of 70-minute full rounds.

**Signatures and slots** (amends 205, 206, 212, 231, 299, 410).
- An Enumerable includer's `def each(*args, &block) = expressions.each(*args, &block)` (regexp_parser's Subexpression, the shape its `class_eval` emits) answers Enumerable's `each()` slot through an adapter that passes no arguments (`seqDropped` drops a trailing rest as it drops nil defaults; an annotated iterator keeps its rest under `GoName_rest` with a no-argument `Each()` adapter, `seqRest`); a splat argument never selects a class twin. An `each(opts = {})` adapter passes an empty literal default as written.
- A gem override with another arity than its slot gets an adapter (`fewerParams`: `rbArity` then the truncated call); one no adapter fits answers its slot with MRI's `ArgumentError` (a `raise` slot, never for `<=>`, which `emitCmpAdapter` owns); a module's method shadows a superclass slot another gem or user module owns; a dyn adapter may answer a module's renamed slot; a gem override's untyped result under a typed slot answers what fits, else the slot's zero (`rbAsOrZero`).
- A superclass's own def gives an override its signature before an included module's (`inheritedSig`), and the superclass slot owns the Go name. A gem parent whose body is one literal or only `nil` or only raises is a placeholder its overrides fill: the overrides infer their own return and the parent's becomes the join, seeded with the literal's type (`onlyLiteral`, `typeAbstracts`; rubocop-ast's `Node#receiver; nil` and `Node#arity = 1` under `Rest`'s Range).
- A gem `def m(*)` whose zsuper reaches a fixed-arity parent spreads its rest, count checked (`restBridge`). An `initialize` whose `super()` passes nothing keeps its own parameter types (Prism's explicit `super()` has no arguments node). A decision-212 dispatcher arm whose override is void answers nil under a valued slot. A dynamic call whose own method cannot be called dynamically takes an included module's (Array#to_h generic over its pairs: Enumerable's).
- Decision 331's dynamic-call uses widen a gem parameter but never type it alone: until a static caller carries a type the parameter stays untyped (`realType` in `updateInference`). ProcessedSource's `parser.parse(@buffer)` reaches every `parse` by name and typed rubocop-ast's `NodePattern::Parser#parse(source)` as a Buffer while its one static caller passes a String. The rule needs a dynamic use: a key whose uses are all static but untyped in an early round (a stored block's `@order[a.val, b.val]`, decision 307) joins as before; the first cut skipped it too, leaving `TestNilLinksTyped`'s and pairing_heap's block parameters untyped until 2026-11-01. A dynamic call's block value, appended to its arguments, is not a parameter's use. Liquid (example 124) and kramdown (123) still equal MRI.

**Load order and constants** (amends 170, 175, 197, 334, 427).
- A constant assigned inside a class-body block (`File.open(path, "rb") { |f| INDEX = Marshal.load(...) }`, unicode-display_width) is declared where the statement runs, as a begin's constants are: untyped in gem code, `#: T` in user code, and the block's value when last.
- A class body with locals runs as one unit (170); a later constant of that body reading no local, and a hook call inside the unit's span, are spliced into the unit in source order (racc's `Racc_token_to_s_table = [...]; Ractor.make_shareable(Racc_token_to_s_table)`).
- A gem's module-body `require`/`require_relative` loads where it is, as a top-level one does (parser's `module Parser; require_relative 'parser/meta'`, read by rubocop-ast's class bodies at load). A gem `autoload :X, computed_path` whose file another require loads moves that file to where the autoload registers (`placePendingAutoloads`; unicode-emoji's `File.join(dir, name.downcase)` loop, unrolled as A `%w[A B].each { |c| autoload c, path }` loop in a class body registers each name). A boot-autoloaded gem file is needed when a symbol argument of a call other than `autoload` names its constant (rubocop's `register_cop :Name, path`). A gem constant a `const_get` or `constants` call may name is never pruned, and a guarded constant is listed once set.
- `method_added` is a class hook: after each def in a class body, `Cls.method_added(:name)` runs where the def is when the class or a superclass defines the hook in user or gem code and already had it (a hook defined later in the same file sees none of the defs before it, as in MRI). rubocop-ast's `Subcompiler` fills a visitor registry so. A trace-recorded block `class_eval` whose ivar writes read an enclosing local anywhere in their values (`base.class_eval { @registry = us.registry.dup }`) runs where it stands, not as the receiver's body.

**Values** (amends 137, 382, 394, 405; see also 140).
- `Marshal.load` reads MRI's own 4.8 stream when it holds only core values (nil, true, false, Integer, Float, String, Symbol, Array, Hash and their links), as `*Array[any]`/`*Hash[any, any]` (`prelude/go/marshal_mri.go`): a gem's `*.marshal.gz` data file. Dumps stay rugaroo's own; any class-naming record raises as before. The alternative, a boot-captured constant emitted as a Go literal, was not taken (~30k values per gem).
- In a gem file, a private instance method no subclass redefines takes its appended String parameter by reference (405): prism's translation lexer appends every unescaped byte into `escape_read(result, ...)`'s parameter, and a plain rebinding lost them silently. A gem caller passes the pointer without the alias proof or shared buffer. `append_as_bytes` (Ruby 3.4) is an append wherever `<<` and `concat` are (`strAppendNames`; each argument's bytes, an Integer's low byte, `rbBytesArg`), and `String#b` is a fresh String for the proof.
- `@a = @b = @c = 0` through untyped ivars: the inner store's value keeps its literal flag, so the next untyped store boxes it (liquid's ResourceLimits#reset wrote a bare Go `0`).
- `respond_to?` on a String answers true for the in-place names rugaroo compiles as rebinding (`stringMutators`), so prism's Ruby 3.4 polyfills (`String.include(Module.new { def append_as_bytes ... })`) stay out instead of raising 331's run-time-include error. `StringScanner#scan_byte`/`peek_byte`, `Ractor.make_shareable` (deep freeze, answers the object), `Range#minmax` (from the ends, never by iterating; `[min, Float::INFINITY]` for a decision-140 Integer range; an untyped tuple, since `[E?, untyped]` renders E? as `*E` in the generic body but `rbOpt[E]` at an Integer call) and `Proc#parameters` (kinds and count from the type; names positional, a Go func carries none) are added.
- A receiverless `binding` that resolves to the class's own method is an ordinary call; Kernel's stays unsupported, as does a bare `method_missing`. A `&:sym` block-pass on a dynamic call passes the symbol's proc as the dynamic block. The Array view's block-less each family answers an Array standing in for the Enumerator. `Symbol#=~`, `!~`, `match`, `match?` match the name. A module only ever extended onto classes compares `self <` as the class object's ancestry. Destructuring an Array of a leaf class opens Go's `**C`.
- Debugging aids: `RUGAROO_KEEP_ENTRY=path` writes the traced entry; `RUGAROO_UNSUPPORTED_STACK` prints the stack at an unsupported node.

**Not done, with the stop that found it.** The twelfth tokenize stop is rubocop-ast's sequence compiler reading `(0..Float::INFINITY).end.infinite?` and `.max`: decision 140 makes that range an endless `Range[Integer]`, which cannot answer a Float. That is a design decision, not a bug, and the research stops there. Also open: a module's `@x` and its includer's `attr_reader :x` are two ivars (decision 147); a value typed Integer in one call and Float in another is stored as Float; a gem parameter typed only by untyped callers still loses its appends (the 405 gate needs an inferred String); the `[E?, untyped]` rendering mismatch. The whitequark lexer is 20k of the 37k traced lines of a rubocop-ast program and is still constructed by `Parser::Base#initialize` under prism translation: the fix is upstream in prism, not a rugaroo rule. Checks: `testdata/run/gem_lenient` (seqish, blkconst, autoish, outish, unitish, metaish, rexish, registryish, arityish), `testdata/test` (enumerator RestForwarded, object BodyBlockConst/ChainedUntypedIvars/OwnBinding, marshal MarshalMRIStreamTest, string StringAppendAsBytesTest, stdlib scan_byte, ractor make_shareable, range RangeMinmaxTest, method ProcParametersTest), `testdata/errors/objects` (const_write_in_class_body_block).

*See also decision 405's #128 amendment (2026-11-11):* the by-reference rule now covers a public gem instance method that no subclass redefines and that overrides no ancestor's method, and a gem's append through an element block parameter raises NotImplementedError instead of being lost.
