# Decision 399

**Rule:** `String#length`, `String#[](i)` and `String#[](start, count)` answer from the bytes when the String (for `[]`, its prefix through the answer) is ASCII, found eight bytes a step, and once before a `while`/`until` loop for a String local its condition takes the length of and the loop cannot change; `String? == String` compares without boxing, as Integer?/Float?/Symbol? do.

**Character loops over a String** (amends 349, 387; 2026-10-27). *See also decisions 136, 332, 337, 393, 397.* spinel's `bm_template.rb` (rugaroo 0.73s, spinel 0.15s) and `bm_json_parse.rb` (0.26s, 0.059s), both built `--nil-check=runtime`, walk a String with `while i < s.length ... s[i] == "{"`. A CPU profile (Linux container, GOMAXPROCS=1) put 65% of template and 56% of json_parse in three scans per call, and most of the rest in boxing:
- **`String#length` scanned twice, `String#[]` twice.** `rbStrLen` ran `utf8.ValidString` then `utf8.RuneCountInString` (byte at a time); `rbStrAt`/`rbStrSub` ran `rbValidUTF8` over the whole String, then `rbRuneOffset` byte by byte to the index. Each call costs the String's length, several times per loop step. Now `rbStrLen` asks `rbASCII` first (one pass, eight bytes a step: Go combines the eight byte loads into one) and returns `len(s)`. `rbStrAt` with `0 <= i < len(s)` returns byte `i` when `s[:i+1]` is ASCII, and `rbStrSub` with `start, count >= 0`, `start <= len(s)` returns `s[start:e]` (`e` clipped to the length) when `s[:e]` is ASCII. Both are right whether the rest of the String is valid UTF-8 or not: with an ASCII prefix, character `i` is byte `i` in UTF-8 and in decision 136's binary reading alike. Anything else (a negative index, a non-ASCII byte before the answer) takes the old path.
- **`c == " "` with `c` a `String?` boxed both sides** into `rbEq[any]` (`Opt(c)` converts the String to `any`, a heap allocation, then an interface lookup): `convTstring` was 12-18% and its garbage another 10-13%. `plainOptEq` (decision 387) now admits String: `rbOptEq(p, v)` is `p != nil && *p == v`, the prelude's `String#==` (Go's byte compare), and still only when that `==` is the prelude's.
- **Measured** (instructions retired, M, GOMAXPROCS=1, median of 5, old/new runs alternating; main at bec61a55 → this): bm_template 8,991 → 2,199 (−75.5%), bm_json_parse 3,381 → 771 (−77.2%); array 153 → 153, bignum 540 → 515, binary_trees 57 → 57, blocks 390 → 389, collections 1,496 → 1,481, exceptions 1,260 → 1,269 (+0.7%), fib 156 → 156, format 1,655 → 1,557 (−5.9%), hash 85 → 85, json 1,977 → 1,997 (+1.0%; −2.2% in a rerun), kramdown 4,275 → 4,260, liquid 1,855 → 1,843, math 52 → 52, objects 505 → 506, pairing_heap 816 → 846 (+3.7%; −1.0% in a rerun: GC noise), regexp 3,092 → 3,059, splay 51 → 51, strings 310 → 282 (−8.8%). Every row prints the same before and after. Wall clock (`scripts/benchmark`, one loaded machine): bm_template 0.22s (spinel 0.18s, MRI 1.16s), bm_json_parse 0.080s (spinel 0.070s, MRI 0.51s).
- **Not fixed, by cause** (#139). The scan is cheaper but still per call: `rbASCII` is 38% of template and 27% of json_parse after this, since a Go string carries no "all ASCII" flag as MRI's code range does; making `length`/`[]` constant time needs a cache or loop-invariant hoisting, not a faster scan. template's `result = result + c` is a fresh allocation per character (its result stays under `String#+`'s 64-byte short path, so decision 332's builder never engages), about 40%. json_parse's `peek`/`advance` return `String?`, a `*String` that escapes from a method Go does not inline: a 16-byte heap allocation per character, about half its time, which `rbOpt[String]` (decision 397's "not done") would remove.
- **Proof:** `StringAsciiIndexTest` in `testdata/test/string_test.rb`: lengths and indexes across ASCII prefixes that end in the first and second eight-byte word, non-ASCII heads, invalid UTF-8 tails, `[start, count]` past the end, crossing into non-ASCII, negative, and `String? == String`/`!=` with nil, against MRI.

**Loop-invariant hoist** (2026-11-11, #139). The per-call scan the section above left (`rbASCII`, 36% of template once decision 382 took `result = result + c`, see there) is gone for the common loop: `while i < s.length ... s[i] ...` on a local or parameter the loop never changes.
- **When** (`hoistStrLoop`, `internal/compiler/strhoist.go`): a `while`/`until` (not `begin ... end while`) whose condition calls `length`/`size` on a local that is exactly `String` here (not a `String?`, a union or a narrowed view), and that inside the condition and body, nested blocks included, is never assigned (any write or target of the name), never the receiver of a method outside 382's `readOnlyStrMethods` (`<<`, `concat`, `setbyte` and the bang methods rebind it: decisions 58, 382, 395), never passed where `outCallArg` says the callee appends to it (decision 405; a receiver it cannot probe before the body is generated, such as a local the loop declares, counts as one when any method of that name has an out parameter), and never in a `super` call's arguments. The local may not be an out parameter itself, nor assigned in any block of the method (a lambda made before the loop may run inside it), and `String#length`/`size`/`[]` must be the prelude's. The condition reads the length at least once per entry, so the one scan is one the loop paid anyway: a loop that never asks the length is left alone.
- **Code.** Before the `for`: `tL, tLim := rbStrLenA(s)`, the length and the bound below which character i is byte i (the length when the String is ASCII and longer than one byte, else 0). In the loop, `s.length`/`s.size` is `tL`; `s[i]` is `rbStrIdxA(s, i, tLim, &tD)` and `s[i, n]` `rbStrSubA(...)`, where `tD` is a `String` declared at the call: the result is written there and its address returned, so the `String?` costs no allocation whether or not the helper inlines (the first try, `return &v`, cost 105 against Go's budget of 80 and its `v` escaped). A fresh `tD` per call and per pass, as Go gives a loop body's variables, so a kept `String?` never sees the next write. Above the bound (non-ASCII, negative, past the end, a one-byte String, whose `s[0]` must not be `s` itself) the helpers take `rbStrAt`/`rbStrSub` as before. A read inside a block in the loop takes the ordinary path: the block may run after the loop, when the local holds another String. An inner loop inside a hoisting loop reuses its values.
- **Not covered.** Ivars (`bm_json_parse`'s `@input`: every writer would have to keep a flag, #139-Iv), `each_char`/`times` blocks, `begin ... end while`, gem code.
- **Measured** (instructions retired, M, GOMAXPROCS=1 GOGC=off, paired alternating runs, min of 7, `--nil-check=runtime`; decision 382's `+=` change → this): bm_template 1,529 → 316 (−79%; from 2,180 before both, −85.5%; spinel 1,336), bm_json_parse 658 → 658 (ivars), benchmarks/ strings 158.4 → 158.3, format 1,263.5 → 1,263.6. All print what MRI prints.
- **Proof:** `StringLoopHoistTest` in `testdata/test/string_test.rb` against MRI: ASCII and non-ASCII receivers (a non-ASCII byte past the first eight-byte word), negative indexes and slices at and past the end in an `until`, a one-byte String's `s[0]` identity, and the cases that must not hoist: reassigned in the loop, appended to in the loop, passed to an out-parameter method in the loop, an out parameter itself, a lambda that reassigns it called from the loop, a lambda made in the loop and called after the local changed; nested loops share one scan.
