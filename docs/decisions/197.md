# Decision 197

**Rule:** A traced program compiles from an entry of what MRI loaded, in load order, with its `-I` dirs as gem dirs; magic comments are gone (288, 296, 297).

**A traced closed world** (#82, Homebrew). *See also decisions 288, 296, 297* (`-trace` builds the entry from a run; `rugaroo_replace` removed) (the magic comments became `-main`;
`rugaroo_fold` is removed). A program too dynamic
to read its requires from source is compiled from an *entry* file
that lists what MRI loaded, in require start order
(`$LOADED_FEATURES` via TracePoint `:script_compiled`), with magic
comments: `# rugaroo_method_requires: runtime` (a require inside a
method body is resolved at run time against what was compiled, not
loaded at compile time), `# rugaroo_replace: path => file` (compile
another file in its place), `# rugaroo_fold: expr => bool` (a fact the
host does not have, `OS.mac?`) and `# rugaroo_main: file` (compiled
after the boot, never booted itself). In this mode the `-I` dirs are
gem dirs: boot capture (161), leniency (172) and pruning (169) apply
to all of them. No eval at run time: what boot evaluated is compiled.

*See also decision 428* (rubocop research, 2026-10-31): the general rules the rubocop CLI's gems needed, several amending this one.
