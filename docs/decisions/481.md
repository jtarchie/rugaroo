# Decision 481

**Rule:** The MRI oracle runs on the repo Gemfile.lock's gems: each MRI run the suite compares against preloads `testdata/mri_gems.rb` (Bundler setup, ENV put back), except in a directory with its own Gemfile, and the Gemfile lists every non-default gem a test or example requires.

**The oracle's gems are the lock's, not the machine's** (2026-11-21). *See also decisions 105, 272, 409, 413.*

`TestMinitest/{json,prism,rxjson,stdlib_hardening}` failed for days with "MRI fails x_test.rb, so the test itself is wrong", with or without `RUGAROO_NO_MRI_CACHE=1`. Nothing in the repo had changed: a `gem install` on 2026-11-14 put json 3.1.0 and prism 2.1.0 beside the versions the tests were written against, and the harness ran bare `ruby`, so RubyGems activated the newest installed version of each. json 3.1.0 drops `escape_slash` and `create_additions`, rejects comments without `allow_comments:` and limits `dump`'s nesting; prism 2.1.0 reports its own version. The Gemfile already pinned `prism 1.9.0`, and the MRI cache keyed on Gemfile.lock as "the gem versions MRI loads", but MRI never read either. Decision 413 says the oracle's gems are the Gemfile's pins; this makes it so.

- **Preload.** `mriRun` (examples, `TestRun`, `TestMinitest`), `TestMulti` and `TestFuzzDiff` run `ruby -r testdata/mri_gems.rb ...`, first, before `mt_trace.rb` (which requires minitest). It sets `BUNDLE_GEMFILE` to the repo Gemfile, requires `bundler/setup`, then restores ENV: Bundler rewrites `GEM_HOME`, `PATH`, `RUBYOPT` and adds `BUNDLER_ORIG_*`, which a program printing ENV would show and the compiled program would not. Not `bundle exec`, for the same reason. A directory with its own Gemfile (example 135) gets no preload: its program calls `bundler/setup` on that Gemfile itself.
- **Gemfile.** Under Bundler a gem the lock does not name cannot load, so the Gemfile now lists the non-default gems the suite requires: `abbrev`, `benchmark`, `csv`, `fiddle`, `minitest`, `observer`, `ostruct` at what bare `ruby` loaded on this machine (the versions the suite was measured with), `json 2.21.1` (Ruby 4.0.9's default 2.18.0 fails `json_test`, which needs 2.19+), and `bigdecimal 4.0.1`, what Ruby 4.0.9 bundles (the old `~> 3.1` pin was never what MRI loaded: bare `ruby` took 4.1.3, and `bigdecimal_test` passes on 4.0.1 and fails on 3.3.1). All are prelude libraries (`libs.go`), so rugaroo's gem lookup (decisions 173, 409) never compiles them from the bundle.
- **Cache.** The key (decision 272) gains the preload's source and moves to `v7`; Gemfile.lock was already in it and now means what it says.
- **Proof.** Every program the oracle runs (testdata/test, testdata/run, testdata/fuzz, examples: 250) run bare and with the preload gives the same stdout, exit code and assertion trace (addresses and oids normalized as `traceAddr` does) except the four tests above, which pass on MRI only with the preload. With json 3.1.0 and prism 2.1.0 still installed, the four pass, cached and with `RUGAROO_NO_MRI_CACHE=1`.
- **Not covered.** `TestGemCorpus` finds kramdown's test cases with bare `ruby` and compiles from a trace; `TestVendoredGemsMRI` runs the vendored gems' own tests, compared with nothing. Neither failed; both still see the newest installed gems.
