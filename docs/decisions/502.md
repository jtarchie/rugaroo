# Decision 502

**Rule:** An inference round re-walks a method's return only when something its last walk read changed: a parameter or signature it read, its class's ivars, or the return of a method it called; every other method's return, and the uses its walk recorded, are the last round's. `RUGAROO_NO_INCREMENTAL=1` walks every return again.

**Incremental rounds** (2026-11-27; Crystal's binding graph at method granularity). *See also decisions 146, 279, 479, 491, 499; docs/research/round-cost-2026-11.md.*

Crystal types a program as a graph: each node observes the nodes it depends on, and a changed type re-types only what observes it. rugaroo's types come from running code generation, one fresh compile per round, so there is no graph to observe. What a round can have is the graph's coarse form: each return walk records what it read, and the next round re-walks only the walks whose reads changed. Under the not-known-yet rounds (decision 499) types only go up, which is what makes a walk's result reusable when its inputs are unchanged; the round-cost plan rejected reuse for the older rounds, whose state is rebuilt each round.

- **What a walk reads** (`incremental.go`). Each read is a position, the def, lambda or block every pending key of one parameter list starts with (`pendingPos`): every pending type it read (`pendingType`, the one place one is read, decision 279); every method it called, by `callEntryAny` or `inferRet` (that method's own position, the positions of its `&block` and `self` keys, `sigKeys`); and its own class's ivars, and those of every method it called (`classPos`). The per-parameter sets a walk may read (`none`, `noDrop`, `hardAny`, `anyUse`, `noUnion`) and each class's ivar types are compared per key and per class; only a phase change or a lambda alias change reuses nothing.
- **What a round does.** A walk whose last record counted (decision 491) and none of whose positions changed is preset: its return, the reason for it, and the uses it recorded are the last round's, its `roundRet` and `hardAny` worked out again from them. The round then walks the rest as before. A preset method one of whose callees this round returned something else is walked again, until none is (`propagateReuse`). A walk that did not count, because it failed, recursed or read a provisional value, is always walked again.
- **Two dependencies the A/B found** (round dumps, `RUGAROO_ROUND_DUMP`, compared with and without reuse): a caller binds its block's parameters from the callee's stored block, whose keys are at the `&block` parameter's position and not at the def's; and a class and its metaclass share a Ruby name, so ivar prints and class positions are keyed by the Go class name.
- **Where the output is not the full rounds'.** A method walked several times in a round keeps the result of its first walk, and that walk's context can differ: rubocop's `ConfigLoaderResolver#defaults_with_preview`, first walked inside a recursion through `ConfigLoader.default_configuration`, read that method's provisional return. Reuse changes which caller walks it first. Full rounds are order-dependent the same way (round-cost-2026-11.md, "inferRet depends on order"); reuse picks another order, not a wrong answer. Of the inputs measured, only rubocop's round state differs (32 dump lines, 166 lines of Go), and its output still equals MRI on every check input.

**Measured** (`RUGAROO_TIMING`'s `incremental` line; full vs reuse, inference cache off):

| | return walks (r-rets) | transpile |
|---|---:|---:|
| rubocop | 128.1 -> 62.7 s | 466.7 -> 397.2 s (-15%) |
| kramdown | 2.1 -> 1.5 s | 19.8 -> 19.3 s |
| liquid | 0.6 -> 0.3 s | 7.6 -> 7.3 s |
| gem_lenient | 0.8 -> 0.5 s | 5.9 -> 5.2 s |

In rubocop's tail rounds 11,500-11,600 of 13,236 walks are reused; about 1,700 must always run again, the walks the last round did not count. `scripts/gen-compare` of reuse on against off over 348 inputs (examples, testdata, benchmarks, spinel's): all generate the same Go. `overrides/rubocop/check` with reuse: 12 of 12 outputs equal MRI.

**Not reused: ivar refinement and discovery** (measured 2026-11-27, then removed). A round's `refineIvars` search was recorded the same way, every position its dry runs read, with the poison they left replayed. On rubocop it was reusable in 1 of 21 rounds: its dry runs read 940-980 positions, so nearly any change touches one, and in 10 rounds the ivars or the candidates had changed anyway. Liquid: 1 of 14. Discovery reads more than refinement. Both stay as they were; within this design the round count, not the work per round, is what is left, and that is the question for a separate type graph (the user's spike, after this list).

**Crystal's ivar guesses as round-one seeds are not needed:** discovery dry-runs every write before the first round (decision 15), so what Crystal guesses from a literal or `Foo.new` is typed already; after round 1 the ivars of 0-9 classes change per round in liquid and kramdown.

**Proof:** the A/B above (`RUGAROO_NO_INCREMENTAL=1` against the default, round dumps and Go) on liquid, kramdown, cuba, pairing_heap, `gem_inference` and `gem_lenient`; gen-compare; rubocop check.
