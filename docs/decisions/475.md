# Decision 475

**Rule:** A gem's own iterator method called with a block that leaves with `break value`, its value used, is the break's value and nil when the method runs to its end; a method ending in an each-like block call keeps the compile error, since MRI answers that call's receiver.

**Found by rubocop under `RUGAROO_INFER_UNKNOWN=1`** (2026-11-21). *See also decisions 172, 233, 410, 417.*

`RuboCop::TargetRuby::GemspecFile#gemspec_filepath` writes

```ruby
@gemspec_filepath = @config.traverse_directories_upwards(base, root) do |dir|
  candidates = gemspec_candidates(dir)
  break candidates.first if candidates.one?
  break if candidates.any?
end
```

and `FileFinder#traverse_directories_upwards` is a Go iterator (it only yields, inside `Pathname#ascend`). In the default lane `@config` is untyped, so the call is dynamic and the block a closure. With the switch `@config` is a `RuboCop::Config`, the call is static, and a static iterator call in value position was a compile error unless the iterator was a core each (decision 417). The method became a NotImplementedError stub; rubocop rescues that per file, so the binary reported "0 files inspected". Better typing reached a gap the static path always had.

Decision 417's loop now serves a gem-defined iterator too (`iterCallValue`, `genBrokenIterLoop` with `ended` false): a variable above the loop, the break's value written before the `goto`, nil otherwise. Not taken when:

- the code is a program's own (still decision 4's and 172's errors);
- the iterator is the prelude's, or is named as an each (decisions 172, 417 own those: the receiver at the end);
- the method's last statement is an each-like call with a block (`endsInEach`): MRI answers that call's receiver, and an `iter.Seq` has no value to give. The compile error stays, which is a stub in gem code as before.

**Proof:** `testdata/run/gem_lenient/walkish.rb` (broken: the value; run to the end: nil).
