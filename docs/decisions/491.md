# Decision 491

**Rule:** An inference round records its call uses in the walk that infers each return, and `collectUses` emits only the methods whose walk does not count: one that failed, recursed, read a recursion's provisional return, read past a statement or `when` arm that does not compile, or whose gem body is poisoned.

**One walk for returns and uses** (2026-11-22). *See also decisions 146, 205, 244, 478, 479; docs/research/round-cost-2026-11.md.*

A round inferred every return (`r-rets`), then emitted every user method again to record the arguments its calls pass (`r-uses`, `collectUses`). The return walk already generates each call, so its argument types are the ones emission would record. Now the return walk records them, and emission runs only where its result could differ.

- **Each walk records into its own buffer** (`bufferRetUses`). The buffer joins the round's uses when the walk counts (`countRetWalk`), and is dropped otherwise. Before the buffer, a walk that failed part way left the uses it had recorded before the error. Emission of that method does not reach the same calls, so those uses outlived it.
- **A walk does not count**, and the method is emitted as before, when:
  - it failed;
  - it recursed;
  - it read a gem recursion's provisional untyped return (`taintRetWalks`);
  - it read past a statement that does not compile (`genStmtPastFailure`) or past a gem `when` arm that does not (`genWhenArm`) (`taintRetWalk`);
  - or the method is poisoned. A poisoned gem body (decision 205) is emitted as a stub that raises and records nothing, while its return walk still reads the body. rubocop's `RequireFileInjector#target_line` (`find` with no block) typed `require_path_fragments(require_directive)` as String from a call that never runs. `render_html` (`ERB.new` of a non-literal template, decision 111) typed `ERBContext#summary`.
- **What is not the same:** the order in which returns are inferred inside a round. Recording uses probes a dynamic call's arguments during the return walk instead of after it, so a few returns and parameters are typed a round earlier or later. On rubocop, 11 lines of the per-round state dump differ (`Buffer#source=`, two `ConfigLoaderResolver` parameters). The rounds reach the same result, and the generated Go is byte-identical.

**Measured** (idle machine, `RUGAROO_TIMING=1`, inference cache off):

| | main | this |
|---|---:|---:|
| rubocop transpile | 227 s | 200 s |
| rubocop `r-uses`, all rounds | 42 s | 12 s |
| rubocop `r-rets`, all rounds | 28 s | 31 s |
| parser gem program `r-uses` | 5.5 s | 3.2 s |
| `TestCompileCost` 064_observable / 116_cuba_web compile | 1.83 / 7.03 s | 1.63 / 6.64 s |

Generated Go is the same on rubocop, on the parser gem's program, and in `scripts/gen-compare` over 347 inputs (examples, testdata, benchmarks, spinel's suite), in both the default lane and `RUGAROO_INFER_UNKNOWN=1`.

**`RUGAROO_ROUND_DUMP=path`** appends each round's state to the file: the refine candidates and which were kept, every inferred parameter and every inferred return. It is a diagnostic (decision 487's second kind). `RUGAROO_TIMING` gains a `round work` line: refine tries and passes, classes seen, returns same or different, and use time. The `RUGAROO_RET_USES` switch the change was measured with is gone.

**The round-cost plan's S2 and S3 are not built.** They assumed about 60% of `collectUses`' time went to the classes `refineIvars` emits. The `round work` counter measured about 7% on rubocop (889 ms of 13.5 s in round 1), so reusing those emissions would save about 1 s a round.
